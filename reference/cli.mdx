`ssp` adds and removes apps, arms, and tokens, stops and resumes arms, and runs the proxy. Install it with the [install script](/getting-started/installation#cli).

```text
ssp app    add | remove | list | show | stop | resume
ssp arm    add | remove | list | show | stop | resume
ssp token  add | remove | list
ssp proxy  docker | cloudrun | kubernetes
ssp init
ssp login | logout | whoami
```

## Conventions

- Commands have the form `ssp <noun> <verb> <object>`. The object is positional, such as the app name or the commit.
- `--app` names the app of an arm, a token, or a proxy.
- A commit is the full commit or its first 7 characters or more.
- No command asks a question, except `ssp login`.
- `ssp app add` and `ssp arm add` print what they found and chose.
- Each command that changes something prints exactly what it changed.

## Common flags

<ParamField body="--json" type="boolean">
  Print exactly one JSON document on standard output. All commands take it, except `ssp proxy`. The document is the response of the [API](/reference/api) route that the command calls.
</ParamField>

<ParamField body="--note" type="string">
  Free text for people and agents, 1 to 200 characters on one line. All commands that change something take it. The dashboard, `ssp app show`, and `ssp arm show` show it.
</ParamField>

## Output and exit codes

- Results go to standard output. Notes and warnings go to standard error.
- An error exits with status 1. With `--json`, the error is `{"error": "..."}`.

## ssp app add

Add an app. It is linked to a repo and to the folder of its `statespace.toml`. You need the admin role on the repo.

```shell
ssp app add shop-prod --note "shop, production"
```

<ParamField body="name" type="string" required>
  The name of the app: 1 to 63 lowercase letters, digits, and `-`. It must be unique in the workspace.
</ParamField>

<ParamField body="--repo" type="string">
  The repo, as `owner/name`, such as `acme/shop`. Default: the repo of the `origin` remote of the current folder.
</ParamField>

<ParamField body="--path" type="string">
  The folder of `statespace.toml`, from the root of the repo. Default: the folder of the nearest `statespace.toml`.
</ParamField>

The command prints the repo and the folder that it found, and the app that it added. It fails outside a repo, without a GitHub remote, or when the folder has no `statespace.toml`. With `--json`, it prints the `App`.

## ssp app remove

Delete an app and all its data. You need the admin role on the repo.

```shell
ssp app remove shop-dev
```

<ParamField body="name" type="string" required>
  The app.
</ParamField>

The command fails while the app has arms that are not removed. It prints what it deleted. With `--json`, it prints `{"deleted": App}`.

<Warning>
  You cannot undo `ssp app remove`. The evidence of all arms of the app is deleted.
</Warning>

## ssp app list

List the apps: repo, folder, live commit, running arms, and holds.

```shell
ssp app list
```

With `--json`, it prints `{"apps": [App]}`.

## ssp app show

Show an app in full: live, the control, the arms with their headline metric, holds, the settings that apply, the proxy instances, the orchestrator, and the lease holder.

```shell
ssp app show shop-prod
```

<ParamField body="name" type="string" required>
  The app.
</ParamField>

With `--json`, it prints the `AppDetail`.

## ssp app stop

Place a hold on the app. Every arm of the app leaves traffic, also the arms that people add later. You need the role write or triage on the repo.

```shell
ssp app stop shop-prod --note "checkout errors > 2%"
```

<ParamField body="name" type="string" required>
  The app.
</ParamField>

A stop on an app that has a hold returns the hold, and changes nothing. With `--json`, it prints the `Hold`. See [Holds](/concepts/holds).

## ssp app resume

Clear the hold on the app. Holds on single arms stay, and the command says so.

```shell
ssp app resume shop-prod
```

<ParamField body="name" type="string" required>
  The app.
</ParamField>

With `--json`, it prints the removed `Hold`.

## ssp arm add

Add a commit as an arm, or change the share of an arm. You need the level that `arm_role` sets for the app.

```shell
ssp arm add a1b2c3d --app shop-prod --share 0.05 \
  --note "green checkout button"
```

<ParamField body="commit" type="string" required>
  The commit. A prefix that matches more than one build fails, and the error lists the matches.
</ParamField>

<ParamField body="--app" type="string" required>
  The app.
</ParamField>

<ParamField body="--share" type="number" default="0.05">
  The fraction of the app's subjects that the arm gets.
</ParamField>

The command prints the build that it chose. Without a build of the commit for the app, it fails: "No build of a1b2c3d for shop-prod. Push it so CI builds it." For an arm that exists, the command changes the share, starts a new version, and prints the old and the new share. With `--json`, it prints the `Arm`, with `build` and, for a change, `previous_share`.

## ssp arm remove

End an arm. Statespace keeps its evidence. Its commit status says "Ended".

```shell
ssp arm remove a1b2c3d --app shop-prod
```

<ParamField body="commit" type="string" required>
  The arm's commit.
</ParamField>

<ParamField body="--app" type="string" required>
  The app.
</ParamField>

With `--json`, it prints the `Arm`.

## ssp arm list

List the arms of an app: running, waiting, stopped, and the arms removed in the last 90 days. An arm whose commit is in the live commit says "Live 9f1ce8a contains this commit · consider ssp arm remove".

```shell
ssp arm list --app shop-prod
```

<ParamField body="--app" type="string" required>
  The app.
</ParamField>

With `--json`, it prints `{"arms": [Arm]}`.

## ssp arm show

Show an arm: its state and reason, the totals and metrics of the arm and the control, the split check, the top events, the versions, the holds, and the override link.

```shell
ssp arm show a1b2c3d --app shop-prod
```

<ParamField body="commit" type="string" required>
  The arm's commit.
</ParamField>

<ParamField body="--app" type="string" required>
  The app.
</ParamField>

With `--json`, it prints the `ArmDetail`.

## ssp arm stop

Place a hold on one arm. The arm leaves traffic in seconds. You need the role write or triage on the repo.

```shell
ssp arm stop a1b2c3d --app shop-prod \
  --note "checkout errors > 2%"
```

<ParamField body="commit" type="string" required>
  The arm's commit.
</ParamField>

<ParamField body="--app" type="string" required>
  The app.
</ParamField>

With `--json`, it prints the `Hold`.

## ssp arm resume

Clear the hold on one arm. A hold on the app stays.

```shell
ssp arm resume a1b2c3d --app shop-prod \
  --note "fixed in b2c3d4e"
```

<ParamField body="commit" type="string" required>
  The arm's commit.
</ParamField>

<ParamField body="--app" type="string" required>
  The app.
</ParamField>

With `--json`, it prints the removed `Hold`.

## ssp token add

Add a runtime token for one app. You need the admin role on the repo. The command prints the secret only one time.

```shell
ssp token add --app shop-prod --note "Cloud Run proxy"
```

<ParamField body="--app" type="string" required>
  The app of the token.
</ParamField>

<Warning>
  Keep the output out of logs. Statespace cannot show the secret again.
</Warning>

## ssp token remove

Remove a runtime token.

```shell
ssp token remove <id>
```

<ParamField body="id" type="string" required>
  The ID of the token. `ssp token list` shows it.
</ParamField>

## ssp token list

List the runtime tokens, without their secrets.

```shell
ssp token list
```

## ssp proxy docker

Run the proxy on a machine with Docker. Live, the control, and the arms run as containers. See [Docker](/guides/docker).

```shell
ssp proxy docker --app shop-dev \
  --image-file /etc/shop/image
```

<ParamField body="--image-file" type="string" required>
  A file that holds the live image. When the file changes, the proxy deploys the new live.
</ParamField>

The [proxy flags](#proxy-flags) also apply.

## ssp proxy cloudrun

Run the proxy in front of a Cloud Run service. The control and the arms run as tagged revisions of the service. See [Cloud Run](/guides/cloud-run).

```shell
ssp proxy cloudrun --app shop-prod \
  --service shop --region us-east1
```

<ParamField body="--service" type="string" required>
  The Cloud Run service that runs live.
</ParamField>

<ParamField body="--region" type="string" required>
  The region of the service, such as `us-east1`.
</ParamField>

The [proxy flags](#proxy-flags) also apply.

## ssp proxy kubernetes

Run the proxy in front of a Kubernetes Deployment. The control and the arms run as copies of the Deployment. See [Kubernetes](/guides/kubernetes).

```shell
ssp proxy kubernetes --app shop-prod \
  --deployment shop --namespace prod
```

<ParamField body="--deployment" type="string" required>
  The Deployment that runs live.
</ParamField>

<ParamField body="--namespace" type="string">
  The namespace of the Deployment.
</ParamField>

<ParamField body="--service" type="string">
  The Service of live. Default: the name of the Deployment.
</ParamField>

The [proxy flags](#proxy-flags) also apply.

## Proxy flags

Each `ssp proxy` command takes these flags. All other settings come from [`statespace.toml`](/reference/statespace-toml).

<ParamField body="--app" type="string" required>
  The app. The command fails when the app does not exist.
</ParamField>

<ParamField body="--listen" type="string" default="0.0.0.0:8080">
  The address that the proxy listens on.
</ParamField>

<ParamField body="--token" type="string">
  The runtime token of the app. Environment variable: `STATESPACE_TOKEN`.
</ParamField>

<ParamField body="--api" type="string" default="https://api.statespace.com">
  The Statespace API. Environment variable: `STATESPACE_API`.
</ParamField>

`ssp proxy` prints no JSON document. It passes HTTP/1.1, HTTP/2, and WebSocket.

## ssp init

Write a starter `statespace.toml` in the current folder, and print the action step to add to your build workflow. The command fails when the file exists. It changes only the working copy.

```shell
ssp init
```

## ssp login

Sign in with GitHub. The CLI shows a code. Approve the code in the browser. This is the only command that waits for you.

```shell
ssp login
```

## ssp logout

Sign this terminal out.

```shell
ssp logout
```

## ssp whoami

Show who is signed in, and the credential that the CLI uses.

```shell
ssp whoami
```
