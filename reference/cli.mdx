Commands print text. Add `--json` to print one JSON document. Errors go to standard error and exit with status 1. With `--json`, an error is `{"error": "..."}`. Notes and warnings go to standard error. Pull requests start arms; the CLI records builds in CI, shows what runs, stops and resumes arms, and runs the proxy and the controller. The dashboard sets up repositories and edits settings. Read recorded data with SQL.
Use `STATESPACE_URL` to select a local or hosted API.

## Authentication

Sign in through GitHub, then approve the terminal's device code.

```shell
ssp login
ssp whoami
ssp logout
ssp logout --all
```

`whoami` shows the account, the credential in use, its scopes, and storage use. `logout --all` ends every session of the account. Use `SSP_TOKEN` for proxies and the controller. CI needs no token. Keep the output of `ssp token create` out of recorded logs.

## Tokens

A token opens the API and, with `query:read`, PostgreSQL. Statespace shows its secret only once, when you create it.

```shell
ssp token create --name production --preset runtime
ssp token create --name analyst --preset analyst --app atlas
ssp token create --name agent --expires-in-days 30 \
  --scope experiments:write --scope query:read
ssp token list
ssp token revoke tok_123
ssp token revoke --all --yes
```

| Preset | Scopes | For |
| --- | --- | --- |
| `runtime` | `runtime:read`, `events:write` | `ssp proxy` |
| `controller` | `runtime:read`, `events:write`, `arms:report` | `ssp controller kubernetes` |
| `analyst` | `query:read` | SQL clients |
| `admin` | every scope, including `tokens:manage` | Agents that run the whole loop |

`--app` limits what the token reads in SQL to one app's views; it needs `query:read`. `token list` shows tokens and sign-in sessions without their secrets. `revoke --all` revokes every token and session of the account, and ends their database sessions.

A token with `query:read` also has a database URL. Its user is the token's ID and its password is the token. Connect over TLS to your workspace hostname, such as `acme.statespace.app`, with `sslmode=verify-full`. Use a PostgreSQL 16 or newer client for the URL's `sslrootcert=system`; older clients must replace that parameter with the path to a trusted public CA bundle.

## Apply

In GitHub Actions, record the image of the job's commit. On the default branch, it becomes a default build. On an `exp/` branch, it becomes a version of the arm.

```shell
ssp apply --image ghcr.io/acme/atlas@sha256:4f2a…
ssp apply --image ghcr.io/acme/atlas:main --dry-run
```

| Flag | Meaning |
| --- | --- |
| `--image` | The image by tag or digest, or `STATESPACE_IMAGE`. A tag is resolved with `docker` |
| `--file` | The path of `statespace.toml`. Defaults to `statespace.toml` |
| `--dry-run` | Check `statespace.toml` and print the plan, but record nothing. It also works outside CI |

`apply` needs the job's OIDC token: the workflow needs `id-token: write`. The [Statespace action](https://github.com/statespace-tech/action) runs it.

## Status

Show what runs, and why.

```shell
ssp status
ssp status https://github.com/acme/atlas/pull/418
ssp status https://github.com/acme/atlas
ssp status services/search
```

A target is a pull request URL, a repository URL, or a path. Without a target, `status` shows the arm of the `exp/` branch that you checked out, else the app of the nearest `statespace.toml`, else the repository that you are in, else every app.

## Stop and resume

Stop arms at once. The Statespace App makes the pull requests drafts, and comments who stopped them. Their subjects get the default.

```shell
ssp stop https://github.com/acme/atlas/pull/418
ssp stop https://github.com/acme/atlas
ssp stop .
```

| Target | Means |
| --- | --- |
| `https://github.com/acme/atlas/pull/418` | That pull request's arm, in every app it runs in |
| `https://github.com/acme/atlas` | Every arm of the repository's apps |
| `.` or `services/search` | The app of the nearest `statespace.toml`; without one, the repository |

Mark the pull requests that a stop made drafts ready for review. Each arm runs again while its pull request can merge. A draft that a person made stays a draft.

```shell
ssp resume https://github.com/acme/atlas/pull/418
```

Give at least one target. Neither command asks for confirmation, so agents can run them. If some pull requests cannot change, the command lists them on standard error and exits with status 1. With `--json`, they are under `failed`.

To stop one arm in the normal way, make its pull request a draft:

```shell
gh pr ready 418 --undo
```

## Apps

The first build that CI records for an app creates it. Its name is also the name of its PostgreSQL schema. `statespace.toml` on the default branch sets its traffic limit and output retention; see [statespace.toml](/reference/experiment-definition). The dashboard shows each app's settings, and **Edit** opens a pull request that changes them.

Erase a subject or delete an app on the **Apps** page of the dashboard, or with the API:

| Request | Does |
| --- | --- |
| `DELETE /v1/apps/{app}/subjects/{subject}` | Erase a subject's runs, requests, and lines in one app |
| `DELETE /v1/apps/{app}` | Delete an app and all its data. Every arm must be stopped |

You cannot undo either.

## Proxy and controller

Run the reverse proxy in front of an app. See [Proxy](/reference/proxy) for every flag.

```shell
ssp proxy --app atlas --image ghcr.io/acme/atlas:main
ssp proxy --app atlas --default http://localhost:8000
```

Run the arms on Kubernetes. See [Controller](/reference/controller).

```shell
ssp controller kubernetes --app atlas --deployment atlas
```

## Storage and retention

Events have a 64 KiB size limit and a 90-day retention limit. The lines arms print follow their app's shorter `output_retention_days`. The quota is 1 GiB on the free plan and 10 GiB on other plans; `ssp whoami` shows its use. Usage warns at 80%; new events are rejected when the quota is full.

## Subject erasure

Erase a subject's persisted and pending runs, requests, and the lines that name it in one app, from the dashboard or with `DELETE /v1/apps/{app}/subjects/{subject}`.

Erased data can remain in encrypted backups until backup retention expires. Operators must reapply later erasures after restoring an older snapshot. The erasure audit record retains the subject identifier as metadata.
