Every command except `ssp proxy` and `ssp controller` prints one JSON document. Errors print `{"error": "..."}` on standard error and exit with status 1. The CLI changes things; read recorded data with SQL.
Use `STATESPACE_URL` to select a local or hosted API.

## Authentication

Sign in through GitHub or Google, then approve the terminal's device code.

```shell
ssp login
ssp whoami
ssp logout
ssp logout --all
```

`whoami` shows the account, the credential in use, its scopes, and storage use. `logout --all` ends every session of the account. Use `SSP_TOKEN` for CI, proxies, and the controller. Keep creation responses out of recorded logs.

## Tokens

A token opens the API and, with `query:read`, PostgreSQL. Its secret appears only in the create response.

```shell
ssp token create --name production --preset runtime
ssp token create --name analyst --preset analyst --app atlas
ssp token create --name agent --scope experiments:write --scope query:read --expires-in-days 30
ssp token list
ssp token revoke tok_123
ssp token revoke --all --yes
```

| Preset | Scopes | For |
| --- | --- | --- |
| `runtime` | `runtime:read`, `events:write` | `ssp proxy` |
| `controller` | `runtime:read`, `events:write`, `variants:report` | `ssp controller` |
| `publisher` | `experiments:write` | CI that publishes variants |
| `analyst` | `query:read` | SQL clients |
| `admin` | every scope, including `tokens:manage` | Agents that run the whole loop |

`--app` limits what the token reads in SQL to one app's views; it needs `query:read`. `token list` shows tokens and sign-in sessions without their secrets. `revoke --all` revokes every token and session of the account, and ends their database sessions.

A token with `query:read` returns a `database_url`. Its user is the token's ID and its password is the token. Connect over TLS to your workspace hostname, such as `acme.statespace.app`, with `sslmode=verify-full`. Use a PostgreSQL 16 or newer client for the URL's `sslrootcert=system`; older clients must replace that parameter with the path to a trusted public CA bundle.

## Signing keys

Create a signing key pair. Nothing is stored. Keep the private key in CI as `SSP_SIGNING_KEY`, and give the public key to proxies and the controller.

```shell
ssp keygen
```

## Apps

Create an app. Its name is also the name of its PostgreSQL schema.

```shell
ssp app create atlas
ssp app create atlas --output-retention-days 14
ssp app update atlas --output-retention-days 30
ssp app list
ssp app show atlas
ssp app erase-subject atlas u_42
ssp app delete atlas --yes
```

`ssp app list` shows the share of subjects running experiments hold. Deleting an app needs every experiment stopped.

## Variants

Sign an image and publish it as the variant's next version.

```shell
ssp variant create atlas-search --app atlas --image ghcr.io/acme/atlas:new-ranking
ssp variant create atlas-search --app atlas --image ghcr.io/acme/atlas@sha256:4f2a… --commit 4f2a9c1
```

| Flag | Meaning |
| --- | --- |
| `--app` | The app, or `STATESPACE_APP` |
| `--image` | The image by tag or digest. A tag is resolved with `docker`, pulling it when it is not local |
| `--commit` | The commit the image was built from. Defaults to `GITHUB_SHA` and the like, or the current directory's Git `HEAD` |
| `--signing-key` | The base64 private key, or `SSP_SIGNING_KEY` |

The same digest and commit reuse the newest version.

```shell
ssp variant list --app atlas
ssp variant show atlas-search --app atlas
ssp variant delete atlas-search --app atlas --yes
```

`show` lists every version. A variant that a draft or running experiment uses cannot be deleted.

## Experiments

Create a draft.

```shell
ssp experiment create rank-v2 --app atlas --split atlas-search=0.05 \
  --subject 'request.headers["x-user-id"]' \
  --eligibility 'request.headers["cf-ipcountry"] == "US"' \
  --description 'Test sorted search results.' --note 'Sorted results should get more clicks.'
```

Change the draft. `--split` replaces the draft's arms, and `--no-eligibility` removes the rule.

```shell
ssp experiment update rank-v2 --split atlas-search=0.05 --split atlas-search-bm25=0.05
ssp experiment update rank-v2 --split atlas-search=0.2 --note 'No regressions at 5%.'
ssp experiment update rank-v2 --no-eligibility
```

Publish and run the draft, stop it, or restart a published version.

```shell
ssp experiment start rank-v2 --note 'First run.'
ssp experiment stop rank-v2 --note 'Ship atlas-search.'
ssp experiment start rank-v2 --version 1
```

Read experiments. Each shows `split`, every arm's share of all subjects.

```shell
ssp experiment list --app atlas
ssp experiment show rank-v2
```

Delete a stopped experiment with all of its versions, runs, and notes.

```shell
ssp experiment delete rank-v2 --yes
```

See [Experiment definition](/reference/experiment-definition) for every field.

## Proxy and controller

Run the reverse proxy in front of an app. See [Proxy](/reference/proxy) for every flag.

```shell
ssp proxy --app atlas --runtime docker --image ghcr.io/acme/atlas:main --trust-key "$SSP_PUBLIC_KEY"
ssp proxy --app atlas --runtime kubernetes --default http://localhost:8000
```

Run the arms on Kubernetes. See [Controller](/reference/controller).

```shell
ssp controller --app atlas --deployment atlas --trust-key "$SSP_PUBLIC_KEY"
```

## Storage and retention

Events have a 64 KiB size limit and a 90-day retention limit. The lines arms print follow their app's shorter `--output-retention-days`. The quota is 1 GiB on the free plan and 10 GiB on other plans; `ssp whoami` shows its use. Usage warns at 80%; new events are rejected when the quota is full.

## Subject erasure

Erase a subject's persisted and pending runs, requests, and the lines that name it in one app.

```shell
ssp app erase-subject atlas u_42
```

Erased data can remain in encrypted backups until backup retention expires. Operators must reapply later erasures after restoring an older snapshot. The erasure audit record retains the subject identifier as metadata.
