Every command except `ssp host` prints one JSON document. Errors print `{"error": "..."}` on standard error and exit with status 1.
Use `STATESPACE_URL` to select a local or hosted API.

## Authentication

Sign in through GitHub or Google, then approve the terminal's device code.

```shell
ssp login
ssp account
ssp logout
```

Use `SSP_API_KEY` for CI and `ssp host`. Keep creation responses out of recorded logs.

## API keys

Create a runtime key for `ssp host`. It reads configurations and writes events.

```shell
ssp key create --name production --preset runtime
ssp key list
ssp key revoke key_123
```

Secrets appear only in create responses. Use the `admin` preset only for management tools, such as CI that publishes variants. Add `--expires-in-days` to set an expiration.

## Apps

Create an app. Its name is also the name of its PostgreSQL schema.

```shell
ssp app create atlas
ssp app create atlas --output-retention 14
ssp app update atlas --output-retention 30
ssp app list
ssp app show atlas
ssp app hosts atlas
ssp app outcomes atlas
ssp app erase-subject atlas u_42
ssp app delete atlas --yes
```

An app name has 1 to 40 lowercase letters, digits, and underscores, and starts with a letter. `--output-retention` sets how many days captured output is kept. `ssp app list` shows how much traffic running experiments hold. `ssp app hosts` lists hosts that reported in the last day. `ssp app outcomes` lists the outcome names recorded in the last 30 days. Deleting an app needs every experiment stopped.

## Variants

Create a signing key pair once. Keep the private key in CI as `SSP_SIGNING_KEY`.

```shell
ssp variant keygen
```

Package, sign, and upload a ready-to-run directory as the variant's next version.

```shell
ssp variant create atlas-search ./build --app atlas
ssp variant create atlas-search ./build --app atlas --command "uvicorn atlas.server:app --port {port}"
ssp variant create atlas-search ./build --app atlas --commit 4f2a9c1 --sign-key "$KEY"
```

| Flag | Meaning |
| --- | --- |
| `--app` | The app, or `STATESPACE_APP` |
| `--command` | How to start this variant, with `{port}`. Defaults to the host's command |
| `--commit` | The commit the build came from. Defaults to the directory's Git `HEAD` |
| `--sign-key` | The base64 private key, or `SSP_SIGNING_KEY` |

The bundle leaves out the directory's `.git`. Identical files, command, and commit reuse the newest version.

Read and delete variants.

```shell
ssp variant list --app atlas
ssp variant show atlas-search --app atlas
ssp variant logs atlas-search --app atlas --limit 200
ssp variant delete atlas-search --app atlas --yes
```

`show` lists every version. `logs` merges lifecycle events and captured output, newest first. A variant that a draft or running experiment uses cannot be deleted.

## Experiments

Create a draft.

```shell
ssp experiment create rank-v2 --app atlas --variant atlas-search=0.5 --traffic 0.2 \
  --subject 'request.headers["x-user-id"]' \
  --eligibility 'request.headers["cf-ipcountry"] == "US"' \
  --description 'Test sorted search results.' --note 'Sorted results should get more clicks.'
```

Change the draft. `--variant` replaces the draft's variants, and `--no-eligibility` removes the rule.

```shell
ssp experiment update rank-v2 --variant atlas-search=0.25 --variant atlas-search-bm25=0.25
ssp experiment update rank-v2 --traffic 0.5 --note 'No regressions at 20%.'
ssp experiment update rank-v2 --no-eligibility
```

Publish and run the draft, stop it, or restart a published version.

```shell
ssp experiment start rank-v2 --note 'First run.'
ssp experiment stop rank-v2 --note 'Ship atlas-search.'
ssp experiment start rank-v2 --version 1
```

Read experiments and results.

```shell
ssp experiment list --app atlas
ssp experiment show rank-v2
ssp experiment results rank-v2 --outcome click
ssp experiment results rank-v2 --outcome purchase --metric amount --version 2
```

Results count each subject once, in the variant it was assigned, even when control served it because the variant was unavailable. Each variant reports its `subjects`, how many of them were `unavailable`, how many `converted`, the `mean` value, and its `effect` against control with a 95% interval. Once 100 subjects ran, `sample_ratio` tests whether subjects split as the weights say. A `mismatch` means the effects cannot be trusted.

Delete a stopped experiment with all of its versions, runs, and notes.

```shell
ssp experiment delete rank-v2 --yes
```

See [Experiment definition](/reference/experiment-definition) for every field.

## Host

Run an app and its variants behind the proxy. See [Host](/reference/host) for every flag.

```shell
ssp host --app atlas --command "gunicorn -b 127.0.0.1:{port} atlas:app" --trust-key "$SSP_PUBLIC_KEY"
```

## Database credentials

Create a read-only PostgreSQL credential. Its connection URL appears only once.

```shell
ssp database credential create --name analyst --app atlas
ssp database credential create --name notebook
ssp database credential list
ssp database credential revoke dbc_123
```

A credential with `--app` reads only that app's schema of views. Without it, a credential reads every app, including apps created later. It cannot write data or connect to another account database.
Connect directly over TLS to your workspace hostname, such as `acme.statespace.app`. Use `sslmode=verify-full` to validate the public certificate. The CLI has no SQL query command
and the API has no SQL query endpoint.

Use a PostgreSQL 16 or newer client for the returned URL's `sslrootcert=system`. Older clients must replace that parameter with the path to a trusted public CA bundle. Keep `sslmode=verify-full`.

Query an app's views with your own SQL client and protected connection settings.

```shell
psql -c 'SELECT * FROM atlas.logs LIMIT 20'
```

## Sessions

List or revoke CLI sessions without exposing their secrets.

```shell
ssp token list
ssp token revoke tok_123
ssp token revoke-all --yes
```

`revoke-all` revokes account API keys, CLI sessions, and browser sessions.

## Audit and storage

Read account audit records and the event storage quota.

```shell
ssp audit --limit 50
ssp audit --limit 50 --before 4821
ssp storage
```

Audit reads require `audit:read`. Records include a `source` field identifying
the control or tenant ledger. IDs support pagination across both ledgers; they
do not define time order. Use `occurred_at` to order events by time.

Events have a 64 KiB size limit and a 90-day retention limit. Captured output follows its app's shorter `--output-retention`. The quota is 1 GiB on the free plan and 10 GiB on other plans. Usage warns at 80%; new events
are rejected when the quota is full.

## Subject erasure

Erase a subject's persisted and pending runs, outcomes, and requests in one app.

```shell
ssp app erase-subject atlas u_42
```

Erased data can remain in encrypted backups until backup retention expires.
Operators must reapply later erasures after restoring an older snapshot. The
erasure audit record retains the subject identifier as metadata.
