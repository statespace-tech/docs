`ssp` adds and removes apps and tokens, sets the arms of experiments, starts and stops experiments, runs the proxy, and gives your SQL login. The proxy runs on Docker, Kubernetes, Cloud Run, ECS Fargate, Fly.io, S3, and Cloud Storage. Install it with the [install script](/getting-started/installation#cli).

```text
ssp app         add | remove | list | show
ssp experiment  list | show | update | start | stop
ssp token       add | remove | list
ssp db          url | rotate
ssp proxy       docker | cloudrun | kubernetes | fargate | fly
                | s3 | gcs
ssp login | logout | whoami
```

## Conventions

- Commands have the form `ssp <noun> <verb> <object>`. The object is positional, such as the app name or the experiment name.
- `--app` names the app of an experiment, a token, or a proxy. You can leave it out when the current folder is linked to exactly one app. `ssp proxy` always needs it.
- A commit is the full commit or its first 7 characters or more.
- A share is a fraction, such as `0.05`. It is never `5` or `5%`.
- No command asks a question, except `ssp login`.
- `ssp app add` and `ssp experiment update` print what they found and chose.
- Each command that changes something prints exactly what it changed.

## Common flags

<ParamField body="--json" type="boolean">
  Print exactly one JSON document on standard output. All commands take it, except `ssp proxy`. The document is the response of the [API](/reference/api) route that the command calls.
</ParamField>

<ParamField body="--note" type="string">
  Free text for people and agents, 1 to 200 characters on one line. All commands that change something take it. The dashboard, `ssp app show`, and `ssp experiment show` show it.
</ParamField>

<ParamField body="--app" type="string">
  The app. Required when the current folder is not linked to exactly one app.
</ParamField>

## Output and exit codes

- Results go to standard output. Notes and warnings go to standard error.
- An error exits with status 1. With `--json`, the error is `{"error": "..."}`.

## ssp app add

Add an app. It is linked to a repo and to the folder of its `statespace.toml`. You need the admin role on the repo.

```shell
ssp app add shop-prod --note "shop, production"
```

<ParamField body="name" type="string" required>
  The name of the app: 1 to 63 lowercase letters, digits, and `-`. It must be unique in the workspace.
</ParamField>

<ParamField body="--repo" type="string">
  The repo, as `owner/name`, such as `acme/shop`. Default: the repo of the `origin` remote of the current folder.
</ParamField>

<ParamField body="--path" type="string">
  The folder of `statespace.toml`, from the root of the repo. Default: the folder of the nearest `statespace.toml`.
</ParamField>

The command prints the repo and the folder that it found, and the app that it added. It fails outside a repo, without a GitHub remote, or when the folder has no `statespace.toml`. With `--json`, it prints the `App`.

## ssp app remove

Delete an app and all its data. You need the admin role on the repo.

```shell
ssp app remove shop-dev
```

<ParamField body="name" type="string" required>
  The app.
</ParamField>

The command fails while an experiment of the app runs. It prints what it deleted. With `--json`, it prints `{"deleted": App}`.

<Warning>
  You cannot undo `ssp app remove`. The evidence of all experiments of the app is deleted.
</Warning>

## ssp app list

List the apps: repo, folder, live commit, and running experiments.

```shell
ssp app list
```

With `--json`, it prints `{"apps": [App]}`.

## ssp app show

Show an app in full: the live commit and when it was built, the experiments and their state, the settings that apply and their source commit, the proxy instances, the orchestrator, and the lease holder.

```shell
ssp app show shop-prod
```

<ParamField body="name" type="string" required>
  The app.
</ParamField>

With `--json`, it prints the `AppDetail`.

## ssp experiment list

List the experiments of an app: state, version, arms, and the headline metric.

```shell
ssp experiment list --app shop-prod
```

<ParamField body="--running" type="boolean">
  Show only the running experiments.
</ParamField>

<ParamField body="--all" type="boolean">
  Also show the experiments that are `gone`: their table is not in the live `statespace.toml`.
</ParamField>

With `--json`, it prints `{"experiments": [Experiment]}`.

## ssp experiment show

Show an experiment in full:

- the definition, and the commit that it comes from;
- the arms with their shares, and the reference;
- the evidence of the current or last version for each arm: totals, metrics, the split check, and the top events;
- the versions, and the history of starts, stops, and metric changes;
- the drift from live, such as "live is now f2f2f2f" or "live c0ffee1 contains a1b2c3d";
- the override link of each arm while the experiment runs, such as `?ssp=checkout:a1b2c3d`.

```shell
ssp experiment show checkout --app shop-prod
```

<ParamField body="name" type="string" required>
  The experiment.
</ParamField>

With `--json`, it prints the `ExperimentDetail`.

## ssp experiment update

Add arms, change their shares, or remove them. Only the arms that you name change. You need the role Write or Maintain on the repo.

```shell
ssp experiment update checkout --app shop-prod \
  --arm c0ffee1=0.05 --arm a1b2c3d=0.05
```

<ParamField body="name" type="string" required>
  The experiment.
</ParamField>

<ParamField body="--arm" type="string">
  `<commit>=<share>`. Repeat it for each arm. The share is a fraction.

  - A new commit is added with the share.
  - A commit that is an arm gets the new share.
  - `=0` removes the arm. Its evidence stays.
</ParamField>

These examples change the arms of `checkout`:

```shell
# Add e5f6a7b.
ssp experiment update checkout --arm e5f6a7b=0.04
# Change the share of c0ffee1.
ssp experiment update checkout --arm c0ffee1=0.06
# Remove e5f6a7b.
ssp experiment update checkout --arm e5f6a7b=0
# Replace a1b2c3d with f6a7b8c.
ssp experiment update checkout \
  --arm a1b2c3d=0 --arm f6a7b8c=0.05
```

The command prints the change and the full list of arms after it. `-` marks a removed arm, and `+` an added arm:

```text
checkout · shop-prod · stopped
  − a1b2c3d   0.05
  + f6a7b8c   0.05
    c0ffee1   0.06   (reference)
  total 0.11 of max_traffic 0.2
```

Without `--arm`, the command prints the current list.

The command fails, and changes nothing, when:

- the experiment runs: "checkout is running. Stop it first: ssp experiment stop checkout";
- the shares add up to more than `max_traffic`;
- a commit has no build for the app: "No build of a1b2c3d for shop-prod. Push it so CI builds it.";
- a prefix matches more than one build. The error lists the matches;
- `=0` names a commit that is not an arm: "e5f6a7b is not an arm of checkout".

With `--json`, it prints `{"experiment": Experiment, "added", "changed", "removed"}`.

## ssp experiment start

Start a new version of the experiment. You need the role Write or Maintain on the repo.

```shell
ssp experiment start checkout --app shop-prod \
  --note "one-page checkout"
```

<ParamField body="name" type="string" required>
  The experiment.
</ParamField>

The command checks, in this order:

1. The experiment has 2 or more arms.
2. The shares add up to `max_traffic` or less.
3. Each arm has a build for the app.
4. The shares of all running experiments of the app, and of this one, add up to 1 or less.

When a check fails, nothing changes, and the command says why. Then the experiment is `starting`. The command waits, and prints each arm when it is ready. When each arm is ready, the experiment is `running`.

When an arm is not ready in 5 minutes, the copies stop, and the experiment is `stopped` again. The command gives the reason for each arm:

```text
starting checkout on shop-prod
  c0ffee1   ready
  a1b2c3d   not ready: the container exits at start (exit 1)
checkout did not start. Nothing changed.
```

The command also tells you when the experiment can claim the requests of another running experiment, for example: "checkout and us-landing can claim the same requests; checkout is first in statespace.toml".

With `--json`, it prints the `Experiment` in its last state.

## ssp experiment stop

Stop one or more experiments. Their arms leave traffic in seconds. You need the role Write or Maintain on the repo.

```shell
ssp experiment stop checkout us-landing --app shop-prod \
  --note "incident 214"
```

<ParamField body="name" type="string" required>
  One or more experiments.
</ParamField>

A stop on a stopped experiment returns it unchanged. With `--json`, it prints the stopped experiments. See [Stop in an emergency](/guides/emergency-stop).

## ssp token add

Add a runtime token for one app. You need the admin role on the repo. The command prints the secret only one time.

```shell
ssp token add --app shop-prod --note "Cloud Run proxy"
```

<ParamField body="--app" type="string" required>
  The app of the token.
</ParamField>

<Warning>
  Keep the output out of logs. Statespace cannot show the secret again.
</Warning>

## ssp token remove

Remove a runtime token.

```shell
ssp token remove <id>
```

<ParamField body="id" type="string" required>
  The ID of the token. `ssp token list` shows it.
</ParamField>

## ssp token list

List the runtime tokens, without their secrets.

```shell
ssp token list
```

## ssp db url

Print the connection string of your PostgreSQL login. The login only reads.
It reads the apps whose repo you can read. The command needs the session of
`ssp login`. See [Query your data with SQL](/guides/sql).

```shell
psql "$(ssp db url)"
```

<ParamField body="--account" type="string">
  The workspace, such as `acme`. Required when you are in more than one
  workspace.
</ParamField>

<ParamField body="--verify" type="flag">
  Check the certificate of the server with the trust store of the system.
  The connection string has `sslmode=verify-full&sslrootcert=system` in place
  of `sslmode=require`. It needs psql or libpq 16 or later.
</ParamField>

Standard output has only the connection string. Standard error says which
apps the login reads. With `--json`, it prints `url`, `account`, `host`,
`port`, `database`, `user`, `password`, `sslmode`, and `apps`. The password
stays the same until `ssp db rotate`.

## ssp db rotate

Give your PostgreSQL login a new password. The old password stops at once,
and its sessions end.

```shell
ssp db rotate --note "pasted in a chat"
```

<ParamField body="--account" type="string">
  The workspace, such as `acme`. Required when you are in more than one
  workspace.
</ParamField>

<ParamField body="--verify" type="flag">
  Print the new connection string with full verification, as
  `ssp db url --verify` does.
</ParamField>

It prints the new connection string, as `ssp db url` does.

## ssp proxy docker

Run the proxy on a machine with Docker. Live and the arms run as containers. See [Docker](/guides/docker).

```shell
ssp proxy docker --app shop-dev \
  --image-file /etc/shop/image
```

<ParamField body="--image-file" type="string" required>
  A file that holds the live image. When the file changes, the proxy deploys the new live.
</ParamField>

<ParamField body="--health" type="string">
  A path, such as `/health`. An arm is ready when this path answers with a 2xx status. Without it, an arm is ready when it accepts a TCP connection.
</ParamField>

The [proxy flags](#proxy-flags) also apply.

## ssp proxy cloudrun

Run the proxy in front of a Cloud Run service. Each arm runs as a tagged revision of the service. See [Cloud Run](/guides/cloud-run).

```shell
ssp proxy cloudrun --app shop-prod \
  --service shop --region us-east1
```

<ParamField body="--service" type="string" required>
  The Cloud Run service that runs live.
</ParamField>

<ParamField body="--region" type="string" required>
  The region of the service, such as `us-east1`.
</ParamField>

<ParamField body="--project" type="string">
  The Google Cloud project. Default: the project of the proxy.
</ParamField>

The [proxy flags](#proxy-flags) also apply.

## ssp proxy kubernetes

Run the proxy in front of a Kubernetes Deployment. Each arm runs as a copy of the Deployment. See [Kubernetes](/guides/kubernetes).

```shell
ssp proxy kubernetes --app shop-prod \
  --deployment shop --namespace prod
```

<ParamField body="--deployment" type="string" required>
  The Deployment that runs live.
</ParamField>

<ParamField body="--namespace" type="string">
  The namespace of the Deployment.
</ParamField>

<ParamField body="--service" type="string">
  The Service of live. Default: the name of the Deployment.
</ParamField>

<ParamField body="--container" type="string">
  The container of the app in the pod. Default: the first container.
</ParamField>

The [proxy flags](#proxy-flags) also apply.

## ssp proxy fargate

Run the proxy in front of an ECS service on Fargate. Each arm runs as an ECS service in the same cluster, from a copy of the task definition with another image. See [ECS Fargate](/guides/fargate).

```shell
ssp proxy fargate --app shop-prod \
  --cluster shop --service shop \
  --live-url http://internal-shop.example.com
```

<ParamField body="--cluster" type="string" required>
  The ECS cluster of the service.
</ParamField>

<ParamField body="--service" type="string" required>
  The ECS service that runs live.
</ParamField>

<ParamField body="--region" type="string">
  The AWS region of the cluster. Default: the region of the AWS configuration, such as `AWS_REGION`.
</ParamField>

<ParamField body="--live-url" type="string">
  Where the proxy sends live traffic, such as the URL of the internal load balancer of live. Default: the first Service Connect name of live.
</ParamField>

<ParamField body="--container" type="string">
  The container of the app in the task definition. Default: the first container with a port mapping.
</ParamField>

<ParamField body="--unit-ip" type="string" default="private">
  The IP address of a task of an arm that the proxy sends to: `private` or `public`. Use `public` only when the proxy runs outside the VPC of the tasks, such as in a test.
</ParamField>

The proxy uses the AWS default credential chain. The [proxy flags](#proxy-flags) also apply.

## ssp proxy fly

Run the proxy in front of a Fly.io app. Each arm runs as a Machine of the app, without services. See [Fly.io](/guides/fly).

```shell
ssp proxy fly --app shop-prod --fly-app shop
```

<ParamField body="--fly-app" type="string" required>
  The Fly.io app whose Machines run live.
</ParamField>

<ParamField body="--fly-token" type="string" required>
  A Fly.io token that can manage the Machines of the app, such as a deploy token. Environment variable: `FLY_API_TOKEN`.
</ParamField>

<ParamField body="--process-group" type="string" default="app">
  The process group of live.
</ParamField>

<ParamField body="--region" type="string">
  The region of the Machines of the arms. Default: the region of a live Machine.
</ParamField>

<ParamField body="--port" type="number">
  The port that the app listens on. Default: the internal port of the first service of live.
</ParamField>

<ParamField body="--live-url" type="string">
  Where the proxy sends live traffic. Default: `http://<fly app>.flycast`.
</ParamField>

The [proxy flags](#proxy-flags) also apply.

## ssp proxy s3

Run the proxy in front of a static site in an S3 bucket, or in an S3-compatible store. Live is the root of the bucket. Each arm is the build folder of its commit. The proxy only reads the bucket. See [S3](/guides/s3).

```shell
ssp proxy s3 --app site-prod --bucket acme-site \
  --region us-east-1 --cache
```

<ParamField body="--bucket" type="string" required>
  The bucket of the site. Live is its root.
</ParamField>

<ParamField body="--endpoint" type="string">
  The address of an S3-compatible store, such as Cloudflare R2, Backblaze B2, DigitalOcean Spaces, or MinIO. The proxy puts the bucket in the path of each request. Default: Amazon S3. Environment variable: `AWS_ENDPOINT_URL_S3`.
</ParamField>

<ParamField body="--region" type="string">
  The region of the bucket. Default: the region of the AWS configuration, such as `AWS_REGION`. With `--endpoint`, the default is `us-east-1`.
</ParamField>

<ParamField body="--cache" type="boolean">
  Keep files in memory, in one cache of 256 MB: the files of an arm until the arm stops, and the files of live for 10 seconds. Default: off.
</ParamField>

<ParamField body="--fallback" type="string">
  A file of each build, such as `200.html`, for a single-page app. A path without a file extension that matches no file gets this file of the same build, with the status 200.
</ParamField>

The proxy uses the AWS default credential chain and SigV4. It needs `s3:ListBucket` and `s3:GetObject` on the bucket. The [proxy flags](#proxy-flags) also apply.

## ssp proxy gcs

Run the proxy in front of a static site in a Cloud Storage bucket. Live is the root of the bucket. Each arm is the build folder of its commit. The proxy only reads the bucket. See [Cloud Storage](/guides/gcs).

```shell
ssp proxy gcs --app site-prod --bucket acme-site --cache
```

<ParamField body="--bucket" type="string" required>
  The bucket of the site. Live is its root.
</ParamField>

<ParamField body="--cache" type="boolean">
  Keep files in memory, as for [`ssp proxy s3`](#ssp-proxy-s3). Default: off.
</ParamField>

<ParamField body="--fallback" type="string">
  A file of each build for a single-page app, as for [`ssp proxy s3`](#ssp-proxy-s3).
</ParamField>

The proxy uses Google credentials: the metadata server, or Application Default Credentials. Its account needs Storage Object Viewer on the bucket. The [proxy flags](#proxy-flags) also apply.

## Proxy flags

Each `ssp proxy` command takes these flags. All other settings come from [`statespace.toml`](/reference/statespace-toml).

<ParamField body="--app" type="string" required>
  The app. The command fails when the app does not exist. Environment variable: `STATESPACE_APP`.
</ParamField>

<ParamField body="--listen" type="string" default="0.0.0.0:8080">
  The address that the proxy listens on.
</ParamField>

<ParamField body="--token" type="string">
  The runtime token of the app. Environment variable: `STATESPACE_TOKEN`.
</ParamField>

<ParamField body="--api" type="string" default="https://api.statespace.com">
  The Statespace API. Environment variable: `STATESPACE_API`.
</ParamField>

`ssp proxy` prints no JSON document. It passes HTTP/1.1, HTTP/2, and WebSocket.

## ssp login

Sign in with GitHub. The CLI shows a code. Approve the code in the browser. This is the only command that waits for you.

```shell
ssp login
```

## ssp logout

Sign this terminal out.

```shell
ssp logout
```

## ssp whoami

Show who is signed in, and the credential that the CLI uses.

```shell
ssp whoami
```
