Commands print text. Add `--json` to print one JSON document. Errors go to standard error and exit with status 1. With `--json`, an error is `{"error": "..."}`. Notes and warnings go to standard error. Pull requests start arms; the CLI sets up repositories, records builds in CI, shows experiments, and stops arms. Read recorded data with SQL.
Use `STATESPACE_URL` to select a local or hosted API.

## Authentication

Sign in through GitHub, then approve the terminal's device code.

```shell
ssp login
ssp whoami
ssp logout
ssp logout --all
```

`whoami` shows the account, the credential in use, its scopes, and storage use. `logout --all` ends every session of the account. Use `SSP_TOKEN` for proxies and the controller. CI needs no token. Keep the output of `ssp token create` out of recorded logs.

## Tokens

A token opens the API and, with `query:read`, PostgreSQL. Statespace shows its secret only once, when you create it.

```shell
ssp token create --name production --preset runtime
ssp token create --name analyst --preset analyst --app atlas
ssp token create --name agent --scope experiments:write --scope query:read --expires-in-days 30
ssp token list
ssp token revoke tok_123
ssp token revoke --all --yes
```

| Preset | Scopes | For |
| --- | --- | --- |
| `runtime` | `runtime:read`, `events:write` | `ssp proxy` |
| `controller` | `runtime:read`, `events:write`, `arms:report` | `ssp controller kubernetes` |
| `analyst` | `query:read` | SQL clients |
| `admin` | every scope, including `tokens:manage` | Agents that run the whole loop |

`--app` limits what the token reads in SQL to one app's views; it needs `query:read`. `token list` shows tokens and sign-in sessions without their secrets. `revoke --all` revokes every token and session of the account, and ends their database sessions.

A token with `query:read` also has a database URL. Its user is the token's ID and its password is the token. Connect over TLS to your workspace hostname, such as `acme.statespace.app`, with `sslmode=verify-full`. Use a PostgreSQL 16 or newer client for the URL's `sslrootcert=system`; older clients must replace that parameter with the path to a trusted public CA bundle.

## Repositories

Install the Statespace GitHub App on the repositories that run experiments, and list them.

```shell
ssp repo connect
ssp repo list
```

Write `statespace.toml` and `.github/workflows/statespace.yml`. The command also prints the step to add to the workflow that builds production.

```shell
ssp init github --app atlas
ssp init github --app atlas --image ghcr.io/acme/atlas --force
```

| Flag | Meaning |
| --- | --- |
| `--app` | The app. Defaults to the directory's name |
| `--image` | The image repository CI pushes to. Defaults to `ghcr.io/<owner>/<repository>` from the `origin` remote |
| `--force` | Replace files that exist |

## Check and apply

Check `statespace.toml`, and test a request against its rules.

```shell
ssp check
ssp check --path /search --query q=maps --header cf-ipcountry=US --cookie ssp_sid=u_1
```

In GitHub Actions, record the image of the job's commit. On the default branch, it becomes a default build. On an `exp/` branch, it becomes a version of the arm.

```shell
ssp apply --image ghcr.io/acme/atlas@sha256:4f2a…
ssp apply --image ghcr.io/acme/atlas:main --dry-run
```

| Flag | Meaning |
| --- | --- |
| `--image` | The image by tag or digest, or `STATESPACE_IMAGE`. A tag is resolved with `docker` |
| `--file` | The path of `statespace.toml` |
| `--dry-run` | Check and print the plan, but record nothing. It also works outside CI |

`apply` needs the job's OIDC token: the workflow needs `id-token: write`. The [Statespace action](https://github.com/statespace-tech/action) runs it.

## Experiments

Show the experiments of an app, or one experiment with its arms, controls, and pull requests. `--app` defaults to the `app` of `statespace.toml`.

```shell
ssp status
ssp status ranking --app atlas
ssp status exp/ranking/recent-clicks
```

Stop every arm of an experiment, or one arm, at once. Their pull requests become drafts. Mark a pull request ready for review to run its arm again.

```shell
ssp stop ranking
ssp stop ranking/recent-clicks
```

To stop one arm in the normal way, make its pull request a draft.

## Apps

The first build that CI records for an app creates it. Its name is also the name of its PostgreSQL schema.

```shell
ssp app list
ssp app show atlas
ssp app set atlas --max-traffic 0.2
ssp app set atlas --output-retention-days 30
ssp app erase-subject atlas u_42
ssp app delete atlas --yes
```

`--max-traffic` limits the share of the app's subjects that experiments hold, arms and controls together. Arms that do not fit wait, first come, first served. A lower limit stops no arm that runs. Deleting an app needs every arm stopped.

## Proxy and controller

Run the reverse proxy in front of an app. See [Proxy](/reference/proxy) for every flag.

```shell
ssp proxy --app atlas --image ghcr.io/acme/atlas:main
ssp proxy --app atlas --default http://localhost:8000
```

Run the arms on Kubernetes. See [Controller](/reference/controller).

```shell
ssp controller kubernetes --app atlas --deployment atlas
```

## Storage and retention

Events have a 64 KiB size limit and a 90-day retention limit. The lines arms print follow their app's shorter `--output-retention-days`. The quota is 1 GiB on the free plan and 10 GiB on other plans; `ssp whoami` shows its use. Usage warns at 80%; new events are rejected when the quota is full.

## Subject erasure

Erase a subject's persisted and pending runs, requests, and the lines that name it in one app.

```shell
ssp app erase-subject atlas u_42
```

Erased data can remain in encrypted backups until backup retention expires. Operators must reapply later erasures after restoring an older snapshot. The erasure audit record retains the subject identifier as metadata.
