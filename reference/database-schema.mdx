title: Database schema
description: Review the tables and guarantees published through DuckDB.
---

Each project publishes one analytical DuckDB database through the Quack protocol. The database represents accepted data after retention and compaction.

## Database connection

Attach the project with a read-only token.

```sql
ATTACH 'quack:atlas-search.db.statespace.app:443' AS statespace (
  TOKEN 'ssp_ro_7j...'
);
```

Use DuckDB 2.0 or later.

## Experiments table

The `experiments` table contains one row for each retained revision.

| Column | Type |
| --- | --- |
| `name` | `VARCHAR` |
| `description` | `VARCHAR` |
| `revision` | `BIGINT` |
| `status` | `VARCHAR` |
| `sampling_traffic` | `DOUBLE` |
| `layer_name` | `VARCHAR` |
| `assignment_method` | `VARCHAR` |
| `assignment_strata` | `JSON` |
| `assignment_block_size` | `INTEGER` |
| `created_at` | `TIMESTAMP` |

## Data guarantees

The published schema provides these guarantees:

1. Event identifiers are unique within a project.
2. Accepted assignments do not change within one revision.
3. Every run references one accepted assignment.
4. Every outcome references one accepted run.
5. Timestamps use UTC.
6. Retention can remove complete historical records after the plan limit.

<Info>
  Parquet stores compacted columnar data. DuckDB provides the SQL interface and statistical aggregate functions. Clients do not need access to the underlying objects.
</Info>
