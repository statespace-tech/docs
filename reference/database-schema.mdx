---
title: PostgreSQL schema
description: Review each app's analysis views, the account's audit log, and what they hold.
---

Each account has one isolated PostgreSQL database. Each app has a schema of the same name, with views that show only that app's rows. Tokens with `query:read` can read these views and nothing else.

```text
atlas.logs          one row per run, with the lines its subject's arm printed after it
atlas.runs          each subject's routing by a proxy
atlas.output        every line the arms printed
atlas.requests      one row per request an arm served
atlas.metrics       per-minute HTTP summaries and resource use of each arm
atlas.lifecycle     arm events: started, ready, exited, stopped, failed
atlas.hosts         proxies and controllers that reported in the last day
atlas.arms          every arm and control of every version, and where it runs
atlas.pull_requests what the pull requests of experiment branches run, and why they wait
atlas.sample_ratio  whether each version's subjects split as its shares say
account.audit       every change to the account and its apps
```

The API commits events to an account outbox. The worker writes the final rows into tables in the `statespace` schema, which tokens cannot read. The default is never recorded.

## Runs

A proxy records a run the first time it routes a subject in an experiment version, and again at most every 30 minutes.

| Column | Type |
| --- | --- |
| `id` | `TEXT` |
| `timestamp` | `TIMESTAMPTZ` |
| `experiment` | `TEXT` |
| `experiment_version` | `INTEGER` |
| `subject_id` | `TEXT` |
| `arm` | `control` or an arm; `NULL` when ineligible |
| `commit` | The arm's commit, or a control's base commit; `NULL` when ineligible |
| `reason` | `assigned`, `ineligible`, `eligibility-error`, or `arm-unavailable` |
| `context` | `JSONB`: the request's `method` and `path` |
| `host` | `TEXT` |

An `arm-unavailable` run names the arm the subject was assigned. The default served it.

## Output

Each line an arm printed is one row. It is kept for the app's output retention.

| Column | Type |
| --- | --- |
| `id` | `TEXT` |
| `timestamp` | `TIMESTAMPTZ` |
| `experiment`, `experiment_version` | The arm's experiment |
| `arm`, `commit` | The arm: `control` or an arm, and its commit |
| `stream` | `stdout` or `stderr` |
| `line` | `TEXT`, after `--redact` |
| `data` | `JSONB`: the line's fields, when it is a JSON object |
| `subject_id` | The line's `subject` field, when it has one |
| `host` | `TEXT` |

## Logs view

`logs` has one row for each run and each line with a subject that followed it. Each line joins the latest run of its subject in the app that started at or before it. Runs without lines have `NULL` line columns.

| Column | Source |
| --- | --- |
| `run_id`, `run_timestamp`, `experiment`, `experiment_version`, `subject_id`, `arm`, `commit`, `reason`, `context` | The run |
| `output_id`, `output_timestamp`, `stream`, `line`, `data` | The line |

Compare arms with a SQL client.

```sql
SELECT
  experiment_version,
  arm,
  commit,
  count(DISTINCT subject_id) AS subjects,
  avg((data->>'position')::double precision) FILTER (WHERE data->>'event' = 'click') AS mean_position
FROM atlas.logs
WHERE experiment = 'ranking'
  AND reason IN ('assigned', 'arm-unavailable')
GROUP BY experiment_version, arm, commit;
```

## Sample ratio

`sample_ratio` has one row per arm and control of each experiment version: `arm`, `commit`, `share`, `subjects`, `expected`, the version's chi-square `statistic` and `p_value`, and `mismatch`. A mismatch is a p-value below 0.001 once 100 subjects ran. It means assignment or recording is broken, and comparisons between the arms cannot be trusted.

## Arm measurements

`requests` has one row per request an arm served: `subject_id`, `experiment`, `experiment_version`, `arm`, `commit`, `method`, `path`, `status`, `duration_ms`, `first_byte_ms`, `request_bytes`, and `response_bytes`. `duration_ms` runs to the response's last byte.

`metrics` has one row per arm and minute. `kind = 'http'` rows hold `requests`, `errors`, `statuses`, `p50_ms`, `p90_ms`, `p99_ms`, and `max_ms`. `kind = 'resources'` rows hold `cpu_percent` and `memory_bytes`, on Docker.

`lifecycle` has arm events with their `data`, such as an exit's `code`.

## Hosts and arms

`hosts` has the newest report of each proxy and controller: `id`, `kind` (`proxy` or `controller`), `version`, `seen_at`, `max_arms`, and `report`, what it runs.

`arms` has every arm and control of every experiment version: `experiment`, `experiment_version`, `kind` (`variant` or `control`), `arm`, `commit`, `base_commit`, `share`, `image`, the version's `status`, `started_at`, and `stopped_at`, and where a controller runs it: `address`, `ready`, and `replicas`. Compare a variant with the control whose `commit` is the variant's `base_commit`.

## Pull requests

`pull_requests` has the pull requests of the app's experiment branches: `repo`, `number`, `branch`, `head_commit`, `state`, `draft`, `review_decision`, `merge_state`, `merged_at`, `held_at` (an emergency stop), `running_commit`, `waiting` (why the head commit does not run), and `waiting_since`.

## Audit

`account.audit` has every change to the account and its apps: `id`, `occurred_at`, `source`, `actor`, `action`, `target`, and `detail`. Records of the account itself, such as new tokens and sign-ins, have the source `control`. Only tokens that read every app can read it.

Create a token for a SQL client. Statespace shows its database URL only once.

```shell
ssp token create --name analyst --preset analyst --app atlas
```
