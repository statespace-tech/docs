Each account publishes one analytical DuckDB database through the Quack protocol. The database contains accepted data after retention and compaction.

## Connect the database

Run `ssp account` to get the URL. Attach it with a read-only token and DuckDB 2.0 or later.

```sql
ATTACH 'quack:atlas-search.db.statespace.app:443' AS statespace (
  TOKEN 'ssp_ro_7j...'
);
```

## Experiments table

The `experiments` table contains one row for each experiment.

| Column | Type |
| --- | --- |
| `name` | `VARCHAR` |
| `description` | `VARCHAR` |
| `status` | `VARCHAR` |
| `assignment` | `VARCHAR` |
| `assignment_method` | `VARCHAR` |
| `assignment_strata` | `VARCHAR` containing JSON |
| `assignment_block_size` | `BIGINT` |
| `traffic` | `DOUBLE` |
| `layer_name` | `VARCHAR` |
| `created_at` | `VARCHAR` containing RFC 3339 time |

## Logs view

The `logs` view exposes records created by `run.log(...)`. Its `data` column uses DuckDB's `JSON` type.

```sql
SELECT
  group_name,
  avg(data.relevance::DOUBLE) AS mean_relevance
FROM statespace.logs
WHERE experiment_name = 'rank-v2'
GROUP BY group_name;
```

The view contains `id`, `timestamp`, `data`, `run_id`, `assignment_id`, `experiment_name`, `subject_id`, and `group_name`.

## Data guarantees

The published database provides these guarantees:

1. Event identifiers are unique within the account database.
2. An accepted subject assignment remains stable for its experiment.
3. Every run references one accepted assignment.
4. Every `run.log(...)` record references one accepted run.
5. Timestamps use UTC and RFC 3339 text.
6. Retention can remove historical records after the plan limit.

<Info>
  Parquet stores compacted columnar data. DuckDB provides the SQL interface and statistical aggregate functions. Clients do not need access to the underlying objects.
</Info>
