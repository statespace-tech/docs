---
title: PostgreSQL schema
description: Review each app's analysis views and the account database tables behind them.
---

Each account has one isolated PostgreSQL database. Each app has a schema of the same name, with views that show only that app's rows. Direct credentials can read these views and nothing else.

```text
atlas.logs        one row per run, with the outcomes that followed it
atlas.runs        each subject's routing by a host
atlas.outcomes    outcomes that processes printed
atlas.requests    one row per request, with --capture http
atlas.output      captured standard output and standard error lines
atlas.metrics     per-minute HTTP summaries and resource use
atlas.lifecycle   process events: started, ready, exited, stopped, failed
atlas.notes       notes on experiment changes
```

The API commits events to an account outbox. The worker writes the final rows into tables in the `statespace` schema, which credentials cannot read.

## Runs

A host records a run the first time it routes a subject in an experiment version, and again at most every 30 minutes.

| Column | Type |
| --- | --- |
| `id` | `TEXT` |
| `timestamp` | `TIMESTAMPTZ` |
| `experiment` | `TEXT` |
| `experiment_version` | `INTEGER` |
| `subject_id` | `TEXT` |
| `variant` | `control` or a variant; `NULL` when ineligible |
| `variant_version` | `INTEGER`, or `NULL` for control |
| `reason` | `assigned`, `ineligible`, `eligibility-error`, or `variant-unavailable` |
| `context` | `JSONB`: the request's `method` and `path` |
| `host` | `TEXT` |

A `variant-unavailable` run names the variant the subject was assigned. Control served it.

## Outcomes

Each outcome line a process printed becomes one row. Outcomes belong to a subject in an app, so any process can report them.

| Column | Type |
| --- | --- |
| `id` | `TEXT` |
| `timestamp` | `TIMESTAMPTZ` |
| `subject_id` | `TEXT` |
| `name` | `TEXT` |
| `data` | `JSONB`: every field of the line except `statespace` and `subject` |
| `variant`, `variant_version` | The process that printed it |
| `host` | `TEXT` |

## Logs view

`logs` has one row for each run and outcome it led to. Each outcome joins the latest run of the same subject in the app that started at or before it. Runs without outcomes have `NULL` outcome columns.

| Column | Source |
| --- | --- |
| `run_id`, `run_timestamp`, `experiment`, `experiment_version`, `subject_id`, `variant`, `variant_version`, `reason`, `context` | The run |
| `outcome_id`, `outcome_timestamp`, `outcome_name`, `data` | The outcome |

Compare variants with a SQL client.

```sql
SELECT
  experiment_version,
  variant,
  count(DISTINCT subject_id) AS subjects,
  avg((data->>'position')::double precision) AS mean_position
FROM atlas.logs
WHERE experiment = 'rank-v2'
  AND reason IN ('assigned', 'variant-unavailable')
  AND outcome_name = 'click'
GROUP BY experiment_version, variant;
```

## Host measurements

`requests` has one row per proxied request when a host runs with `--capture http`: `subject_id`, `experiment`, `experiment_version`, `variant`, `variant_version`, `method`, `path`, `status`, `duration_ms`, `first_byte_ms`, `request_bytes`, and `response_bytes`. `duration_ms` runs to the response's last byte.

`output` has captured lines: `variant`, `variant_version`, `stream`, `line`, and `host`. It is kept for the app's output retention.

`metrics` has one row per process and minute. `kind = 'http'` rows hold `requests`, `errors`, `statuses`, `p50_ms`, `p90_ms`, `p99_ms`, and `max_ms`. `kind = 'resources'` rows hold `cpu_percent`, `memory_bytes`, and `processes`.

`lifecycle` has process events with their `data`, such as an exit's `code` and `signal`.

## Notes

`notes` has one row for each `--note`: `timestamp`, `experiment`, `experiment_version`, `action`, `note`, `actor`, and `variants`, the variant versions and commits that the experiment version pinned.

Create a revocable connection URL for a SQL client.

```shell
ssp database credential create --name analyst --app atlas
```
