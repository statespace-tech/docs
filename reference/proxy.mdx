title: Proxy
description: Every flag of ssp proxy, and how it routes requests, runs containers, and records events.

`ssp proxy` is a reverse proxy in front of an app. For each request, it finds the subject. Then it sends the request to the app's default, or to the arm of the subject's experiment.

```text
load balancer → ssp proxy :8080
  ├→ default                (deployed image)
  ├→ control of ranking     (default of the base)
  └→ recent-clicks@4be1f0c  (branch image)
```

The proxy needs a token with the `runtime` preset in `SSP_TOKEN`. A runtime token for one app, from `ssp token create --preset runtime --app atlas`, gives the proxy its app.

## Two ways to run

| Flags | The proxy | The default | The arms |
| --- | --- | --- | --- |
| `--image` or `--image-file` | Runs on a machine with Docker | A container that the proxy runs | Containers that the proxy runs |
| `--default` | Only routes, such as beside the default in its pod | Runs at the `--default` address | Pods that a [controller](/reference/controller) runs |

<CodeGroup>

```shell Docker
ssp proxy --image-file /etc/atlas/image \
  --health /health \
  --arm-env DATABASE_URL="$ARM_DATABASE_URL" \
  --redact 'sk_live_\w+'
```

```shell Routing only
ssp proxy --default http://localhost:8000
```

</CodeGroup>

## Flags

Give one of `--image`, `--image-file`, or `--default`.

<ParamField body="--app" type="string">
  The app whose experiments the proxy serves. Defaults to the app of a token for one app. Without such a token, `--app` is required. With such a token, another app is an error. Environment variable: `STATESPACE_APP`.
</ParamField>

<ParamField body="--image" type="string">
  The app's default image. The proxy runs it and every arm as Docker containers on this machine. Environment variable: `STATESPACE_IMAGE`.
</ParamField>

<ParamField body="--image-file" type="string">
  A file that holds the default image. On `SIGHUP`, the proxy reads the file again. It replaces the default when the new container is ready, and drops no requests. Environment variable: `STATESPACE_IMAGE_FILE`.
</ParamField>

<ParamField body="--default" type="string">
  The address of the default, such as `http://localhost:8000`. The proxy only routes, and a controller runs the arms. Environment variable: `STATESPACE_DEFAULT`.
</ParamField>

<ParamField body="--listen" type="string" default="0.0.0.0:8080">
  The public address. Environment variable: `STATESPACE_LISTEN`.
</ParamField>

<ParamField body="--health" type="string">
  A path that must answer 200 before an arm gets traffic. Without it, an arm is ready when its port accepts connections. Environment variable: `STATESPACE_HEALTH`.
</ParamField>

<ParamField body="--max-arms" type="integer" default={5}>
  How many arms run at the same time, controls included, 1 to 64.
</ParamField>

<ParamField body="--stale-after" type="integer" default={300}>
  The seconds that the proxy uses its last configuration while Statespace is unreachable. After that time, every subject gets the default.
</ParamField>

<ParamField body="--arm-env" type="NAME=VALUE">
  An environment variable that every arm gets and the default does not, such as a database URL without schema permissions. Repeat it for each variable.
</ParamField>

<ParamField body="--redact" type="regex">
  A regular expression. The proxy replaces its matches in recorded lines before the lines leave this machine. Repeat it for each expression.
</ParamField>

<ParamField body="--port" type="integer">
  The port that the app listens on in its container. Defaults to the image's `EXPOSE` port. With `--image` only. Environment variable: `STATESPACE_PORT`.
</ParamField>

<ParamField body="--volume" type="SOURCE:TARGET">
  A volume, as `docker run --volume` takes it. Repeat it for each volume. With `--image` only.
</ParamField>

<ParamField body="--memory" type="string">
  A memory limit for each container, such as `1g`. With `--image` only.
</ParamField>

<ParamField body="--cpus" type="number">
  A CPU limit for each container, such as `1.5`. With `--image` only.
</ParamField>

## Requests

For each request, the proxy hashes the subject of each experiment, and finds the arm whose ranges contain it. The arms of an app hold ranges that do not overlap, so a subject is in one experiment at most. Then the proxy checks eligibility. See [Random assignment](/concepts/random-assignment).

The proxy sends these headers to the app. It removes the same headers from client requests.

| Header | Value |
| --- | --- |
| `x-statespace-subject` | The subject ID, or the `ssp_sid` cookie |
| `x-statespace-arm` | `default`, `control`, or the arm that serves the request |
| `x-statespace-experiment` | The experiment, when the subject is in one |

The proxy sets the `ssp_sid` cookie on the first response to a new visitor. It accepts HTTP/1.1 and HTTP/2, streams request and response bodies, and passes WebSocket and other upgrades through. If an arm does not answer a request without a body, the proxy sends that request to the default again.

A subject gets the default when its arm starts, fails, or is over `--max-arms`. Its run records `reason = 'arm-unavailable'`. Every subject gets the default when the proxy has no configuration newer than `--stale-after`.

## Containers

With `--image`, the proxy runs each container with `docker run` on a private port of `127.0.0.1`. An init process sends stop signals to the app. Each container gets the proxy's environment, then `--arm-env` for arms and controls, then these variables.

| Variable | Value |
| --- | --- |
| `PORT` | The port that the app listens on in its container |
| `STATESPACE_APP` | The app |
| `STATESPACE_ARM` | `default`, `control`, or the arm's name |
| `STATESPACE_COMMIT` | The arm's commit, or a control's base commit. Not set for the default |
| `STATESPACE_EXPERIMENT` | The arm's experiment. Not set for the default |

Containers do not get the proxy's own settings (`SSP_*` and `STATESPACE_*`). They also do not get the variables that describe the machine or the session, such as `PATH`, `HOME`, and the variables of systemd.

Statespace names the image of each arm by digest. An arm runs an image that CI recorded with its OIDC token. A control runs a default build that a proxy or controller of the app ran. The proxy reports the digest of its default, so Statespace knows which commit is deployed. A container that stops starts again, with a delay of up to one minute.

Containers have the labels `statespace.com/app`, `statespace.com/proxy`, and `statespace.com/target`. After a crash, a new proxy with the same `--app` and `--listen` adopts the containers that still run, and removes the others. On `SIGTERM`, the proxy stops new connections and lets requests finish for up to 10 seconds. Then it removes every container that it ran.

## Events

The proxy records the arms. It never records the default.

| Event | What it has |
| --- | --- |
| Run | The first time the proxy routes a subject in an experiment version, with the reason. Again every 30 minutes at most |
| Output | Each line that an arm prints, on standard output or standard error |
| Request | Each request that an arm serves: method, path, status, times, and sizes |
| Lifecycle | `started`, `ready`, `exited`, `stopped`, and `failed` |
| Metrics | HTTP summaries for each minute and arm. On Docker, also CPU and memory |

The proxy never sends request headers or bodies. It sends events in batches. When Statespace is slow or unreachable, the proxy drops events. It does not make the app wait. The [SQL views](/reference/database-schema) show the events.
