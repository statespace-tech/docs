---
title: Controller
description: Every flag of ssp controller kubernetes, and how it runs arms on Kubernetes.
---

`ssp controller kubernetes` runs the arms and controls of an app's experiments on Kubernetes. It runs as one pod in the app's namespace. It does not change the default's Deployment, and it does not handle requests. `ssp proxy --default` runs beside the default in each pod and routes the requests.

```shell
ssp controller kubernetes --deployment atlas
```

The controller needs a token with the `runtime` preset in `SSP_TOKEN`. The proxies and the controller can use the same token. A runtime token for one app gives the controller its app. Set `STATESPACE_CONTROLLER` to the name of the controller's own Deployment. Then Kubernetes deletes its arms when you delete the controller.

## Flags

<ParamField body="--app" type="string">
  The app whose experiments the controller serves. Defaults to the app of a token for one app. Without such a token, `--app` is required. Environment variable: `STATESPACE_APP`.
</ParamField>

<ParamField body="--deployment" type="string" required>
  The Deployment that runs the app's default. Environment variable: `STATESPACE_DEPLOYMENT`.
</ParamField>

<ParamField body="--container" type="string">
  The app's container in the default's pods. Defaults to the first container that is not `statespace-proxy`. Environment variable: `STATESPACE_CONTAINER`.
</ParamField>

<ParamField body="--namespace" type="string">
  The namespace of the Deployment. Defaults to the controller's own namespace. Environment variable: `STATESPACE_NAMESPACE`.
</ParamField>

<ParamField body="--health" type="string">
  A path that must answer 200 before an arm gets traffic. Without it, an arm is ready when its port accepts connections. Environment variable: `STATESPACE_HEALTH`.
</ParamField>

<ParamField body="--max-arms" type="integer" default={5}>
  How many arms run at the same time, controls included, 1 to 64.
</ParamField>

<ParamField body="--stale-after" type="integer" default={300}>
  The seconds to keep the last configuration while Statespace is unreachable.
</ParamField>

<ParamField body="--arm-env" type="NAME=VALUE">
  An environment variable that the container of every arm gets. Repeat it for each variable.
</ParamField>

<ParamField body="--redact" type="regex">
  A regular expression. The controller replaces its matches in recorded lines before the lines leave the cluster. Repeat it for each expression.
</ParamField>

## Arms

Every few seconds, the controller compares the running experiments with the arms that it runs. For each arm and control, it keeps a Deployment and a Service. Their names come from the default, the experiment, and the arm.

| Part | What the controller does |
| --- | --- |
| Pods | Copies the default's pod spec: environment, Secrets, service account, resources, probes, and volumes. Only the image of the app container is different. The `statespace-proxy` sidecar is not copied |
| Labels | Sets only `statespace.com/arm`, `statespace.com/app`, and `app.kubernetes.io/managed-by: ssp-controller`. The default's Service does not send traffic to arms |
| Replicas | Uses the default's replicas times the arm's share of all subjects, with one replica at least |
| Images | Runs the image that Statespace names by digest: a build that CI recorded, or for a control, the default build of its base |
| Ownership | Makes the controller's Deployment the owner of each object |

When an arm stops, the controller deletes it. After the controller starts again, it deletes the arms that no running experiment uses.

## Reports

The controller reports the address of each arm, and whether it is ready. The proxies beside the default send requests only to arms that are ready. The controller also reports the digest that the default's ready pods run, so Statespace knows which commit is deployed. The `atlas.arms` view shows the arms.

The controller reads the log of each arm pod through the Kubernetes API, and records each line. Kubernetes merges the standard output and standard error of a container, so each line has the stream `stdout`. The controller keeps the position in each log in the ConfigMap `<deployment>-statespace`. Then a controller that starts again records each line one time only.

## Permissions

The controller needs these permissions in its namespace.

| Resources | Verbs |
| --- | --- |
| `deployments` | `get`, `list`, `create`, `update`, `delete` |
| `services`, `configmaps` | `get`, `list`, `create`, `update`, `delete` |
| `pods`, `pods/log` | `get`, `list` |

The [Kubernetes example](https://github.com/statespace-tech/statespace/tree/main/examples/kubernetes) has the Role, the RoleBinding, and the controller's Deployment.
