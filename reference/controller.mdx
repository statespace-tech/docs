---
title: Controller
description: Review how ssp controller kubernetes runs arms.
---

`ssp controller kubernetes` runs the arms and controls of an app's experiments on Kubernetes. It runs as one pod in the app's namespace, never touches the default's Deployment, and never handles requests.

```shell
ssp controller kubernetes --app atlas --deployment atlas
```

| Flag | Meaning |
| --- | --- |
| `--app` | The app, or `STATESPACE_APP` |
| `--deployment` | The default's Deployment, or `STATESPACE_DEPLOYMENT` |
| `--container` | The app's container in the default's pods. Defaults to the first container other than `statespace-proxy` |
| `--namespace` | The namespace. Defaults to the controller's own |
| `--max-arms` | How many arms run at once, controls included, 1 to 64. Defaults to 5 |
| `--arm-env NAME=VALUE` | An environment variable every arm's container gets. Repeatable |
| `--redact REGEX` | Replace matches in recorded lines before they leave the cluster. Repeatable |

The controller needs a token with the `controller` preset in `SSP_TOKEN`. Set `STATESPACE_CONTROLLER` to the name of its own Deployment, so its arms are deleted with it.

## Arms

Every few seconds, the controller compares the running experiments with the arms it runs. For each arm and control, it keeps a Deployment and a Service named after the default, the experiment, and the arm.

- **Pods.** A copy of the default's pod spec: its environment, Secrets, service account, resources, probes, and volumes. Only the app container's image differs, and the `statespace-proxy` sidecar is left out.
- **Labels.** Only `statespace.com/arm`, `statespace.com/app`, and `app.kubernetes.io/managed-by: ssp-controller`, so the default's Service never sends arms traffic.
- **Replicas.** The default's replicas times the arm's share of all subjects, at least one.
- **Images.** Each arm runs the image Statespace names by digest: a build CI recorded, or for a control, the default build of its base.
- **Ownership.** Each object is owned by the controller's Deployment, so deleting the controller deletes every arm.

When an arm stops, the controller deletes it. After its own restart, it deletes the arms no running experiment uses.

## Reports

The controller reports each arm's address and readiness to Statespace, and the proxies beside the default forward to arms that are ready. It also reports the digest that the default's ready pods run, so Statespace knows which commit is deployed. The `atlas.arms` view shows the arms.

The controller streams each arm pod's log through the Kubernetes API and records every line. Kubernetes merges a container's standard output and standard error, so every line is recorded as `stdout`. Each pod's position is kept in the ConfigMap `<deployment>-statespace`, so a restarted controller records each line once.

## Permissions

The controller needs these permissions in its namespace.

| Resources | Verbs |
| --- | --- |
| `deployments` | `get`, `list`, `create`, `update`, `delete` |
| `services`, `configmaps` | `get`, `list`, `create`, `update`, `delete` |
| `pods`, `pods/log` | `get`, `list` |

The [Kubernetes example](https://github.com/statespace-tech/statespace/tree/main/examples/kubernetes) has the Role, the RoleBinding, and the controller's Deployment.
