---
title: CEL variables
description: The variables and fields that each CEL expression in statespace.toml can use.
---

`statespace.toml` uses [CEL](https://cel.dev) expressions in three places. Each place has its own variables.

| Key | Gives | Variables |
| --- | --- | --- |
| `subject` | string | `request` |
| `eligibility` | bool | `request` |
| `[[event]] match` | bool | `request` and `response` |

CI checks each expression when it records a build. An error fails the CI step, with the message. A field that is not on this page is an error.

## request

| Field | Type | Example |
| --- | --- | --- |
| `request.method` | string | `request.method == "POST"` |
| `request.host` | string | `request.host == "shop.acme.com"` |
| `request.path` | string | `request.path == "/checkout"` |
| `request.query` | map of strings | `request.query.ref == "mail"` |
| `request.headers` | map of strings | `request.headers["x-user-id"]` |
| `request.cookies` | map of strings | `request.cookies.ssp_sid` |

Header names are lowercase.

## response

Only `[[event]] match` can use `response`.

| Field | Type | Example |
| --- | --- | --- |
| `response.status` | number | `response.status < 300` |
| `response.headers` | map of strings | `response.headers["x-app-event"]` |
| `response.ms` | number | `response.ms > 1000.0` |

- `response.status` is the status that the visitor got. When the arm fails, the proxy answers itself, such as with a 502.
- `response.ms` is the time to the response headers, in milliseconds.
- Header names are lowercase.

## Subject and eligibility

The proxy evaluates `subject` and `eligibility` before it sends the request. So they use `request` only.

```toml statespace.toml
[experiment.checkout]
subject = 'request.headers["x-user-id"]'
eligibility = 'request.headers["cf-ipcountry"] == "US"'
```

- `subject` and `eligibility` are keys of an `[experiment.<name>]` table.
- When `subject` gives no string, the experiment skips the request.
- When `eligibility` is false or has an error, the experiment skips the request.

## Event match

The proxy evaluates each `match` one time for each request of an arm, when the response headers arrive. It never reads a body.

```toml statespace.toml
[[event]]
name = "purchase"
match = '''
request.method == "POST"
  && request.path == "/checkout"
  && response.status < 300
'''
```

- A missing field is no match. It is not an error.
- A `match` that does not give a boolean fails in CI.
- The proxy can match headers and cookies. It never sends or keeps them.
