`statespace.toml` holds the events and experiments of the apps that run from its folder. It has no app name: the name comes from `ssp app add`. Several apps can run from one folder, such as `shop-dev` and `shop-prod`.

## Starter file

Write this file in the folder of your app's code. Change the event to a route of your app.

<StarterToml />

## Full example

This file has a shared event, two experiments, an own event, and a per-app section.

```toml statespace.toml
# Shared events: in every experiment.
[[event]]
name = "purchase"
match = '''
request.method == "POST"
  && request.path == "/checkout"
  && response.status < 300
'''

# Experiments, in priority order.
[experiment.checkout]
subject = 'request.headers["x-user-id"]'
max_traffic = 0.2

[[experiment.checkout.event]]
name = "coupon"
match = '''
request.method == "POST"
  && request.path == "/checkout/coupon"
'''

[experiment.us-landing]
eligibility = 'request.headers["cf-ipcountry"] == "US"'
max_traffic = 0.15

# Per-app sections replace and extend the shared settings.
[app.shop-dev.experiment.checkout]
max_traffic = 1.0
```

## Top-level tables

<ParamField path="[[event]]" type="table">
  A shared event. It applies to every experiment. See [Events](#events).
</ParamField>

<ParamField path="[experiment.<name>]" type="table">
  One experiment. An empty table is an experiment with the defaults. See [Experiments](#experiments).
</ParamField>

<ParamField path="[app.<name>]" type="table">
  Settings for one app. See [Per-app sections](#per-app-sections).
</ParamField>

## Experiments

Each `[experiment.<name>]` table defines one experiment. You set its arms with [`ssp experiment update`](/reference/cli/experiment#ssp-experiment-update), not in the file.

<ParamField path="subject" type="CEL → string" default="request.cookies.ssp_sid">
  The subject ID of a request. When the expression gives no string, the experiment skips the request. See [Subjects](/concepts/subjects-and-eligibility).
</ParamField>

<ParamField path="eligibility" type="CEL → bool" default="everyone">
  Who can enter the experiment. When the expression is false or has an error, the experiment skips the request.
</ParamField>

<ParamField path="max_traffic" type="number" default="0.2">
  The largest total of the shares of the arms. A fraction: more than 0, and 1 at most.
</ParamField>

<ParamField path="[[experiment.<name>.event]]" type="table">
  An own event of the experiment. It applies only to this experiment.
</ParamField>

- Each experiment exists in every app of the folder. Its arms and its state are different for each app.
- `subject` and `eligibility` run before the response exists. They can use only `request`. See [CEL](/reference/cel).
- The order of the `[experiment.*]` tables is the priority order. When two running experiments can claim the same request, the first in the file gets it. See [Subjects](/concepts/subjects-and-eligibility).

## Events

Each `[[event]]` table defines one event: a rule over one request and its response. See [Events and results](/concepts/events-and-results).

<ParamField path="name" type="string" required>
  The name of the event, such as `purchase`. Lowercase snake_case: a lowercase letter, then lowercase letters, digits, or `_`. `requests_4xx` and `requests_5xx` are built-in events, and CI refuses them as names.
</ParamField>

<ParamField path="match" type="CEL → bool" required>
  The rule. It can use `request` and `response`. See [CEL](/reference/cel).
</ParamField>

- Shared events apply to every experiment. The own events of an experiment come after the shared ones.
- The same name two times fails in CI: `event "coupon" is defined twice`.
- The results show `requests_4xx` and `requests_5xx` first, then each event in this order.
- The **headline** is the first event of the experiment, shared events first. Without events, it is `requests_5xx`. The [commit status](/reference/commit-status) shows it.

## Per-app sections

An `[app.<name>]` section holds settings for one app:

- `[[app.<name>.event]]`: events for this app. They come after the shared events.
- `[app.<name>.experiment.<exp>]`: experiment keys. They replace the shared keys of that experiment for this app.

A section that matches no app gives a warning in CI. It is not an error.

## When a change takes effect

1. You commit a change to `statespace.toml`.
2. CI records the build and checks the file. A wrong key, a wrong type, or a CEL error fails the CI step, with the message.
3. The commit runs as live.
4. The app uses the file in the build of its live commit.

A release that changes the file can stop running experiments:

| The release changes | Result |
| --- | --- |
| Only code | Nothing |
| `subject`, `eligibility`, or `max_traffic` of the experiment, or removes its table | The experiment stops |
| A shared event | Every running experiment of the app stops |
| An own event of the experiment | The experiment stops |

The reason of the stop is, for example, "its definition changed in live d00d123". The versions of `ssp experiment show`, the commit statuses, and the audit log show it. See [Experiments](/concepts/experiments).

## Limits

| Value | Limit |
| --- | --- |
| Experiment name | 1 to 40 characters: lowercase letters, digits, and `-` |
| Event name | 1 to 64 characters: a lowercase letter, then lowercase letters, digits, and `_` |
| `max_traffic` | More than 0, at most 1. Default `0.2` |
| Shares of the arms of one experiment | `max_traffic` at most |
| Shares of all running experiments of an app | 1 at most |
| Arms to start an experiment | 2 or more |

### Other limits

| Item | Limit |
| --- | --- |
| App name | 1 to 63 characters: lowercase letters, digits, and `-`. Unique in the workspace |
| `--note` | 1 to 200 characters, one line |
| Commit prefix | 7 characters or more |
| Storage of an account | 1 GiB on the free plan, 10 GiB on other plans. Statespace warns at 80% |
| One subject of a running version | 256 bytes of storage |
| Arms of a starting experiment become ready | 5 minutes at most. Then the start fails |
| Subject cookie `ssp_sid` | 90 days, renewed on each response |
| Override cookie `ssp` | 1 hour, renewed on each request |
| 95% interval of an arm | From 30 subjects |
| Split check | From 100 subjects in all arms |

When an account is full, Statespace takes no new subjects. When a version stops, Statespace keeps its results and deletes its subjects. `ssp app remove` deletes all data of the app. See [Data and security](/concepts/data-and-security).
