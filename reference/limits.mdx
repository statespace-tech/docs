---
title: Limits and retention
description: How long Statespace keeps data, and the limits of names, notes, shares, rows, and storage.
---

This page lists the limits and times of Statespace.

## Retention

| Data | Kept |
| --- | --- |
| `requests`, `stdout`, `stderr`, `events`, `runs`, and `lifecycle` rows | 90 days |
| Totals of each version | Until you remove the app. So Statespace can always compute the evidence again |
| History and evidence of a `gone` experiment | Kept. `ssp experiment list --all` shows it |

Statespace never records live.

## Storage

| Limit | Value |
| --- | --- |
| One row | 64 KiB |
| One batch of rows from the proxy | 100 rows |
| One account | 10 GiB. Statespace warns at 80% |

Each account has its own PostgreSQL database. A subject can be erased with `POST /v1/subjects/erase`. See [API](/reference/api#other).

## Names and values

| Value | Limit |
| --- | --- |
| App name | 1 to 63 characters: lowercase letters, digits, and `-`. Unique in the workspace |
| Experiment name | 1 to 40 characters: lowercase letters, digits, and `-` |
| Commit prefix | 7 characters or more |
| `--note` | 1 to 200 characters, one line |
| Share of an arm | A fraction, such as `0.05`. `0` removes the arm |
| `max_traffic` | More than 0, at most 1. Default `0.2` |
| Shares of all running experiments of an app | 1 at most |
| Arms to start an experiment | 2 or more |
| Commit status description | 140 characters |

## Times

| Item | Time |
| --- | --- |
| Arms of a starting experiment become ready | 5 minutes at most. Then the start fails |
| Arms of a stopped experiment leave traffic | Seconds |
| Visitor cookie `ssp_sid` | 90 days, renewed on each response |
| Override cookie `ssp_arm` | 1 hour, renewed on each request |
| Commit status update | At each change of state, and once an hour while the experiment runs |
| Roles from GitHub | Kept 10 minutes |
| Proxy lease | 30 seconds. The holder renews it every 10 seconds |
| Runtime configuration older than this sends every request to live | 5 minutes |

## Split check

The split check starts at 100 subjects in the arms of the experiment. It reports `split off` when p is less than 0.001.
