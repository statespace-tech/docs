---
title: Commit status
description: Each state and description of the statespace/<app>/<experiment> commit status on an arm's commit.
---

Statespace posts a commit status on the commit of each arm, the reference too. There is one status for each app and experiment. Its context is `statespace/<app>/<experiment>`, such as `statespace/shop-prod/checkout`.

- Statespace posts at each change of state: start, stop, removal, and an arm that is not ready.
- While the experiment runs, Statespace posts once an hour, only when the description changed.
- Statespace posts only for arms of running experiments, and one last time at stop or removal. Old lines stay as they were last written.
- GitHub accepts 1,000 statuses for each commit and context at most. Statespace stops the hourly posts at 950, to keep room for changes of state.
- The description has 140 characters at most.
- **Details** opens the experiment in the dashboard: `https://statespace.com/dashboard/apps/<app>/experiments/<experiment>?workspace=<login>`.
- The state says where the arm is. It never says that the arm is good or bad. It is never `failure`.

## States

| The arm | State | Description, for example |
| --- | --- | --- |
| Runs | `pending` | `v1 running · 0.05 · 2,040 subjects · split OK · purchase rate % 3.4 vs 2.8 (c0ffee1)` |
| Runs, the reference | `pending` | `v1 reference · 0.05 · 2,031 subjects · split OK · purchase rate % 2.8 vs 3.4 (a1b2c3d)` |
| Runs, not ready | `pending` | `v1 not ready: the container exits (exit 1) · subjects go to live` |
| Is stopped | `success` | `v1 stopped · 2,040 subjects · purchase rate % 3.4 vs 2.8 (c0ffee1)` |
| Is stopped by a release | `success` | `v1 stopped: definition changed in live d00d123 · 2,040 subjects · …` |
| Is removed | `success` | `removed · last v2 · 3,310 subjects · purchase rate % 3.3 vs 2.9 (c0ffee1)` |

## The running description

The description of an arm in a running experiment has these parts, in this order:

1. the version, such as `v1`;
2. `running`, or `reference` for the reference arm;
3. the share of the arm;
4. the subjects of the arm;
5. the split check: `split OK` or `split off (p=0.0004)`;
6. the headline metric, this arm vs the other arm, with the commit of the other arm.

With 3 or more arms, the line of the reference says `reference of 2 arms`.

## GitHub App permission

The Statespace GitHub App needs only the permission to write commit statuses for this. Your CI does nothing for it.
