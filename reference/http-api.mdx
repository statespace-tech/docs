---
title: HTTP API
description: Review public authentication, token, experiment, and event routes.
---

The production API base URL is `https://api.statespace.com`. Prefer the SDK for runtime assignment and event delivery.

## Authentication

Send an account session or database token as a bearer credential.

```http
Authorization: Bearer ssp_rw_7j...
```

Account sessions manage tokens and experiment state. Read-write tokens initialize experiments, assign subjects, and record outcomes. Read-only tokens query DuckDB.

## Account endpoint

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/v1/account` | Show plan limits, usage, and the database URL. |

## Token endpoints

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/v1/tokens` | List token metadata. |
| `POST` | `/v1/tokens` | Create a read-only or read-write token. |
| `DELETE` | `/v1/tokens/{id}` | Revoke a token. |

Token creation returns the complete secret once.

## Layer endpoints

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/v1/layers` | List exclusion layers. |
| `POST` | `/v1/layers` | Create a layer. |
| `GET` | `/v1/layers/{name}` | Show a layer. |
| `PUT` | `/v1/layers/{name}` | Replace a layer definition. |
| `DELETE` | `/v1/layers/{name}` | Delete an unused layer. |

## Experiment endpoints

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/v1/experiments` | List experiments. |
| `POST` | `/v1/experiments` | Register a runtime experiment definition. |
| `GET` | `/v1/experiments/{name}` | Show an experiment. |
| `PUT` | `/v1/experiments/{name}` | Replace a draft or stopped definition. |
| `DELETE` | `/v1/experiments/{name}` | Delete an experiment and its data. |
| `POST` | `/v1/experiments/{name}/state` | Start or stop an experiment. |
| `POST` | `/v1/experiments/{name}/traffic` | Increase running traffic. |

The SDK reads the runtime manifest with a read-write token.

```http
GET /v1/runtime/experiments/rank-v2
```

## Assignment and outcome endpoints

| Method | Path | Purpose |
| --- | --- | --- |
| `POST` | `/v1/assign` | Resolve one stable subject assignment. |
| `POST` | `/v1/runs` | Record one applied configuration. |
| `POST` | `/v1/run-outcomes` | Record one JSON outcome for a run. |
| `POST` | `/v1/outcomes` | Record a structured outcome for an assignment. |

Each write request includes its stable event identifier in the JSON body. Repeating an accepted identifier does not create a second record.

## Error responses

Error responses contain one concise message.

```json
{
  "error": "experiment already exists"
}
```

| Status | Meaning |
| --- | --- |
| `400` | The request is invalid. |
| `401` | Authentication is missing or invalid. |
| `404` | The resource does not exist. |
| `409` | The request conflicts with current state. |
| `429` | The account exceeded its write limit. |
| `500` | The service could not complete a valid request. |

<Note>
  Retry `429` and transient `500` responses with bounded exponential backoff. Do not retry validation or authentication errors without changing the request.
</Note>
