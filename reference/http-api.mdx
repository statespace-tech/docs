title: HTTP API
description: Review account, experiment, runtime, and event routes.

The CLI and local SDKs can use a saved account session. Deployed SDKs use
`SSP_API_KEY`. Bearer API keys require the route's scope. Browser sessions use
cookies and the configured frontend origin for mutations.

## Account routes

Use account routes to manage credentials, sessions, audit records, and storage.

```text
GET    /v1/account
GET    /v1/keys
POST   /v1/keys
DELETE /v1/keys/{id}
GET    /v1/tokens
DELETE /v1/tokens/{id}
POST   /v1/credentials/revoke-all
GET    /v1/database/credentials
POST   /v1/database/credentials
DELETE /v1/database/credentials/{id}
GET    /v1/audit
GET    /v1/storage
```

`/v1/audit` includes `source` and `occurred_at`. Use IDs with the `before` cursor
for pagination. Compare `occurred_at` for chronology; IDs combine independent
ledger counters.

There is no SQL query endpoint. Account database credentials provide read-only
access through your PostgreSQL client.

## Authentication routes

Sign in or sign up with a configured GitHub or Google provider.

```text
GET    /v1/auth/providers
GET    /v1/auth/web/{provider}/start
GET    /v1/auth/github/callback
GET    /v1/auth/google/callback
GET    /v1/auth/session
DELETE /v1/auth/session
POST   /v1/auth/device
POST   /v1/auth/device/approve
POST   /v1/auth/device/token
```

Provider clients must be registered with the exact callback URLs. Device
approval requires a signed-in user. Callback state and device redemption are
single use.

## Group and experiment routes

Upload components, define groups, and manage experiments with an `experiments:write` key or a session.

```text
GET    /v1/artifacts
GET    /v1/artifacts/{sha256}
PUT    /v1/artifacts/{sha256}
GET    /v1/groups
POST   /v1/groups
GET    /v1/groups/{name}
PATCH  /v1/groups/{name}
DELETE /v1/groups/{name}
GET    /v1/experiments
POST   /v1/experiments
GET    /v1/experiments/{name}
PATCH  /v1/experiments/{name}
DELETE /v1/experiments/{name}
POST   /v1/experiments/{name}/start
POST   /v1/experiments/{name}/stop
GET    /v1/experiments/{name}/results?outcome={name}&metric={field}&version={n}
DELETE /v1/experiments/{name}/subjects
```

`PUT /v1/artifacts/{sha256}` takes the component bytes. The service validates the component and checks that its SHA-256 matches the path. A group parameter is a value or a reference to an uploaded component.

```json
{
  "name": "atlas-search",
  "parameters": {
    "ranker": { "kind": "function", "sha256": "3fa9…", "source": { "path": "rerank.py", "entry": "score", "sha256": "9b1c…" } },
    "top_k": { "kind": "value", "value": 10 }
  }
}
```

`PATCH /v1/groups/{name}` merges parameters, and `null` removes one. An experiment's groups map names to weights.

```json
{
  "name": "rank-v2",
  "assignment": "user_id",
  "eligibility": "context.country == \"US\"",
  "groups": { "atlas-search": 0.2 }
}
```

`PATCH /v1/experiments/{name}` changes the draft. `POST /start` publishes it and accepts an optional `{"version": 1}` to restart a published version instead.

## SDK routes

Read running configurations and components, then submit runs and outcomes. These routes need a `runtime:read` and `events:write` key.

```text
GET  /v1/runtime/experiments/{name}
GET  /v1/runtime/artifacts/{sha256}
POST /v1/events
```

The batch endpoint accepts up to 100 runs and outcomes in one request. An outcome names its experiment and subject, not a run.

```json
{
  "runs": [{ "id": "run_1", "experiment": "rank-v2", "version": 1, "subject_id": "u_42",
             "group": "atlas-search", "reason": "assigned", "context": { "country": "US" } }],
  "outcomes": [{ "id": "out_1", "experiment": "rank-v2", "subject_id": "u_42",
                 "name": "click", "data": { "position": 1 } }]
}
```

`202 Accepted` means the account outbox has committed the events. The worker
retries SQS delivery and writes the final rows. Duplicate queue delivery is
idempotent. Each serialized event is limited to 64 KiB. Raw events expire after
90 days. The default event quota is 10 GiB per account, including pending events.

## Errors

Errors use one JSON object and an HTTP error status.

```json
{
  "error": "bad request: event exceeds 64 KiB"
}
```
