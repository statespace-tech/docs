---
title: Quickstart
description: Test a new ranking function on live traffic and read the result.
---

This example tests a new search ranker against the application's current one. The group is named `atlas-search`. The experiment is `rank-v2`.

<Steps>
  <Step title="Install the CLI and sign in">
    Install `ssp`, then sign in with GitHub or Google and approve the displayed code.

    ```shell
    curl -fsSL https://statespace.com/install | bash
    ssp login
    ```
  </Step>

  <Step title="Write the candidate">
    Save the candidate function as `rerank.py`. It takes and returns JSON values.

    ```python
    def score(items: list[int]) -> list[int]:
        return sorted(items, reverse=True)
    ```

    Run it locally in the same sandbox the SDKs use.

    ```shell
    ssp run rerank.py:score --input '[3, 1, 2]'
    ```
  </Step>

  <Step title="Create a group">
    Put the function in a group, with any value you want to test together with it.

    ```shell
    ssp group create atlas-search ranker=rerank.py:score top_k=10
    ```

    The CLI builds the function into a WebAssembly component and uploads it.
  </Step>

  <Step title="Create and start the experiment">
    Send 20% of eligible US users to the group, and start the experiment.

    ```shell
    ssp experiment create rank-v2 --group atlas-search=0.2 --eligibility 'context.country == "US"'
    ssp experiment start rank-v2
    ```

    The other 80% are control and receive the application's current code.
  </Step>

  <Step title="Create an application key">
    Create a runtime key and store its secret as `SSP_API_KEY` where the application runs.

    ```shell
    ssp key create --name production --preset runtime
    ```

    Locally, the SDKs use your `ssp login` session instead.
  </Step>

  <Step title="Read the group in the application">
    Install the Python SDK.

    ```shell
    pip install statespace-sdk
    ```

    Assign each subject, read the group's parameters with your current code as the default, and log outcomes.

    ```python
    import statespace

    experiment = statespace.experiment("rank-v2")
    group = experiment.assign("u_42", context={"country": "US"})
    rank = group.function("ranker", current_rerank)
    results = rank(items)[: group.value("top_k", 20)]
    experiment.log("u_42", "click", {"position": 1})
    ```

    The function runs locally. If it fails, the SDK uses your function and records the failure.
  </Step>

  <Step title="Read the results">
    Compare the share of subjects who clicked in each group.

    ```shell
    ssp experiment results rank-v2 --outcome click
    ```

    Create a read-only credential to analyze every run and outcome with SQL.

    ```shell
    ssp database credential create --name analyst
    psql "$DATABASE_URL" -c "SELECT group_name, outcome_name, data FROM statespace.logs WHERE experiment_name = 'rank-v2'"
    ```
  </Step>
</Steps>
