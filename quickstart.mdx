---
title: Quickstart
description: Test a new search ranking on live traffic and read the result.
---

This example tests a branch of the search app `atlas` that ranks results differently. The variant is `atlas-search`. The experiment is `rank-v2`.

<Steps>
  <Step title="Install the CLI and sign in">
    Install `ssp`, then sign in with GitHub or Google and approve the displayed code.

    ```shell
    curl -fsSL https://statespace.com/install | bash
    ssp login
    ```
  </Step>

  <Step title="Create the app and a signing key">
    Create the app, then create a key pair for signing variants.

    ```shell
    ssp app create atlas
    ssp variant keygen
    ```

    Store the private key as `SSP_SIGNING_KEY` in CI. Hosts trust the public key.
  </Step>

  <Step title="Report an outcome">
    Print one JSON line wherever something happens that you want to measure. The subject is the `x-statespace-subject` request header.

    ```python
    subject = request.headers["x-statespace-subject"]
    print(json.dumps({"statespace": "click", "subject": subject, "position": 1}))
    ```

    Deploy this change to production as usual. It is the same in control and every variant.
  </Step>

  <Step title="Publish the variant">
    Build the branch the way you build production, then package, sign, and upload it.

    ```shell
    git checkout new-ranking && uv sync --frozen
    ssp variant create atlas-search . --app atlas
    ```
  </Step>

  <Step title="Create and start the experiment">
    Give the variant half of the subjects, and start the experiment.

    ```shell
    ssp experiment create rank-v2 --app atlas --variant atlas-search=0.5 \
      --subject 'request.headers["x-user-id"]' --note 'Sorted results should get more clicks.'
    ssp experiment start rank-v2
    ```

    The other half are control and get the code you deployed.
  </Step>

  <Step title="Run the host">
    Create a runtime key and store it as `SSP_API_KEY` where the app runs.

    ```shell
    ssp key create --name production --preset runtime
    ```

    Replace the app's start command with `ssp host`. It runs your app, downloads and verifies the variant, and routes each user.

    ```shell
    ssp host --app atlas --command "gunicorn -b 127.0.0.1:{port} atlas:app" \
      --trust-key "$SSP_PUBLIC_KEY"
    ```
  </Step>

  <Step title="Read the results">
    Compare the share of subjects who clicked in each variant.

    ```shell
    ssp experiment results rank-v2 --outcome click
    ```

    Create a read-only credential to analyze every run and outcome with SQL.

    ```shell
    ssp database credential create --name analyst --app atlas
    psql "$DATABASE_URL" -c "SELECT variant, outcome_name, data FROM atlas.logs WHERE experiment = 'rank-v2'"
    ```
  </Step>
</Steps>
