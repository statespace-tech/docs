---
title: Quickstart
description: Complete one experiment from YAML to SQL.
---

This quickstart tests reciprocal rank fusion. The SDK creates the experiment at runtime and records one JSON outcome for each subject.

<Steps>
  <Step title="Install and sign in">
    Install the current `ssp` binary on macOS or Linux.

    ```bash
    curl -fsSL https://statespace.com/install | bash
    ssp login
    ```
  </Step>

  <Step title="Create a token">
    Create a read-write token for the runtime application.

    ```bash
    ssp token create -n quickstart --access read-write
    ```

    <Tip>
      The command shows the token secret once. Store it in a secret manager.
    </Tip>
  </Step>

  <Step title="Define the experiment">
    Save the complete definition as `experiment.yaml`.

    ```yaml
    name: rank-v2
    description: Test reciprocal rank fusion.
    assignment: user_id
    groups:
      - name: treatment
        weight: 0.2
        config:
          reranker: rrf
    ```

    <Note>
      Statespace adds an empty control group with the remaining weight of `0.8`.
    </Note>
  </Step>

  <Step title="Run the experiment">
    Install the SDK and configure the token.

    ```bash
    uv add statespace-sdk
    export STATESPACE_TOKEN=ssp_rw_7j...
    ```

    Load the definition. The first `init` call creates and starts the experiment.

    ```python
    import statespace

    experiment = statespace.load("experiment.yaml")

    with statespace.init(**experiment) as run:
        for user_id in ["u_42", "u_73", "u_91"]:
            config = run.get_config(user_id)
            result = search("query goes here", reranker=config.get("reranker", None))
            run.log({"relevance": result.relevance})
    ```

    Later calls accept the same definition. A conflicting definition with the same name returns an error.
  </Step>

  <Step title="Analyze the outcomes">
    Run `ssp account` to get the database URL. Attach it through the DuckDB Quack protocol.

    ```sql
    ATTACH 'quack:atlas-search.db.statespace.app:443' AS statespace (
      TOKEN 'ssp_ro_7j...'
    );

    SELECT
      group_name,
      count(*) AS outcomes,
      avg(data.relevance::DOUBLE) AS mean_relevance
    FROM statespace.logs
    WHERE experiment_name = 'rank-v2'
    GROUP BY group_name;
    ```

    <Info>
      Use DuckDB 2.0 or later. Review the workflow pages before you make a production decision.
    </Info>
  </Step>
</Steps>

Continue with [Define the experiment](/workflow/define-the-experiment) to review each design decision.
