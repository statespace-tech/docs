---
title: Quickstart
description: Test a new search ranking on live traffic and read the result.
---

This example tests a branch of the search app `atlas` that ranks results differently. The variant is `atlas-search`. The experiment is `rank-v2`.

<Steps>
  <Step title="Install the CLI and sign in">
    Install `ssp`, then sign in with GitHub or Google and approve the displayed code.

    ```shell
    curl -fsSL https://statespace.com/install.sh | bash
    ssp login
    ```
  </Step>

  <Step title="Create the app and a signing key">
    Create the app, then create a key pair for signing variants.

    ```shell
    ssp app create atlas
    ssp keygen
    ```

    Store the private key as `SSP_SIGNING_KEY` in CI. Proxies trust the public key.
  </Step>

  <Step title="Print what you measure">
    Statespace records each line that an arm prints, with its arm. Thus, your current logs are also data. To compare subjects, print a JSON line with a `subject` field. The proxy sets the `x-statespace-subject` header to the subject from your rule, or to the browser ID.

    ```python
    subject = request.headers["x-statespace-subject"]
    print(json.dumps({"event": "click", "subject": subject, "position": 1}))
    ```

    Deploy this change to production as usual, so the default and every variant print the same lines.
  </Step>

  <Step title="Publish the variant">
    Build the branch's image the way you build production and push it. Then sign and publish it by digest.

    ```shell
    docker build -t ghcr.io/acme/atlas:new-ranking . && docker push ghcr.io/acme/atlas:new-ranking
    ssp variant create atlas-search --app atlas --image ghcr.io/acme/atlas:new-ranking
    ```
  </Step>

  <Step title="Create and start the experiment">
    Give the variant 10% of the subjects. The control arm gets another 10%.

    ```shell
    ssp experiment create rank-v2 --app atlas --split atlas-search=0.1 \
      --subject 'request.headers["x-user-id"]' --note 'Sorted results should get more clicks.'
    ssp experiment start rank-v2
    ```

    Every other subject gets the default, the version you deployed.
  </Step>

  <Step title="Run the proxy">
    Create a runtime token and store it as `SSP_TOKEN` where the app runs.

    ```shell
    ssp token create --name production --preset runtime
    ```

    Run the app behind `ssp proxy`. On a machine with Docker, it runs your deployed image and both arms as containers, and routes each user.

    ```shell
    ssp proxy --app atlas --runtime docker --image ghcr.io/acme/atlas:main \
      --health /health --trust-key "$SSP_PUBLIC_KEY"
    ```

    On Kubernetes, run it beside the app in each pod instead. See [Deployment](/getting-started/deployment).
  </Step>

  <Step title="Read the results">
    Create a token that reads the app in SQL. The output shows its database URL.

    ```shell
    ssp token create --name analyst --preset analyst --app atlas
    ```

    Compare the share of subjects who clicked in each arm.

    ```sql
    SELECT variant,
           count(DISTINCT subject_id) AS subjects,
           count(DISTINCT subject_id) FILTER (WHERE data->>'event' = 'click') AS clicked
    FROM atlas.logs
    WHERE experiment = 'rank-v2' AND reason IN ('assigned', 'variant-unavailable')
    GROUP BY variant;
    ```
  </Step>
</Steps>
