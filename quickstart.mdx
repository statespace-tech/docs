In this tutorial, you test a change to the app `shop-dev` on live traffic. The app runs on one machine with Docker. At the end, 5% of the visitors get your commit, and 5% get the control. The commit status `statespace/shop-dev` shows the evidence.

## Prerequisites

- A GitHub repo with a `Dockerfile`, such as `acme/shop`. The app listens on the port that the `Dockerfile` names with `EXPOSE`.
- A Linux machine with Docker. The proxy runs the app on this machine.
- The admin role on the repo. You need it to add the app and its token.

## Run your first arm

<Steps>
  <Step title="Install the GitHub App">
    On [statespace.com](https://statespace.com), select **Connect GitHub**. Install the Statespace GitHub App on the account that owns the repo. The App can read code, metadata, and members, and write commit statuses. It cannot write code.
  </Step>

  <Step title="Install the CLI">
    Install the CLI, and sign in with the same GitHub account.

    ```shell
    curl -fsSL https://statespace.com/install.sh | bash
    ssp login
    ```
  </Step>

  <Step title="Write statespace.toml">
    In the root folder of the repo, write a starter file.

    ```shell
    ssp init
    ```

    Add one event and one metric to the file. The event counts the visitors who send a checkout. The metric is the share of visitors with a checkout.

    ```toml statespace.toml
    [[event]]
    name = "checkout"
    match = '''
    request.method == "POST"
      && request.path == "/api/checkout"
      && request.status < 300
    '''

    [[metric]]
    label = "checkout rate %"
    value = '100.0 * events["checkout"].subjects / subjects'
    ```

    See [statespace.toml](/reference/statespace-toml) for every key.
  </Step>

  <Step title="Build every push">
    `ssp init` printed the action step. Add the workflow below to the repo. It builds each push to each branch, pushes the image to GitHub Packages, and records the build.

    <BuildWorkflow />

    Commit both files, and push them to `main`.

    ```shell
    git add statespace.toml .github/workflows/build.yml
    git commit -m "Record builds with Statespace"
    git push
    ```

    When the workflow is done, the build of this commit is recorded.
  </Step>

  <Step title="Add the app">
    In the repo folder, add the app. The CLI reads the repo from the `origin` remote, and the folder from the nearest `statespace.toml`. It prints what it found.

    ```shell
    ssp app add shop-dev --note "shop on the dev machine"
    ```
  </Step>

  <Step title="Add a runtime token">
    Add a token for the proxy. The CLI shows the secret only one time.

    ```shell
    ssp token add --app shop-dev --note "Docker proxy"
    ```

    On the machine, put the secret in `/etc/shop/env`.

    ```shell /etc/shop/env
    STATESPACE_TOKEN=<secret>
    ```
  </Step>

  <Step title="Run the proxy">
    On the machine, write the live image to a file. Use the digest of the build of `main`.

    ```shell
    echo "ghcr.io/acme/shop@sha256:<digest>" \
      | sudo tee /etc/shop/image
    ```

    Start the proxy. It runs live from the file, and it listens on port 8080. Point your traffic at port 8080.

    ```shell
    set -a; . /etc/shop/env; set +a
    ssp proxy docker --app shop-dev \
      --image-file /etc/shop/image
    ```

    To run the proxy as a service, see [Docker](/guides/docker).
  </Step>

  <Step title="Push a change">
    Make a change on a new branch, and push it. CI builds the commit and records it.

    ```shell
    git switch -c green-button
    git commit -am "Make the checkout button green"
    git push -u origin green-button
    ```
  </Step>

  <Step title="Add the arm">
    When the workflow is done, add the commit as an arm. The CLI prints the build that it chose.

    ```shell
    ssp arm add "$(git rev-parse HEAD)" --app shop-dev \
      --share 0.05 --note "green checkout button"
    ```

    The proxy starts the control and the arm. Then 5% of the visitors get the arm, and 5% get the control.
  </Step>

  <Step title="Read the evidence">
    Show the arm.

    ```shell
    ssp arm show "$(git rev-parse HEAD)" --app shop-dev
    ```

    The commit on GitHub has the status `statespace/shop-dev`. When the arm runs, the status says, for example:

    ```text
    5% · 1,204 subjects · split OK · checkout rate % 3.4 vs 2.8
    · errors 0.3% vs 0.2%
    ```

    Statespace updates the status about every 10 minutes. Select **Details** to see the arm in the dashboard.
  </Step>

  <Step title="Remove the arm">
    When you have the evidence that you need, remove the arm. Statespace keeps its evidence, and the status says "Ended".

    ```shell
    ssp arm remove "$(git rev-parse HEAD)" --app shop-dev
    ```

    To ship the change, merge the branch and deploy it as usual.
  </Step>
</Steps>
