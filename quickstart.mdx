---
title: Quickstart
description: Test a new search ranking on live traffic from a pull request, and read the result.
---

In this tutorial, you test a change to the search app `atlas` on live traffic. You push the branch `exp/recent-clicks`, which ranks results by recent clicks. At the end, 10% of the subjects get the branch and 10% get its control. Then you compare the two in SQL.

## Prerequisites

- A GitHub repository with a `Dockerfile`, such as `acme/atlas`.
- A GitHub Actions workflow that builds and deploys the app from `main`.
- A server with Docker that runs the app.

## Run your first experiment

<Steps>
  <Step title="Connect GitHub">
    On [statespace.com](https://statespace.com), select **Connect GitHub**. Pick your organization and the repositories that run experiments. One screen installs the Statespace GitHub App and signs you in.

    Install the CLI, and sign in with the same GitHub account.

    ```shell
    curl -fsSL https://statespace.com/install.sh | bash
    ssp login
    ```
  </Step>

  <Step title="Merge the setup pull request">
    The App opens a pull request named "Set up Statespace". It adds `statespace.toml` and `.github/workflows/statespace.yml`. The workflow builds each push to an `exp/` branch from your `Dockerfile`, and records the image.

    In the workflow that builds production, add this step after the build. Statespace then knows the commit of each production image.

    ```yaml .github/workflows/production.yml
    - uses: statespace-tech/action@v1
      with:
        image: >-
          ghcr.io/acme/atlas@${{ steps.build.outputs.digest }}
    ```

    Merge the pull request. In branch protection for `main`, require one approval.

    <Tip>
      If the App did not open the pull request, open it from the checklist on the **Apps** page.
    </Tip>
  </Step>

  <Step title="Print what you measure">
    Statespace records each line that an arm prints. To compare subjects, print a JSON line with a `subject` field. The proxy puts the subject in the `x-statespace-subject` header.

    ```python app.py
    subject = request.headers["x-statespace-subject"]
    print(json.dumps({
        "event": "click",
        "subject": subject,
        "position": 1,
    }))
    ```

    Deploy this change to production as usual. Then the default and every arm print the same lines.
  </Step>

  <Step title="Run the proxy">
    Create a runtime token, and store it as `SSP_TOKEN` where the app runs.

    ```shell
    ssp token create --name production --preset runtime
    ```

    Run the app behind `ssp proxy`. It runs your deployed image and each arm as containers, and routes each subject.

    ```shell
    ssp proxy --app atlas --health /health \
      --image ghcr.io/acme/atlas:main
    ```

    On Kubernetes, run the proxy beside the app in each pod instead. See [Deployment](/getting-started/deployment).
  </Step>

  <Step title="Open a pull request">
    Start the branch, and change the ranking. Set the arm's share in `statespace.toml`.

    ```toml statespace.toml
    app = "atlas"
    share = 0.1
    subject = 'request.headers["x-user-id"]'
    ```

    Push the branch, and open a pull request.

    ```shell
    git switch -c exp/recent-clicks
    git commit -am "Rank results by recent clicks"
    git push -u origin exp/recent-clicks
    gh pr create --fill
    ```

    CI records the commit. When a reviewer approves the pull request and GitHub says that it can merge, the arm runs.
  </Step>

  <Step title="Check that the arm runs">
    Show the arm of the branch that you are on.

    ```shell
    ssp status
    ```

    Make sure that the status is `running`, with a share of 10%. If the status is `waiting`, it tells you why. The `statespace/arm` check on the pull request shows the same status.
  </Step>

  <Step title="Read the results">
    Create a token that reads the app in SQL. The output shows its database URL.

    ```shell
    ssp token create --name analyst --preset analyst \
      --app atlas
    ```

    Compare the share of subjects who clicked in each arm.

    ```sql
    SELECT arm, commit,
           count(DISTINCT subject_id) AS subjects,
           count(DISTINCT subject_id)
             FILTER (WHERE data->>'event' = 'click') AS clicked
    FROM atlas.logs
    WHERE experiment = 'recent-clicks'
      AND reason IN ('assigned', 'arm-unavailable')
    GROUP BY arm, commit;
    ```

    To ship the arm, merge the pull request. To stop it, make the pull request a draft, or run `ssp stop` with its URL.

    ```shell
    ssp stop https://github.com/acme/atlas/pull/418
    ```
  </Step>
</Steps>
