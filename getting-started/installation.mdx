Set up Statespace for your repositories, your terminal, and your servers.

## GitHub

<Steps>
  <Step title="Install the GitHub App">
    On [statespace.com](https://statespace.com), select **Connect GitHub**, and install the Statespace GitHub App on the repositories that run experiments. The same screen signs you in.

    Your workspace takes the name of the GitHub organization or user. If that name is not available, choose a workspace name in the dashboard.
  </Step>

  <Step title="Merge the setup pull request">
    For each repository that you selected, the App opens a "Set up Statespace" pull request. It adds `statespace.toml` and `.github/workflows/statespace.yml`. See [Deployment](/getting-started/deployment) for the step that you add to your production workflow.

    <Note>
      If you gave the App access to all repositories, it opens no pull requests by itself. Open them from the checklist on the **Apps** page, for the repositories that you choose.
    </Note>
  </Step>
</Steps>

The App asks for these repository permissions. It writes only `statespace.toml` and the Statespace workflow.

| Permission | Access | Why |
| --- | --- | --- |
| Checks | Read and write | Post the `statespace/apply` and `statespace/arm` checks |
| Contents | Read and write | Find merge bases, open the setup pull request, and commit settings that you change in the dashboard |
| Pull requests | Read and write | Read merge state, and make pull requests drafts when you stop arms |
| Workflows | Read and write | Add `.github/workflows/statespace.yml` in the setup pull request |
| Metadata | Read | Required by GitHub |

The App receives the events check suite, pull request, pull request review, and push.

## CLI

Install the CLI on macOS or Linux, and sign in with the same GitHub account.

```shell
curl -fsSL https://statespace.com/install.sh | bash
ssp login
```

Check the version, and the credential that the CLI uses.

```shell
ssp --version
ssp whoami
```

The same binary runs `ssp proxy` on machines with Docker. On Kubernetes, the proxy and the controller run from the `ghcr.io/statespace-tech/statespace` image.

To use a local API, or a hosted domain other than the default, set `STATESPACE_URL`.

```shell
export STATESPACE_URL=http://127.0.0.1:8080
```

## Tokens

CI needs no token: `ssp apply` proves itself with the job's GitHub OIDC token. Your servers and SQL clients need their own tokens.

| Where | Token | Purpose |
| --- | --- | --- |
| Your terminal | `ssp login` | Show what runs, stop and resume arms, and manage tokens |
| CI | None | Record images with `ssp apply` |
| Your servers | `--preset runtime` | Run `ssp proxy` |
| Kubernetes | `--preset controller` | Run `ssp controller kubernetes` |
| SQL clients | `--preset analyst` | Read runs, lines, and requests |

Create a runtime token for `ssp proxy`. Store the token in the output as `SSP_TOKEN` in a secret manager.

```shell
ssp token create --name production --preset runtime
```

<Warning>
  Statespace shows a token only once. Keep the output out of recorded logs.
</Warning>
