## CLI

Install the CLI on macOS or Linux.

```shell
curl -fsSL https://statespace.com/install.sh | bash
```

Make sure that the CLI is installed.

```shell
ssp --version
```

The same binary runs `ssp proxy` on machines with Docker. On Kubernetes, the proxy and the controller run from the `ghcr.io/statespace-tech/statespace` image.

## GitHub

On [statespace.com](https://statespace.com), select **Connect GitHub**, and install the Statespace GitHub App on the repositories that run experiments. The same screen signs you in. Your workspace takes the name of the GitHub organization or user. If that name is not available, choose a workspace name in the dashboard.

Sign the terminal in with the same GitHub account.

```shell
ssp login
```

For each repository that you selected, the App opens a "Set up Statespace" pull request. It adds `statespace.toml` and `.github/workflows/statespace.yml`. If you gave the App access to all repositories, open the pull request from the checklist on the **Apps** page, for the repositories that you choose. See [Deployment](/getting-started/deployment).

The App asks for these repository permissions:

| Permission | Access | Why |
| --- | --- | --- |
| Checks | Read and write | Post the `statespace/apply` and `statespace/arm` checks |
| Contents | Read and write | Find merge bases, open the setup pull request, and commit settings that you change in the dashboard |
| Pull requests | Read and write | Read merge state, and make pull requests drafts when you stop arms |
| Workflows | Read and write | Add `.github/workflows/statespace.yml` in the setup pull request |
| Metadata | Read | Required by GitHub |

The App writes only `statespace.toml` and the Statespace workflow. It receives the events check suite, pull request, pull request review, and push.

## Tokens

CI needs no token: `ssp apply` proves itself with the job's GitHub OIDC token. Your servers and SQL clients need their own tokens.

| Where | Token | Purpose |
| --- | --- | --- |
| Your terminal | `ssp login` | Show what runs, stop and resume arms, and manage tokens |
| CI | none | Record images with `ssp apply` |
| Your servers | `--preset runtime` | Run `ssp proxy` |
| Kubernetes | `--preset controller` | Run `ssp controller kubernetes` |
| SQL clients | `--preset analyst` | Read runs, lines, and requests |

Create a runtime token for `ssp proxy`, then store the returned token as `SSP_TOKEN` in a secret manager.

```shell
ssp token create --name production --preset runtime
```

Check which credential the CLI uses and what it may do.

```shell
ssp whoami
```

Set `STATESPACE_URL` when the CLI or proxy uses a local API or a hosted domain other than its default.

```shell
export STATESPACE_URL=http://127.0.0.1:8080
```

See [Deployment](/getting-started/deployment) to set up CI and run proxies in production.
