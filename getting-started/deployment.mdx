A deployment has three parts. CI records the image of each commit with `ssp apply`. Branch protection decides who approves each commit of an arm. Your servers run `ssp proxy` in front of the app.

The [FastAPI example](https://github.com/statespace-tech/statespace/tree/main/examples/fastapi) and the [Kubernetes example](https://github.com/statespace-tech/statespace/tree/main/examples/kubernetes) have every file on this page, ready to copy.

## Record builds from CI

`ssp init github` writes `.github/workflows/statespace.yml`. It builds each commit of an `exp/` branch the way you build production, pushes the image, and records it.

```yaml
name: Statespace
on:
  push:
    branches: ["exp/**"]
permissions:
  contents: read
  packages: write
  id-token: write
jobs:
  arm:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5
      - uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}
      - uses: docker/build-push-action@v6
        id: build
        with:
          push: true
          tags: ghcr.io/acme/atlas:${{ github.sha }}
      - uses: statespace-tech/action@v1
        with:
          image: ghcr.io/acme/atlas@${{ steps.build.outputs.digest }}
```

Add the same last step to the workflow that builds production, after its build. On the default branch, the step records a default build. When a proxy runs that image, its commit becomes a base that arms can start from.

The job needs `id-token: write`. `ssp apply` sends the job's GitHub OIDC token, which proves the repository, the workflow, and the commit. CI keeps no Statespace secret.

## Protect the default branch

An arm runs only while GitHub says that its pull request can merge. So your branch protection or rulesets decide who approves:

- Require one approval, so that a second person approves each commit before users see it.
- Turn on "Dismiss stale pull request approvals when new commits are pushed", so that each new commit needs a new approval.
- To make a team approve every change of an arm's share or rules, put `statespace.toml` in `CODEOWNERS` and require code owner review.

Without branch protection, a pull request can merge at once, and its arm runs without review.

## Run proxies on Docker

On a virtual machine with Docker, `ssp proxy` runs the app's default image and every arm as containers on private ports of `127.0.0.1`, and listens on the public port. Run it with systemd.

```ini
[Unit]
After=docker.service
Requires=docker.service

[Service]
SupplementaryGroups=docker
EnvironmentFile=/etc/atlas/env
Environment=STATESPACE_APP=atlas
Environment=STATESPACE_IMAGE_FILE=/etc/atlas/image
ExecStart=/usr/local/bin/ssp proxy --health /health
ExecReload=/bin/kill -HUP $MAINPID
KillMode=mixed
TimeoutStopSec=60
Restart=always
```

Pass the runtime token as `SSP_TOKEN`. The containers inherit the service's environment, such as the app's settings in `/etc/atlas/env`, without the proxy's own variables.

Deploy a new default by writing its image to the file and reloading the service. The proxy starts the new image, sends it traffic once `--health` answers, then stops the old container.

```shell
echo ghcr.io/acme/atlas:4f2a9c1 | sudo tee /etc/atlas/image
sudo systemctl reload atlas
```

## Run proxies on Kubernetes

On Kubernetes, the default is your Deployment as it is. Add `ssp proxy` to its pods as a sidecar, and point the Service at the sidecar's port. With `--default`, the proxy only routes.

```yaml
containers:
  - name: atlas
    image: ghcr.io/acme/atlas:main
    ports:
      - containerPort: 8000
  - name: statespace-proxy
    image: ghcr.io/statespace-tech/statespace:0.2.0
    args: ["proxy", "--default", "http://localhost:8000"]
    env:
      - name: STATESPACE_APP
        value: atlas
      - name: SSP_TOKEN
        valueFrom:
          secretKeyRef: {name: statespace, key: runtime-token}
    ports:
      - containerPort: 8080
```

The Service's `targetPort` becomes `8080`, the sidecar's port.

Run one `ssp controller kubernetes` in the namespace with a controller token. It runs each arm and control as a copy of the Deployment with the arm's image, and deletes it when the arm stops. It also reports the digest of the default that the Deployment's pods run. Apply the example's [manifest](https://github.com/statespace-tech/statespace/blob/main/examples/kubernetes/statespace-controller.yaml), which grants it Deployments, Services, and its ConfigMap in this namespace, and read access to pods and their logs.

```shell
ssp token create --name controller --preset controller
kubectl apply -f statespace-controller.yaml
```

See [Controller](/reference/controller) for what each arm copies from the default.

## Load balancers

Keep as many machines or pods as you run now. Every proxy assigns a subject to the same arm, so requests need no sticky sessions.

Point health checks at the app's health path. The default answers them, so a proxy passes while arms start.

On `SIGTERM`, a proxy lets requests finish for up to 10 seconds. Give the platform a longer stop timeout than that.

## Capacity

Each proxy on Docker, and each controller, runs up to `--max-arms` arms, 5 by default, controls included. Size machines for that many copies of the app, or lower the limit. On Kubernetes, each arm gets the default's replicas times its share of subjects, at least one. Subjects of the arms beyond the limit get the default.

To limit how many subjects are in experiments at all, set the app's traffic limit. Arms that do not fit wait, first come, first served.

```shell
ssp app set atlas --max-traffic 0.2
```

Check what each proxy runs.

```sql
SELECT id, kind, version, max_arms, report FROM atlas.hosts;
```
