A deployment has three parts. CI records the image of each commit. Branch protection decides who approves each commit of an arm. Your servers run `ssp proxy` in front of the app.

<Tip>
  The [FastAPI example](https://github.com/statespace-tech/statespace/tree/main/examples/fastapi) and the [Kubernetes example](https://github.com/statespace-tech/statespace/tree/main/examples/kubernetes) have every file on this page, ready to copy.
</Tip>

## Record builds from CI

<Steps>
  <Step title="Merge the Statespace workflow">
    The "Set up Statespace" pull request adds this workflow. It builds each commit of an `exp/` branch from the `Dockerfile` nearest the root of the repository. Then it pushes the image to GitHub Packages, and records it.

    ```yaml .github/workflows/statespace.yml
    # Build each commit of an exp/ branch, and record
    # it as a version of its arm.
    name: Statespace
    on:
      push:
        branches: ["exp/**"]
    permissions:
      contents: read
      packages: write
      id-token: write
    jobs:
      arm:
        runs-on: ubuntu-latest
        steps:
          - uses: actions/checkout@v5
          - uses: docker/login-action@v3
            with:
              registry: ghcr.io
              username: ${{ github.actor }}
              password: ${{ secrets.GITHUB_TOKEN }}
          # This step builds your Dockerfile. To build
          # another way, such as with ko, Jib, or
          # buildpacks, replace this step. Keep the id
          # and the digest output, or give the image to
          # the last step.
          - uses: docker/build-push-action@v6
            id: build
            with:
              context: .
              push: true
              tags: ghcr.io/acme/atlas:${{ github.sha }}
          # Record the image. Keep this step.
          - uses: statespace-tech/action@v1
            with:
              image: >-
                ghcr.io/acme/atlas@${{ steps.build.outputs.digest }}
    ```

    When the `Dockerfile` is in a folder, such as `services/api/Dockerfile`, the build step sets `context: services/api` and `file: services/api/Dockerfile`. If the repository has no `Dockerfile`, the comment above the build step says so. Change that step to build your image the way you build production. Keep its `id`, or give the image to the last step.
  </Step>

  <Step title="Record production builds">
    Add the last step of the workflow to the workflow that builds production, after its build. The App does not change deploy workflows, so this step is yours to add.

    ```yaml .github/workflows/production.yml
    - uses: statespace-tech/action@v1
      with:
        image: >-
          ghcr.io/acme/atlas@${{ steps.build.outputs.digest }}
    ```

    On the default branch, the step records a default build. When a proxy runs that image, its commit becomes a base that arms can start from.
  </Step>
</Steps>

Both jobs need `id-token: write`. `ssp apply` sends the job's GitHub OIDC token, which proves the repository, the workflow, and the commit. CI keeps no Statespace secret.

## Protect the default branch

An arm runs only while GitHub says that its pull request can merge. So your branch protection or rulesets decide who approves.

- Require one approval, so that a second person approves each commit before users see it.
- Turn on "Dismiss stale pull request approvals when new commits are pushed". Then each new commit needs a new approval.
- To make a team approve each change of an arm's settings, put `statespace.toml` in `CODEOWNERS`. Then require code owner review.

<Warning>
  Without branch protection, a pull request can merge at once, and its arm runs without review.
</Warning>

## Run proxies

<Tabs>
  <Tab title="Docker">
    On a virtual machine with Docker, `ssp proxy` runs the default image and each arm as containers. The containers use private ports of `127.0.0.1`, and the proxy listens on the public port. Run the proxy with systemd.

    ```ini /etc/systemd/system/atlas.service
    [Unit]
    After=docker.service
    Requires=docker.service

    [Service]
    SupplementaryGroups=docker
    EnvironmentFile=/etc/atlas/env
    Environment=STATESPACE_IMAGE_FILE=/etc/atlas/image
    ExecStart=/usr/local/bin/ssp proxy --health /health
    ExecReload=/bin/kill -HUP $MAINPID
    KillMode=mixed
    TimeoutStopSec=60
    Restart=always
    ```

    Put a runtime token for the app in `/etc/atlas/env` as `SSP_TOKEN`. The proxy takes the app from the token. The containers get the environment of the service, but not the variables of the proxy.

    ```shell
    ssp token create --name atlas-proxy \
      --preset runtime --app atlas
    ```

    To deploy a new default, write its image to the file, and reload the service. The proxy starts the new image. When `--health` answers, the proxy sends it traffic and stops the old container.

    ```shell
    echo ghcr.io/acme/atlas:4f2a9c1 \
      | sudo tee /etc/atlas/image
    sudo systemctl reload atlas
    ```
  </Tab>

  <Tab title="Kubernetes">
    On Kubernetes, the default is your Deployment as it is. Add `ssp proxy` to its pods as a sidecar. With `--default`, the proxy only routes.

    ```yaml deployment.yaml
    containers:
      - name: atlas
        image: ghcr.io/acme/atlas:main
        ports:
          - containerPort: 8000
      - name: statespace-proxy
        image: ghcr.io/statespace-tech/statespace:0.3.0
        args:
          - proxy
          - --default
          - http://localhost:8000
        env:
          - name: SSP_TOKEN
            valueFrom:
              secretKeyRef:
                name: statespace
                key: token
        ports:
          - containerPort: 8080
    ```

    Set the Service's `targetPort` to `8080`, the sidecar's port.

    Run one `ssp controller kubernetes` in the namespace. It runs each arm and control as a copy of the Deployment, with the arm's image. When the arm stops, the controller deletes the copy. It also reports the digest of the default that the Deployment's pods run.

    The sidecars and the controller use the same runtime token for the app, and take the app from it.

    ```shell
    ssp token create --name atlas \
      --preset runtime --app atlas
    kubectl create secret generic statespace \
      --from-literal=token=<token>
    kubectl apply -f statespace-controller.yaml
    ```

    The example's [manifest](https://github.com/statespace-tech/statespace/blob/main/examples/kubernetes/statespace-controller.yaml) gives the controller its permissions. It can change Deployments, Services, and its ConfigMap in the namespace, and read pods and their logs. See [Controller](/reference/controller) for what each arm copies from the default.
  </Tab>
</Tabs>

## Load balancers

Keep as many machines or pods as you run now. All proxies assign a subject to the same arm, so requests need no sticky sessions.

- Point health checks at the app's health path. The default answers them, so a proxy passes while arms start.
- On `SIGTERM`, a proxy lets requests finish for up to 10 seconds. Give the platform a longer stop timeout than that.

## Capacity

Each proxy on Docker, and each controller, runs a maximum of `--max-arms` arms, controls included. The default is 5. Make the machines large enough for that many copies of the app, or set a lower limit. On Kubernetes, each arm gets the replicas of the default, times its share of subjects. Each arm gets a minimum of one replica. Subjects of arms over the limit get the default.

To limit how many subjects are in experiments at all, set the app's traffic limit on the default branch. Arms that do not fit wait, first come, first served. The setup pull request sets 20%. Without the key, the limit is 100%.

```toml statespace.toml
app = "atlas"
max_traffic = 0.2
```

You can also change it with **Edit** on the **Apps** page of the dashboard. The App opens a pull request that changes the file, and the limit changes when the pull request merges.

Check what each proxy runs.

```sql
SELECT id, kind, version, max_arms, report
FROM atlas.hosts;
```
