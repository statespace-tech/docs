---
title: Account-level experiment
description: Keep users in one account in the same arm.
---

Use account-level randomization when users share data or can affect each other. The randomization unit is the account, not each user or request.

Read the account from the request in the subject rule of the branch's `statespace.toml`. Here a gateway in front of the app sets `x-account-id`.

```toml
app = "atlas"
share = 0.1
subject = 'request.headers["x-account-id"]'
```

Every user in an account gets the same arm on every proxy. The app receives the account ID as `x-statespace-subject`. All arms of the experiment must use this subject rule.

Print lines with the account ID as the subject.

```python
subject = request.headers["x-statespace-subject"]
print(json.dumps({
    "event": "click",
    "subject": subject,
    "user": user_id,
}))
```

Count independent accounts rather than requests.

```sql
SELECT arm, commit, count(DISTINCT subject_id) AS accounts
FROM atlas.runs
WHERE experiment = 'ranking'
  AND experiment_version = 1
  AND reason IN ('assigned', 'arm-unavailable')
GROUP BY arm, commit;
```

Aggregate outcomes at the account level before a simple independent-unit analysis. Request-level standard errors can understate uncertainty when requests in an account are related.
