---
title: Account-level experiment
description: Keep all users of one account in the same arm, and count accounts, not requests.
---

Use the account as the subject when users of an account share data, or can affect each other. In this example, a gateway in front of `atlas` sets the `x-account-id` header.

<Steps titleSize="h3">
  <Step title="Use the account as the subject">
    Read the account from the request in the arm's `statespace.toml`.

    ```toml statespace.toml
    app = "atlas"
    share = 0.1
    subject = 'request.headers["x-account-id"]'
    ```

    Each user of an account gets the same arm on every proxy. All arms of the experiment must use this subject rule.
  </Step>

  <Step title="Print the outcome">
    The app gets the account ID in the `x-statespace-subject` header. Print it as the subject, and print the user as a field.

    ```python
    subject = request.headers["x-statespace-subject"]
    print(json.dumps({
        "event": "click",
        "subject": subject,
        "user": user_id,
    }))
    ```
  </Step>

  <Step title="Count accounts">
    Count independent accounts, not requests.

    ```sql
    SELECT arm, commit,
           count(DISTINCT subject_id) AS accounts
    FROM atlas.runs
    WHERE experiment = 'ranking'
      AND experiment_version = 1
      AND reason IN ('assigned', 'arm-unavailable')
    GROUP BY arm, commit;
    ```
  </Step>
</Steps>

<Warning>
  Requests of one account are related. Aggregate outcomes for each account before an analysis that assumes independent units. Otherwise the uncertainty looks smaller than it is.
</Warning>
