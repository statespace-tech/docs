---
title: Account-level experiment
description: Keep users in one account in the same variant.
---

Use account-level randomization when users share data or can affect each other. The randomization unit is the account, not each user or request.

Read the account from the request in the subject rule. Here a gateway in front of the app sets `x-account-id`.

```shell
ssp experiment create rank-v2 --app atlas --variant atlas-search=0.5 \
  --subject 'request.headers["x-account-id"]' \
  --note 'Test sorted results by account.'
ssp experiment start rank-v2
```

Every user in an account gets the same variant on every host. The app receives the account ID as `x-statespace-subject`.

Print outcomes with the account ID as the subject.

```python
subject = request.headers["x-statespace-subject"]
print(json.dumps({"statespace": "click", "subject": subject, "user": user_id}))
```

Count independent accounts rather than requests.

```sql
SELECT variant, count(DISTINCT subject_id) AS accounts
FROM atlas.runs
WHERE experiment = 'rank-v2' AND experiment_version = 1 AND reason = 'assigned'
GROUP BY variant;
```

Aggregate outcomes at the account level before a simple independent-unit analysis. Request-level standard errors can understate uncertainty when requests in an account are related.
