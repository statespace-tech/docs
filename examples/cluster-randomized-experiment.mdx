---
title: Cluster-randomized experiment
description: Assign related observations through one shared cluster identifier.
---

This standalone example tests ranking at the organization level. Every user in one organization receives the same group.

## Define the experiment

Set `account_id` as the experiment randomization unit.

```yaml
name: rank-v2
description: Test reciprocal rank fusion by account.
assignment: account_id
traffic: 1.0
groups:
  - name: treatment
    weight: 0.50
    config:
      reranker: rrf
```

## Assign the clusters

Pass the account identifier for every user request.

```python
config = run.get_config("account_7")
reranker = config.get("reranker", None)
```

The same account receives one stable group across its users and runs.

## Aggregate the outcomes

Build one outcome value for each independently assigned account.

```sql
WITH account_outcomes AS (
  SELECT
    subject_id AS account_id,
    group_name,
    avg(data.relevance::DOUBLE) AS account_relevance
  FROM statespace.logs
  WHERE experiment_name = 'rank-v2'
  GROUP BY subject_id, group_name
)
SELECT
  group_name,
  count(*) AS accounts,
  avg(account_relevance) AS mean_relevance
FROM account_outcomes
GROUP BY group_name;
```

## Estimate the effect

Use the number of assigned accounts, not the number of users or requests, as the independent sample size.

| Count | Role |
| --- | --- |
| Accounts | Independent experimental units |
| Users | Observations nested in accounts |
| Requests | Repeated observations nested in users |

Use a cluster-aware method when the analysis retains user-level or request-level rows.
