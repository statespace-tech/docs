---
title: Analysis walkthrough
description: Check delivery and health, then compare one JSON outcome.
---

Analyze one immutable version at a time.

## Check delivery

Count runs by assignment reason.

```sql
SELECT reason, count(*)
FROM atlas.runs
WHERE experiment = 'rank-v2'
  AND experiment_version = 1
GROUP BY reason;
```

A large share of `variant-unavailable` means the variant often could not serve its subjects. Read its lifecycle events before you go on.

```shell
ssp variant logs atlas-search --app atlas
```

## Check allocation

Compare observed variant shares with configured weights.

```sql
SELECT
  variant,
  count(*) AS runs,
  count(*)::double precision / sum(count(*)) OVER () AS observed_share
FROM atlas.runs
WHERE experiment = 'rank-v2'
  AND experiment_version = 1
  AND reason = 'assigned'
GROUP BY variant;
```

## Check health

Compare error rates and latency of each process.

```sql
SELECT
  variant,
  sum((data->>'errors')::int)::double precision
    / nullif(sum((data->>'requests')::int), 0) AS error_rate,
  avg((data->>'p90_ms')::double precision) AS mean_p90_ms
FROM atlas.metrics
WHERE kind = 'http'
GROUP BY variant;
```

## Compare the outcome

Read the planned field from each JSON outcome.

```sql
SELECT
  variant,
  count(*) AS observations,
  avg((data->>'position')::double precision) AS mean_position,
  stddev_samp((data->>'position')::double precision) AS sd_position
FROM atlas.logs
WHERE experiment = 'rank-v2'
  AND experiment_version = 1
  AND outcome_name = 'click'
GROUP BY variant;
```

## Record the decision

Stop the experiment with a note that states the decision and its evidence.

```shell
ssp experiment stop rank-v2 --note 'Keep control: no change in click position, p90 latency +40 ms.'
```
