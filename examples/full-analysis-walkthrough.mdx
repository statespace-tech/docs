---
title: Analysis walkthrough
description: Check delivery and health, then compare one field of the lines arms print.
---

Analyze one immutable version at a time.

## Check delivery

Count runs by assignment reason.

```sql
SELECT reason, count(*)
FROM atlas.runs
WHERE experiment = 'ranking'
  AND experiment_version = 1
GROUP BY reason;
```

A large share of `arm-unavailable` means an arm often could not serve its subjects. Read its lifecycle events and errors before you go on.

```sql
SELECT timestamp, arm, commit, event, data
FROM atlas.lifecycle
WHERE experiment = 'ranking'
ORDER BY timestamp DESC
LIMIT 20;
```

## Check allocation

Compare each arm's subjects with the number its share predicts.

```sql
SELECT arm, commit, subjects, expected, p_value, mismatch
FROM atlas.sample_ratio
WHERE experiment = 'ranking' AND experiment_version = 1;
```

## Check health

Compare error rates and latency of each arm.

```sql
SELECT
  arm,
  commit,
  avg((status >= 500)::int) AS error_rate,
  percentile_cont(0.9)
    WITHIN GROUP (ORDER BY duration_ms) AS p90_ms
FROM atlas.requests
WHERE experiment = 'ranking' AND experiment_version = 1
GROUP BY arm, commit;
```

## Compare the outcome

Read the planned field from each JSON line.

```sql
SELECT
  arm,
  commit,
  count(*) AS observations,
  avg((data->>'position')::float) AS mean_position,
  stddev_samp((data->>'position')::float) AS sd_position
FROM atlas.logs
WHERE experiment = 'ranking'
  AND experiment_version = 1
  AND data->>'event' = 'click'
GROUP BY arm, commit;
```

## Record the decision

Write the decision and its evidence in the pull request. Then close it to drop the arm, or merge it to ship.

```shell
gh pr close 412 --comment "Keep the default:
no change in click position, p90 latency +40 ms."
```
