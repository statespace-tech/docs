---
title: Analysis walkthrough
description: Check delivery and health, then compare one field of the lines arms print.
---

Analyze one immutable version at a time.

## Check delivery

Count runs by assignment reason.

```sql
SELECT reason, count(*)
FROM atlas.runs
WHERE experiment = 'rank-v2'
  AND experiment_version = 1
GROUP BY reason;
```

A large share of `variant-unavailable` means an arm often could not serve its subjects. Read its lifecycle events and errors before you go on.

```sql
SELECT timestamp, variant, event, data
FROM atlas.lifecycle
WHERE experiment = 'rank-v2'
ORDER BY timestamp DESC
LIMIT 20;
```

## Check allocation

Compare each arm's subjects with the number its share predicts.

```sql
SELECT variant, subjects, expected, p_value, mismatch
FROM atlas.sample_ratio
WHERE experiment = 'rank-v2' AND experiment_version = 1;
```

## Check health

Compare error rates and latency of each arm.

```sql
SELECT
  variant,
  avg((status >= 500)::int) AS error_rate,
  percentile_cont(0.9) WITHIN GROUP (ORDER BY duration_ms) AS p90_ms
FROM atlas.requests
WHERE experiment = 'rank-v2' AND experiment_version = 1
GROUP BY variant;
```

## Compare the outcome

Read the planned field from each JSON line.

```sql
SELECT
  variant,
  count(*) AS observations,
  avg((data->>'position')::double precision) AS mean_position,
  stddev_samp((data->>'position')::double precision) AS sd_position
FROM atlas.logs
WHERE experiment = 'rank-v2'
  AND experiment_version = 1
  AND data->>'event' = 'click'
GROUP BY variant;
```

## Record the decision

Stop the experiment with a note that states the decision and its evidence.

```shell
ssp experiment stop rank-v2 --note 'Keep the default: no change in click position, p90 latency +40 ms.'
```
