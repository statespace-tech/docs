Statespace A/B tests whole versions of an app in production. A branch named `exp/<experiment>/<arm>` is an arm. When GitHub says that its pull request can merge, `ssp proxy` sends a share of real subjects to the branch, and the same share to a control: the version the branch started from. Then it records what they do.

```text
push exp/ branch → CI runs ssp apply → pull request can merge → ssp proxy routes subjects → arms print lines → SQL
```

## What serves a request

Every request goes to one of three places.

| Target | What it runs | Who gets it |
| --- | --- | --- |
| Default | The image you deployed | Every subject outside an experiment |
| Control | The default build of the commit an arm's branch started from | An experiment's baseline |
| Arm | The image of a commit of an `exp/` branch | An experiment's treatment |

A control gets the share of the largest arm on its base. Compare an arm with its control.

## What decides

GitHub decides what may run, and Statespace decides only whether it runs fairly.

| The pull request | The arm |
| --- | --- |
| Can merge | Runs the latest commit |
| Never could merge | Does not run |
| Could merge, and then could not | Runs the last commit that could merge, and warns after 7 days |
| Is a draft, or a reviewer requested changes | Stops |
| Merged | The experiment ends |

Branch protection decides who must approve. Each new commit needs a new approval, unless your repository says otherwise.

## Interfaces

| Interface | Responsibility |
| --- | --- |
| GitHub App | Reports the state of pull requests, and posts the `statespace/apply` and `statespace/arm` checks. |
| `ssp apply` | Runs in CI. It records the image of each commit with the job's GitHub OIDC token. |
| `ssp proxy` | Assigns each request's subject and forwards it. With `--image`, it also runs the default and the arms on Docker. |
| `ssp controller kubernetes` | Runs the arms on Kubernetes as copies of the default's Deployment. |
| PostgreSQL | Stores one isolated account database, with one schema of views per app. |

Your app prints what happens, as it already does. Every line an arm prints is recorded, and a JSON line with a `subject` field is tied to that subject's arm.

```python
print(json.dumps({"event": "click", "subject": subject, "position": 1}))
```
