Statespace A/B tests whole versions of an app in production. A variant is a signed image of your app, usually built from a branch. `ssp proxy` sends a share of real subjects to it and the same share to a control arm of the version you deployed, and records what they do.

```text
ssp variant create → ssp experiment start → ssp proxy routes subjects → arms print lines → SQL
```

## What serves a request

Every request goes to one of three places.

| Target | What it runs | Who gets it |
| --- | --- | --- |
| Default | The image you deployed | Every subject outside an experiment |
| Control | The default's image, pinned when the experiment started | An experiment's baseline arm |
| Variant | A signed image of a branch | An experiment's treatment arm |

Control and each variant get the same share of subjects. Compare a variant with its experiment's control arm.

## Interfaces

Each interface has one responsibility.

| Interface | Responsibility |
| --- | --- |
| `ssp` CLI | Defines apps, publishes variants, runs experiments, and manages tokens. |
| `ssp proxy` | Assigns each request's subject and forwards it. On Docker, it also runs the default and the arms. |
| `ssp controller` | Runs the arms on Kubernetes as copies of the default's Deployment. |
| PostgreSQL | Stores one isolated account database, with one schema of views per app. |

Your app prints what happens, as it already does. Every line an arm prints is recorded, and a JSON line with a `subject` field is tied to that subject's arm.

```python
print(json.dumps({"event": "click", "subject": subject, "position": 1}))
```
