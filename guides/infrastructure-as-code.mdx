Your infrastructure tools need no setting for Statespace. Use this page to see what they see while the proxy runs.

## What the proxy changes

- The proxy never changes a resource that it did not create. Your service, Deployment, container, and bucket stay as you deployed them.
- Each arm is a resource that the proxy creates, labels, and deletes. It is not in the state of your tools.
- When an experiment stops, the proxy deletes its arms.
- The proxy itself is a resource that you deploy. Manage it with the same tool as live.

| Runtime | Each arm is | Label of the app |
| --- | --- | --- |
| Docker | A container `<live>-ssp-…`, with no Compose labels | `com.statespace.app` |
| Kubernetes | A Deployment and a Service `<deployment>-ssp-…` | `statespace.com/app` |
| Cloud Run | A service `<service>-ssp-…` | `statespace-app` |
| ECS Fargate | A service and task definition `<service>-ssp-…` | `statespace.com/app` |
| Fly.io | A Machine `ssp-…`, with no services | `statespace_app` |
| S3, Cloud Storage | A build folder that your CI uploads | None |

The other labels are in [Use your own data tools](/guides/own-tools#resource-labels).

## No drift

| Tool | What it sees |
| --- | --- |
| Terraform, OpenTofu, Pulumi | `plan` and `preview` show no change. A full apply of live does not change the arms. |
| CloudFormation, CDK | Drift detection shows no drift. |
| Helm | `helm upgrade`, `helm diff`, and `helm uninstall` see only the objects of the release. |
| Argo CD | The Application stays `Synced`. With orphaned resource monitoring, it lists the arms as orphaned. |
| Flux | `prune: true` deletes only the objects that Flux applied. |
| Docker Compose | `up --remove-orphans` and `down` do not remove the arms. `down` stops the proxy, and the proxy removes its arms. |
| Fly.io | `fly deploy` and `fly scale` do not change the arms. |

Keep the permissions of the proxy in your code too, such as its IAM role or Kubernetes Role.

## Ignore rules

On S3 and Cloud Storage, the builds are folders in the bucket of live, such as `builds/`. A deploy that deletes unknown files also deletes the builds. Then the subjects of those arms get live. Exclude the folder:

```shell
aws s3 sync dist/ s3://acme-site/ --delete \
  --exclude 'builds/*'
gcloud storage rsync -r dist/ gs://acme-site/ \
  --delete-unmatched-destination-objects \
  --exclude 'builds/.*'
```

A tool that manages each object of the bucket, such as Terraform with one resource for each file, must leave out `builds/`.

## Before you delete live

The arms are not in your state, so `terraform destroy`, `pulumi destroy`, and a stack delete do not delete them. An arm that stays can block a delete, such as of an ECS cluster that still has services. Stop the experiments of the app first:

```shell
ssp experiment list --app shop-prod --running
ssp experiment stop checkout --app shop-prod \
  --note "remove the stack"
```
