The proxy runs only builds that your CI recorded. Use this guide to record each build with `statespace-tech/action@v1`.

## Record each build

Record each commit that can become an arm. The workflows below record each push to each branch. A branch name means nothing to Statespace.

The runtime of the app sets the kind of build. Docker, Kubernetes, ECS Fargate, Cloud Run, Fly.io, and Lambda run an image. S3 and Cloud Storage serve a folder of files.

The job needs `id-token: write`. The action sends the GitHub OIDC token of the job. Statespace gets the repo and the commit from it, so CI keeps no Statespace secret.

Put the action step after your tests to record only tested commits.

## When the step fails

The step fails, and Statespace records nothing, when:

- the registry does not have the image by digest, or the job cannot read it;
- the folder is empty, or the job cannot read it;
- `statespace.toml` has a wrong key, a wrong type, or a CEL error. The step prints the message.

A section `[app.<name>]` that matches no app gives a warning only.

## Build labels

Some builds put a different value in the build for each app, such as the API address of `shop-dev` and `shop-prod`. Make one build for each app, and give it `app`. This job builds once for each app in its matrix:

```yaml .github/workflows/build.yml
jobs:
  build:
    strategy:
      matrix:
        app: [shop-dev, shop-prod]
    steps:
      # Build the image for matrix.app, as above.
      - uses: statespace-tech/action@v1
        with:
          image: >-
            ghcr.io/acme/shop@${{ steps.build.outputs.digest }}
          path: .
          app: ${{ matrix.app }}
```

1. A build with `app: shop-prod` serves only `shop-prod`.
2. For `shop-prod`, it wins over a build of the same commit without `app`.
3. A build without `app` serves every app of the repo and folder.

`ssp experiment update` prints the build that it chose for each arm.

## Reproducible builds

Statespace records one build for each commit, folder, and label, and never changes it. When CI builds a commit again, such as on a branch and then on `main`, the result must be the same. The same image or files again is accepted. A different build fails the step:

```text
a1b2c3d has a build without app already. Add app: so
Statespace knows which build is for which app
```

Many tools put the time or a random ID in the build. Use the commit instead:

| Tool | Setting |
| --- | --- |
| SvelteKit | `kit.version.name`: the commit, such as `process.env.GITHUB_SHA` |
| Next.js | `generateBuildId`: return the commit |
| Docker | Build from the same files, and do not copy the time into the image |

## Inputs

Give exactly one of `image` and `files`.

<ParamField body="image" type="string">
  The image by digest, such as `ghcr.io/acme/shop@sha256:…`. The action resolves a tag to its digest.
</ParamField>

<ParamField body="files" type="string">
  The folder, as `s3://<bucket>/<folder>/` or `gs://<bucket>/<folder>/`. It ends with `/`. It cannot be the root of the bucket.
</ParamField>

<ParamField body="path" type="string" default=".">
  The folder of `statespace.toml`, from the root of the repo.
</ParamField>

<ParamField body="app" type="string">
  The app that this build is for. See [Build labels](#build-labels).
</ParamField>
