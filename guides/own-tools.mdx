Statespace keeps only the counts for its results. Use this guide to find the requests, logs, and traces of an arm in the tools that you use now.

## The labels of an arm

The proxy labels each arm. It sends no data to your tools: they read the labels where they already collect data. Live gets none of these labels, so no label means live. Each label holds the full commit.

| Where | Label | Read by |
| --- | --- | --- |
| The resources of the arm | The experiment and the commit. See [Resource labels](#resource-labels) | Log collectors, cloud consoles |
| The environment of the arm | `SSP_EXPERIMENT`, `SSP_ARM`, `OTEL_RESOURCE_ATTRIBUTES` | Your code, every OpenTelemetry SDK |
| Each request to the arm | The headers `ssp-experiment` and `ssp-arm` | Your app |
| The browser of the subject | The cookie `ssp_arms` | Browser analytics |

On S3 and Cloud Storage, an arm is a folder of files. The cookie is its only label.

## Resource labels

| Runtime | Resource | Experiment | Commit |
| --- | --- | --- | --- |
| Docker | Container labels | `com.statespace.experiment` | `com.statespace.commit` |
| Kubernetes | Deployment and pod labels | `statespace.com/experiment` | `statespace.com/commit` |
| ECS Fargate | Service and task definition tags | `statespace.com/experiment` | `statespace.com/commit` |
| Cloud Run | Service labels | `statespace-experiment` | `statespace-commit` |
| Fly.io | Machine metadata | `statespace_experiment` | `statespace_commit` |

## Environment and headers

The container that runs the arm gets `SSP_EXPERIMENT` (such as `checkout`) and `SSP_ARM` (the commit). The proxy also adds three keys to the `OTEL_RESOURCE_ATTRIBUTES` of live. For example, live has `deployment.environment=prod,service.version=1.4.2`. The arm gets this value:

```text
deployment.environment=prod,
statespace.experiment=checkout,
statespace.arm=a1b2c3d…,service.version=a1b2c3d…
```

- When live reads the variable from a secret or a reference, such as `valueFrom` on Kubernetes, the arm gets only its own keys.
- Live never gets `SSP_EXPERIMENT` or `SSP_ARM`. The proxy does not copy their values from live to an arm.

The proxy adds `ssp-experiment` and `ssp-arm` to each request of an arm. It first removes them from each incoming request, so a client cannot set them.

## The browser cookie

A response that an arm serves to an assigned subject sets `ssp_arms`:

```text
ssp_arms=checkout:a1b2c3d…; Path=/;
  Max-Age=7776000; SameSite=Lax; Secure
```

JavaScript can read it. It lasts 90 days, as `ssp_sid`. Over plain `http`, it has no `Secure`. When a later request is in no arm, such as live or an override, the response removes it. An override never sets it.

## Find an arm

`ssp experiment show` prints the label of each arm and the start of the version:

```text
Find it in your own data tools: statespace.arm = "c0ffee1…" | "a1b2c3d…"
```

1. Set the time range of your tool to the time of the version.
2. Filter by `statespace.arm` or `service.version`, with the full commit. `--json` gives it in `lookup`.
3. In browser analytics, filter by `ssp_arms`, such as `checkout:c0ffee1…`.

## Examples

<Tabs>
  <Tab title="OpenTelemetry">
    Every OpenTelemetry SDK reads `OTEL_RESOURCE_ATTRIBUTES`. So each span, log, and metric of an arm has `statespace.arm`, with no code change. For data that no SDK sends, such as container logs, the Collector copies the pod labels:

    ```yaml otel-collector.yaml
    processors:
      k8sattributes:
        extract:
          labels:
            - tag_name: statespace.arm
              key: statespace.com/commit
              from: pod
    ```
  </Tab>
  <Tab title="Datadog">
    With OpenTelemetry, Datadog maps `service.version` to `version`. In APM, filter by `version:<commit>`. With the Datadog Agent on Kubernetes, turn the pod label into a tag, and filter by `ssp_arm:<commit>`:

    ```yaml values.yaml
    datadog:
      podLabelsAsTags:
        statespace.com/commit: ssp_arm
    ```

    On Docker, use `DD_CONTAINER_LABELS_AS_TAGS` with `com.statespace.commit`. With a Datadog tracing library, set `DD_VERSION` from `SSP_ARM` in the start script of the image:

    ```sh entrypoint.sh
    #!/bin/sh
    # Live has no SSP_ARM, so it keeps its DD_VERSION.
    if [ -n "$SSP_ARM" ]; then
      export DD_VERSION="$SSP_ARM"
    fi
    exec "$@"
    ```
  </Tab>
  <Tab title="Grafana">
    In Tempo, use TraceQL. A regular expression must match the full value, so end it with `.*`:

    ```text
    { resource.statespace.arm =~ "a1b2c3d.*" }
    ```

    Loki keeps resource attributes as structured metadata, with `_` in place of `.`:

    ```text
    {service_name="shop"} | statespace_arm=~"a1b2c3d.*"
    ```
  </Tab>
  <Tab title="Browser analytics">
    Read the cookie, and send it to your tool. A browser in no arm gets `none`:

    ```js arms.js
    const arms =
      document.cookie
        .split("; ")
        .find((c) => c.startsWith("ssp_arms="))
        ?.slice("ssp_arms=".length) ?? "none";
    ```

    PostHog sends a super property with each event:

    ```js
    posthog.register({ ssp_arms: arms });
    ```

    A GA4 user property has 36 characters at most. Send the first 7 characters of the commit:

    ```js
    const [experiment, commit] = arms.split(":");
    const value = commit
      ? `${experiment}:${commit.slice(0, 7)}`
      : "none";
    gtag("set", "user_properties", { ssp_arms: value });
    ```

    Then, in GA4 **Admin** > **Custom definitions**, make a custom dimension with the scope **User** and the property `ssp_arms`.
  </Tab>
</Tabs>
