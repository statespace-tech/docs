A coding agent can run the whole loop: change the code, run the change as an arm, read the evidence, and decide. Every command works without questions and prints JSON with `--json`.

## Give the agent the skill

Give this prompt to your coding agent.

```text
Read https://statespace.com/skill.md and follow it.
```

The skill has the [starter file](/reference/statespace-toml#starter-file). So the agent can write `statespace.toml` for a new app.

## Give the agent a credential

The agent uses a GitHub credential. Its role on the repo decides what it can do. To update, start, and stop experiments, the agent needs the role Write or Maintain. See [Permissions](/concepts/permissions).

- In a terminal, sign in with `ssp login`.
- For the API, send a GitHub user token, such as `github_pat_...`.

## The loop

In this example, the live `statespace.toml` of `shop-prod` has the table `[experiment.search]`. A new experiment must ship to live before it can start.

1. The agent makes a change on a branch, commits it, and pushes it.

   ```shell
   git switch -c faster-search
   git commit -am "Cache search results for 60 seconds"
   git push -u origin faster-search
   ```

2. CI builds the commit and records it. The agent waits for the workflow.

   ```shell
   gh run watch --exit-status \
     "$(gh run list --commit "$(git rev-parse HEAD)" \
       --json databaseId --jq '.[0].databaseId')"
   ```

3. The agent finds the live commit. It is the first arm.

   ```shell
   ssp app show shop-prod --json
   ```

4. The agent sets the arms: the live commit `c0ffee1` and the change. Each arm gets 5%.

   ```shell
   ssp experiment update search --app shop-prod \
     --arm c0ffee1=0.05 \
     --arm "$(git rev-parse HEAD)=0.05" --json
   ```

5. The agent starts the experiment, with a note that says why. The command waits until the arms are ready, for 5 minutes at most.

   ```shell
   ssp experiment start search --app shop-prod \
     --note "cache search, expect p95 down" --json
   ```

6. The agent reads the evidence from time to time.

   <Planned />

   ```shell
   ssp experiment show search --app shop-prod --json
   ```

   The JSON has the same data as the text: `experiment`, `version`, `app`, `started_at`, `stopped_at`, `subjects`, `split`, `arms`, `lookup`, `override_links`, and `versions`. Each item of `arms` has `commit`, `subjects`, `latency_ms` (`p50`, `p95`, `p99`), and `events`. `events` has `requests_4xx`, `requests_5xx`, and each event of `statespace.toml`. Each event has an `estimate`, a fraction of the subjects, and `ci95`, its 95% interval `[low, high]`. The commit status `statespace/shop-prod/search` has the same headline.

7. The agent or a person decides, and stops the experiment.

   ```shell
   ssp experiment stop search --app shop-prod \
     --note "p95 412 and 455 ms, open a pull request"
   ```

## Rules for agents

- Read `split` first. When the split is off, do not trust the other numbers.
- Compare numbers of one version only. Each start begins a new version. `--version N` shows an earlier version.
- Read the intervals in `ci95`. When the intervals of two arms overlap, the data does not show a difference yet.
- Find the detail of an arm in the user's own data tools with the label in `lookup`. See [Find it in your own data tools](/guides/own-tools).
- Give shares as fractions, such as `0.05`.
- `update` changes only the arms that you name. To remove an arm, give it `=0`.
- Stop the experiment at once when `requests_5xx` goes up.
- Write a `--note` on each change. People read it in the dashboard and in `ssp experiment show`.
