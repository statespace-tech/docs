On a machine with Docker, you run live as you do now, such as with Docker Compose. `ssp proxy docker` runs next to it. It sends live traffic to your container, and runs each arm as a copy of that container with another image.

```text
                 ┌─► container shop      (live)
visitors ─► ssp ─┼─► checkout c0ffee1    (arm)
                 └─► checkout a1b2c3d    (arm)
```

## How it works

- Live is a container that you run, such as the container `shop` of a Compose service. `--live-container` names it. The proxy never runs, changes, or stops it.
- The live image is the image of that container.
- The proxy checks the container every 2 seconds. When you create the container again, such as with a new image, the proxy sends live traffic to the new container within seconds.
- The port of live is `--live-port`. Without it, the port is the only TCP port that the container exposes.
- For each arm, the proxy creates a copy of the live container with another image. The copy keeps the environment that live sets, its command and entry point when live sets them, its mounts, its limits, and its networks.
- The copy gets none of the labels, names, network aliases, published ports, or restart policy of live. It gets no variable that starts with `STATESPACE_`. Thus Compose does not count the arms as its own.
- The proxy labels the arms `statespace.com/app`, `statespace.com/experiment`, and `statespace.com/commit`. After a crash, a new proxy adopts them.
- An arm is ready when it accepts a TCP connection, or when it answers `--health` with a 2xx status.
- When an experiment stops, the proxy removes the containers of its arms. When the proxy stops, it removes all its arms.

The proxy uses the Docker Engine API. It finds Docker at `DOCKER_HOST` (`unix://`, or `tcp://` without TLS), or at `/var/run/docker.sock`. It needs no `docker` command, so it runs in the `ssp` image.

## Prerequisites

- A Linux machine with Docker and Docker Compose.
- An app, such as `shop-dev`. See [Apps](/concepts/apps).
- A recorded build of the image that live runs.
- An app image that exposes one TCP port, such as `EXPOSE 3000`. Otherwise, add `--live-port`.

## Run the proxy with Compose

<Steps>
  <Step title="Add a runtime token">
    In your terminal, add a token for the app.

    ```shell
    ssp token add --app shop-dev --note "Docker proxy"
    ```

    On the machine, put the secret in `.env`, next to `compose.yaml`. Let only you read it.

    ```shell .env
    STATESPACE_TOKEN=<secret>
    ```
  </Step>

  <Step title="Add the proxy to compose.yaml">
    Give the container of your app a fixed name, such as `shop`. Add the service `ssp`, and move port 80 from `shop` to `ssp`.

    ```yaml compose.yaml
    services:
      shop:
        image: ghcr.io/acme/shop@sha256:<digest>
        # ssp finds live by this name.
        container_name: shop
        env_file: shop.env
        restart: unless-stopped
        # For debugging only. Visitors go through ssp.
        ports:
          - "127.0.0.1:3000:3000"

      ssp:
        image: ghcr.io/statespace-tech/statespace:0.4.3
        command:
          - proxy
          - docker
          - --live-container
          - shop
          - --health
          - /health
        environment:
          STATESPACE_TOKEN: ${STATESPACE_TOKEN}
        ports:
          - "80:8080"
        volumes:
          # ssp starts and stops the arms with the socket.
          - /var/run/docker.sock:/var/run/docker.sock
        # The Docker socket belongs to root.
        user: root
        depends_on:
          - shop
        restart: unless-stopped
        # ssp lets requests finish and removes the arms.
        stop_grace_period: 30s
    ```

    Compose puts both services on one network. The proxy sends traffic to `shop` on that network.
  </Step>

  <Step title="Start the project">
    Start the project.

    ```shell
    docker compose up -d
    ```
  </Step>

  <Step title="Check the app">
    In your terminal, show the app. It shows live, the proxy instance, and the orchestrator `docker`.

    ```shell
    ssp app show shop-dev
    ```
  </Step>
</Steps>

### The Docker socket

<Warning>
  The Docker socket gives `ssp` control of Docker on this machine. A process that can use the socket can start any container, and thus can get root access to the machine. Mount the socket only in the `ssp` service.
</Warning>

The proxy needs the socket for these tasks:

1. It reads the live container and follows it.
2. It pulls the images of the arms.
3. It creates, starts, stops, and removes the containers of the arms.

### Port of the app

Publish the port of `shop` only on `127.0.0.1`, as in the example. Then you can send requests to live from the machine for debugging, and visitors cannot go around the proxy. Visitors that go around the proxy are never in an arm.

### An existing reverse proxy

When a reverse proxy, such as nginx or Caddy, already listens on port 80, keep it. Do not publish a port of `ssp`. Change the upstream of the reverse proxy from `shop:3000` to `ssp:8080`.

The reverse proxy can also send traffic to `shop:3000` when `ssp` is down. See [Fall back to live](/guides/fall-back-to-live).

### Private images

The proxy pulls the images of the arms with the credentials in `auths` of `$DOCKER_CONFIG/config.json`. The default is `~/.docker/config.json`. It does not read credential helpers.

## Deploy a new live

Change the image of `shop` in `compose.yaml`, and start the project again. Compose creates the container `shop` again. The proxy sends live traffic to the new container within seconds.

```shell
docker compose up -d
```

The arms are fixed commits. So a new live does not change a running experiment, unless its `statespace.toml` changes the experiment. See [What a release does](/concepts/experiments#what-a-release-does).

The arms have no Compose labels. Thus `docker compose up --remove-orphans` and `docker compose down` do not remove them. See [Infrastructure as code](/guides/infrastructure-as-code).

## Run the proxy on the machine

You can also run the `ssp` binary on the machine, outside a container. Then live must publish its port. The proxy sends live traffic to that port. The arms publish their port on `127.0.0.1`.

```shell
STATESPACE_TOKEN=<secret> ssp proxy docker \
  --live-container shop --health /health
```

The user of the proxy must be able to use the Docker socket.

## Size the machine

The machine runs live and one container for each arm of each running experiment. Size the machine for that many copies of the app, or keep few arms.
