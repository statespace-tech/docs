A CDN can sit in front of `ssp proxy` on any runtime. The CDN keeps static files. The proxy picks the arm of each page request.

## Rules for any CDN

- **Use the proxy as the origin**, such as the load balancer in front of the proxy. A request that does not go through the proxy is never in an arm.
- **Do not cache pages.** One URL gives different pages to different subjects. The proxy marks arm responses `Cache-Control: private, no-cache`.
- **Send the cookies `ssp_sid` and `ssp`, and the query parameter `ssp`.** The proxy reads the subject from `ssp_sid` and [overrides](/concepts/overrides) from `ssp`.
- **Send the headers that `subject` and `eligibility` read.**
- **Cache hashed static files**, such as `/assets/app.3f9a1c.js`. A file with a hash of its content in its name is the same in each build.
- **Make redirects in the CDN.** The proxy makes no redirects.

<Warning>
  Do not cache a file without a hash in its name, such as `/favicon.ico`. A visitor can then get the file of another arm or of live.
</Warning>

## CloudFront

<Steps>
  <Step title="Add the origin">
    Add an origin with the DNS name of the load balancer of the proxy.
  </Step>
  <Step title="Send pages to the proxy">
    In the default cache behavior (`*`), set the managed cache policy `CachingDisabled` and the origin request policy `AllViewer`.

    When `eligibility` reads a CloudFront header, such as `cloudfront-viewer-country`, use `AllViewerAndCloudFrontHeaders-2022-06`.
  </Step>
  <Step title="Cache hashed static files">
    Add a cache behavior for the folder of the hashed files, such as `/assets/*`, with the managed cache policy `CachingOptimized`.
  </Step>
</Steps>

Do not use `CachingOptimized` for pages. Its minimum TTL is 1 second, so CloudFront keeps each page for 1 second, also with `no-cache`.

## Cloudflare

<Steps>
  <Step title="Point the domain to the proxy">
    Add a `CNAME` from `shop.acme.com` to the load balancer of the proxy. Turn on the proxy status.
  </Step>
  <Step title="Set the encryption mode">
    Set SSL/TLS to **Full (strict)**.
  </Step>
  <Step title="Cache hashed static files">
    Add a cache rule for the folder of the hashed files, such as a URI path that starts with `/assets/`. Set it to **Eligible for cache**.
  </Step>
  <Step title="Bypass the cache for shared names">
    Cloudflare caches `/favicon.ico` and `/robots.txt` by default. Add a cache rule for them with **Bypass cache**.
  </Step>
</Steps>

Do not add a rule that makes pages **Eligible for cache**. To get `cf-ipcountry` for `eligibility`, turn on the Managed Transform **Add visitor location headers**.

## Fall back to live

Live keeps its own address. So the CDN or load balancer in front of the proxy can send traffic to live when the proxy is down. Without a fallback, run two or more instances of the proxy to keep your app up during a restart.

During a fallback, all visitors get live, and the proxy counts nothing. When the proxy is back, each subject gets the same arm as before.

Point the fallback to the address of live, such as the live container or Service. On Amazon S3 and Google Cloud Storage, use an origin that serves the root of the bucket. It does not use the path rules of the proxy.

<Tabs>
  <Tab title="nginx">
    nginx uses `shop`, the backup server, only when it cannot use `ssp`:

    ```nginx nginx.conf
    upstream shop_front {
        server ssp:8080;
        server shop:3000 backup;
    }

    server {
        listen 80;
        location / {
            proxy_pass http://shop_front;
            proxy_set_header Host $host;
            proxy_connect_timeout 2s;
            proxy_next_upstream error timeout
                http_502 http_503;
        }
    }
    ```

    The proxy answers 503 while it does not know the address of live.
  </Tab>
  <Tab title="Caddy">
    Caddy sends each request to the first available upstream:

    ```text Caddyfile
    shop.acme.com {
        reverse_proxy ssp:8080 shop:3000 {
            lb_policy first
            lb_try_duration 5s
            fail_duration 30s
        }
    }
    ```
  </Tab>
  <Tab title="Traefik">
    Traefik uses `live` when the health check of `ssp` fails:

    ```yaml dynamic.yaml
    http:
      services:
        shop-front:
          failover:
            service: ssp
            fallback: live
        ssp:
          loadBalancer:
            healthCheck:
              path: /health
              interval: 5s
            servers:
              - url: http://ssp:8080
        live:
          loadBalancer:
            servers:
              - url: http://shop:3000
    ```
  </Tab>
  <Tab title="Cloudflare">
    In Cloudflare Load Balancing:

    1. Add a pool for the proxy, with a health monitor.
    2. Add a pool for live.
    3. In the load balancer, use the pool of the proxy, and set the pool of live as the fallback pool.
  </Tab>
  <Tab title="CloudFront">
    1. Add two origins: the proxy and live.
    2. Make an origin group. The primary origin is the proxy. The secondary origin is live.
    3. Choose the failover status codes 500, 502, 503, and 504.
    4. Set the origin group as the origin of the default cache behavior.

    CloudFront fails over only for `GET`, `HEAD`, and `OPTIONS`.
  </Tab>
</Tabs>

A fallback on status codes also sends to live the requests that an arm answers with those codes.
