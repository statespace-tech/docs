A CDN can sit in front of `ssp proxy` on any runtime. The CDN keeps static files near your visitors. The proxy picks the arm of each page request. A request goes through these parts:

1. The CDN gets the request from the visitor.
2. The CDN sends it to the load balancer of the proxy.
3. The proxy sends it to an arm or to live.

## Rules for any CDN

### Send pages to the proxy

One URL gives different pages to different subjects. So the CDN must send each page request to the proxy, and must not keep a copy of a page for other visitors.

- Do not cache pages in the CDN.
- Send cookies to the proxy, at least `ssp_sid` and `ssp`. The proxy reads the subject from `ssp_sid`, and overrides from `ssp`.
- Send the query parameter `ssp` to the proxy. It opens an [override](/concepts/overrides).
- Send the headers that `subject` and `eligibility` read, such as `x-user-id`.

The proxy marks arm responses `Cache-Control: private, no-cache`. A CDN that obeys `Cache-Control` keeps no copy of them.

### Cache hashed static files

A file with a hash of its content in its name, such as `/assets/app.3f9a1c.js`, is the same in each build that has it. So a cached copy is correct for every arm and for live. Keep these files in the CDN cache, such as for one year.

<Warning>
  Do not cache a file without a hash in its name that two builds can have with different content, such as `/favicon.ico` or `/robots.txt`. A visitor can then get the file of another arm or of live. Send such files to the proxy without caching, or give them hashed names.
</Warning>

### Use the proxy as the origin

The origin of the CDN is the address of the proxy, such as:

- the Application Load Balancer in front of the proxy on ECS Fargate;
- the URL of the proxy's Cloud Run service;
- the load balancer of the proxy's Kubernetes Service.

Do not use the bucket or the live service as the origin. Requests that do not go through the proxy are never in an arm. Use live only as a [fallback](/guides/fall-back-to-live).

### Redirects

The proxy makes no redirects. Make them in the CDN, such as with Cloudflare Redirect Rules or CloudFront Functions.

## CloudFront

<Steps>
  <Step title="Add the origin">
    In the distribution, add an origin with the domain of the proxy, such as the DNS name of the load balancer. Use HTTPS when the load balancer has a certificate.
  </Step>

  <Step title="Send pages to the proxy">
    In the default cache behavior (`*`), set these managed policies:

    1. The cache policy `CachingDisabled`. Its TTLs are 0, so CloudFront keeps no page.
    2. The origin request policy `AllViewer`. It sends all headers, cookies, and query strings to the proxy.

    When the origin needs its own host name in the `Host` header, use `AllViewerExceptHostHeader`. CloudFront then sends the domain of the origin as `Host`.

    Do not use `CachingOptimized` for pages. Its minimum TTL is 1 second, so CloudFront keeps a page for at least 1 second, also with `private` or `no-cache`.
  </Step>

  <Step title="Cache hashed static files">
    Add a cache behavior for the folder of the hashed files, such as `/assets/*`. Set the managed cache policy `CachingOptimized`. Its default TTL is 24 hours, and its maximum TTL is 365 days.
  </Step>

  <Step title="Send viewer headers that the rules read">
    When `eligibility` reads a CloudFront header, such as `cloudfront-viewer-country`, use the managed origin request policy `AllViewerAndCloudFrontHeaders-2022-06` in the default behavior. It sends all viewer values and the CloudFront headers, such as `CloudFront-Viewer-Country`.
  </Step>
</Steps>

## Cloudflare

<Steps>
  <Step title="Point the domain to the proxy">
    Add a DNS record for your domain, such as a `CNAME` from `site.acme.com` to the DNS name of the load balancer. Turn on the proxy status (orange cloud).
  </Step>

  <Step title="Set the encryption mode">
    Set the SSL/TLS encryption mode to **Full (strict)**. The certificate of the origin must be valid, from a public certificate authority or from Cloudflare's Origin CA, and must match the host name.
  </Step>

  <Step title="Keep pages out of the cache">
    By default, Cloudflare does not cache HTML or JSON. It also does not cache a response with `private`, `no-store`, `no-cache`, or `max-age=0`. Do not add a cache rule that makes pages **Eligible for cache**.
  </Step>

  <Step title="Cache hashed static files">
    Add a cache rule for the folder of the hashed files, such as when the URI path starts with `/assets/`. Set the cache eligibility to **Eligible for cache**.
  </Step>

  <Step title="Bypass the cache for shared names">
    By default, Cloudflare caches some files without a hash in their names, such as `/favicon.ico` and `/robots.txt`. Add a cache rule for these files. Set the cache eligibility to **Bypass cache**.
  </Step>
</Steps>

Cloudflare sends all request headers to the origin, with the cookies. To get the header `cf-ipcountry` for `eligibility`, turn on the Managed Transform **Add visitor location headers**.

## Fall back to live

This part is optional. The CDN can send requests to live when the proxy is down, such as with a CloudFront origin group or a Cloudflare fallback pool. See [Fall back to live](/guides/fall-back-to-live).
