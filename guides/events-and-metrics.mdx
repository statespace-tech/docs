This guide shows how to write events and metrics in `statespace.toml`. Your app needs no code change. See [Events and metrics](/concepts/events-and-metrics) for the model.

## Steps

1. Choose what to count: a request, or a line that the app prints.
2. Choose where the count applies. Write a shared `[[event]]` for every experiment, or an own `[[experiment.<name>.event]]` for one experiment.
3. Write a `[[metric]]` for each number that you want to compare. Put the most important metric first.
4. Push the commit. CI checks every expression when it records the build.
5. The change applies when the commit runs as live.

<Warning>
  A release that changes a shared event stops every running experiment of the app. A release that changes an own event stops its experiment. A change of a metric stops nothing. See [What a release does](/concepts/experiments#what-a-release-does).
</Warning>

## Count requests

A request event can use `method`, `path`, `query`, `headers`, `cookies`, `status`, and `ms`. Request events also count subjects, so use them for rates per visitor.

```toml statespace.toml
# A visitor signs up.
[[event]]
name = "signup"
match = '''
request.method == "POST"
  && request.path == "/signup"
  && request.status < 300
'''

# A visitor sends an order.
[[event]]
name = "purchase"
match = '''
request.method == "POST"
  && request.path == "/checkout"
  && request.status < 300
'''

# A page takes more than one second.
[[event]]
name = "slow"
match = 'request.ms > 1000'

# A visitor opens the shop from the mobile app.
[[event]]
name = "mobile"
match = 'request.headers["x-client"] == "mobile"'
```

Statespace can match headers and cookies, but it never stores them.

## Count output lines

An output event uses `stdout` or `stderr`, with `text` and `json`. `json` is the line as an object, or `{}` when the line is not a JSON object.

```toml statespace.toml
# The app prints {"event": "payment_failed", ...}.
[[event]]
name = "payment_failed"
match = 'stdout.json.event == "payment_failed"'

# The app prints a fatal error.
[[event]]
name = "fatal"
match = 'stderr.text.contains("FATAL")'
```

Output lines have no subject. So an output event has `.lines`, and no `.subjects`.

## Write metrics

A metric uses the totals of one arm. Statespace computes it for each arm of the experiment.

```toml statespace.toml
# The headline: the share of visitors who order.
[[metric]]
label = "purchase rate %"
value = '100.0 * events["purchase"].subjects / subjects'

[[metric]]
label = "signup rate %"
value = '100.0 * events["signup"].subjects / subjects'

[[metric]]
label = "slow requests %"
value = '100.0 * events["slow"].lines / requests'

[[metric]]
label = "failed payments per 1k requests"
value = '1000.0 * events["payment_failed"].lines / requests'

[[metric]]
label = "p90 ms"
value = 'p90_ms'
```

Errors and latency always show in the evidence. You do not need a metric for them.

## Count for one experiment

An own event or metric applies only to its experiment. Use it for a measure that only one experiment needs. The first own metric is the headline of the experiment.

```toml statespace.toml
[experiment.checkout]
max_traffic = 0.2

# Only the arms of checkout count coupons.
[[experiment.checkout.event]]
name = "coupon"
match = '''
request.method == "POST"
  && request.path == "/checkout/coupon"
'''

# The headline of checkout.
[[experiment.checkout.metric]]
label = "coupon use %"
value = '100.0 * events["coupon"].subjects / subjects'
```

## Count for one app

Events and metrics in a section `[app.<name>]` are added after the shared ones, for that app only.

```toml statespace.toml
[[app.shop-prod.event]]
name = "refund"
match = '''
request.path == "/refund"
  && request.status < 300
'''
```

## Rules

- Each event uses exactly one source. An expression with no source, or with two sources, fails in CI.
- The same event name or metric label two times fails in CI.
- A missing field is no match. It is not an error.
- An event without rows is `0`. All numbers are decimals.
- A metric that uses `.subjects` of an output event fails in CI.
- A metric that uses an event that does not exist fails in CI.
- An arm with no subjects shows `–`.
