title: Permissions
description: How roles on GitHub decide what each person, workflow, and agent can do in Statespace.

Who can add arms, stop them, and run a proxy?

Each app is linked to a repo. Your role on that repo on GitHub decides what you can do with the app. There are no Statespace roles to manage.

## Levels

| Level | Allows | GitHub role |
| --- | --- | --- |
| `read` | See apps, arms, and evidence | Read |
| `write` | Stop and resume. Add and remove arms when `arm_role = "write"` | Write. Triage can stop and resume only |
| `maintain` | Add and remove arms when `arm_role = "maintain"` | Maintain |
| `admin` | Add and remove apps and runtime tokens | Admin |

`arm_role` in `statespace.toml` sets the level that adds and removes arms of the app. The default is `write`.

```toml statespace.toml
[app.shop-prod]
arm_role = "maintain"
```

Statespace keeps roles for 10 minutes. So stop and resume work while GitHub is down.

## Credentials

People and agents use the GitHub credential that they have.

| Credential | Who uses it |
| --- | --- |
| A session from `ssp login` | People and agents in a terminal |
| The OIDC token of a GitHub Actions job | Workflows of the app's repo. It counts as `write` |
| A GitHub user token: `gho_`, `ghp_`, `ghu_`, or `github_pat_` | Agents and scripts. Statespace asks GitHub who it is, and its role on the repo |

## Runtime tokens

A runtime token is the only kind of Statespace token. Each token is for one app. The proxy uses it.

```shell
ssp token add --app shop-prod --note "Cloud Run proxy"
```

A runtime token can:

- read the runtime configuration of its app;
- report, and hold the lease;
- send events.

It cannot add, remove, stop, or resume arms. It cannot read evidence.

<Warning>
  The CLI shows the secret of a token only one time. Keep it in a secret manager, and keep it out of logs.
</Warning>
