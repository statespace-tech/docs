An [outcome measure](https://en.wikipedia.org/wiki/Outcome_measure) assesses the effect of an intervention or treatment. Statespace stores raw outcomes and lets SQL define metrics.

```text
assignment → exposure → raw outcome → metric
```

## Treatment exposure

An assignment records which variant a unit should receive. An exposure records that the unit received it.

`ssp host` records a run the first time it routes a subject, when it serves the request. A run with `reason = 'assigned'` is an exposure. A run with `reason = 'variant-unavailable'` was assigned a variant but served by control. Count both in the assigned variant, so a variant that fails for some subjects cannot hide them.

This distinction affects whether the [estimand](/concepts/statistical-inference#estimands) measures assignment or actual exposure.

## Raw outcomes

An outcome records a named JSON response for a subject. Any process of the app can print it, in control or in a variant.

```python
print(json.dumps({"statespace": "click", "subject": subject, "position": 3}))
```

`statespace` names the outcome and `subject` identifies the subject. Every other field becomes the outcome's `data`. The subject of the current request is the `x-statespace-subject` header. Use the same name, meaning, and unit in every variant.

## Outcome metrics

A metric is a rule that summarizes raw outcomes. Choose important metrics before you inspect the variant comparison.

| Metric | Purpose |
| --- | --- |
| Primary | Answers the main experiment question. |
| Secondary | Measures another expected effect. |
| Diagnostic | Explains why another metric changed. |
| Data quality | Detects missing or invalid instrumentation. |

Statespace does not require metric definitions in the experiment definition. This keeps the raw evidence available for new SQL analyses.

## Outcome attribution

Attribution connects an outcome to the run whose treatment could have caused it. It is an experiment join rule, not marketing attribution.

An app's `logs` view joins each outcome to the latest run of the same subject in the app that started at or before it. A subject is in at most one experiment of an app at a time, so an outcome needs no experiment name. Results count an outcome for the variant of the subject's first run in the analyzed version, until the subject's next run in another experiment, and ignore outcomes that came before it. Define a narrower attribution window in SQL when a response can occur long after exposure.

## Repeated observations

One randomization unit can produce many runs and outcomes. These observations are related because they come from the same assigned unit.

```text
user_42
├── click → position: 1
├── click → position: 4
└── click → position: 2
```

Aggregate repeated observations at the randomization-unit level before a simple independent-unit analysis.

```sql
WITH unit_outcomes AS (
  SELECT
    subject_id,
    variant,
    avg((data->>'position')::double precision) AS unit_position
  FROM atlas.logs
  WHERE experiment = 'rank-v2'
    AND experiment_version = 1 AND reason IN ('assigned', 'variant-unavailable') AND outcome_name = 'click'
  GROUP BY subject_id, variant
)
SELECT
  variant,
  count(*) AS units,
  avg(unit_position) AS mean_position
FROM unit_outcomes
GROUP BY variant;
```

<Warning>
  Counting every run as an independent unit can understate uncertainty. Match the analysis unit to the [stable identity](/concepts/random-assignment#stable-identity), or use a method that accounts for clustering.
</Warning>

## Guardrail metrics

A guardrail metric detects unacceptable harm outside the primary objective. Common guardrails include latency, error rate, safety violations, and user abandonment.

`ssp host` records some guardrails for every process without code: per-minute request counts, error rates, and latency percentiles, and CPU and memory use.

```sql
SELECT variant, timestamp, data->>'p90_ms' AS p90_ms, data->>'errors' AS errors
FROM atlas.metrics
WHERE kind = 'http'
ORDER BY timestamp DESC;
```

Print other guardrails as outcomes in control and every variant.

```python
print(json.dumps({"statespace": "performance", "subject": subject, "latency_ms": 42}))
```

## Structured outcomes

An outcome can contain any JSON-compatible result. This supports conversations, traces, evaluations, and other semi-structured evidence.

```python
print(json.dumps({
    "statespace": "conversation",
    "subject": subject,
    "tool_calls": 3,
    "termination": "completed",
}))
```

Each outcome line must be smaller than 60 KiB. Store large artifacts elsewhere and record a durable reference.
