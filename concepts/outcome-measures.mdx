---
title: Outcome measures
description: What Statespace records as evidence, and how raw lines become metrics in SQL.
---

How does an experiment measure change? An [outcome measure](https://en.wikipedia.org/wiki/Outcome_measure) assesses the effect of a treatment. Statespace records what each subject was assigned and what the arms print. You define metrics over that evidence in SQL.

## Treatment exposure

An assignment records which arm a subject should get. An exposure records that the subject got it.

`ssp proxy` records a run the first time that it routes a subject. A run with `reason = 'assigned'` is an exposure. A run with `reason = 'arm-unavailable'` was assigned an arm, but the default served it. Count both in the assigned arm, so an arm that fails for some subjects cannot hide them.

This difference decides whether the [estimand](/concepts/statistical-inference#estimands) measures assignment or exposure.

## Raw outcomes

Each line that an arm prints is a raw outcome. A JSON line keeps its fields as `data`, and its `subject` field ties it to that subject's arm.

```python
print(json.dumps({
    "event": "click",
    "subject": subject,
    "position": 3,
}))
```

The proxy sends the subject from your rule in the `x-statespace-subject` header, so each arm uses the subject that the proxy assigned. Use the same event names, meanings, and units in the default and in every arm.

A line without a subject still belongs to the arm that printed it. Such lines serve rates per request, such as errors.

## Outcome metrics

A metric is a rule that summarizes raw outcomes. Choose the important metrics before you look at the comparison.

| Metric | Purpose |
| --- | --- |
| Primary | Answers the main question of the experiment |
| Secondary | Measures another expected effect |
| Diagnostic | Explains why another metric changed |
| Data quality | Finds missing or incorrect instrumentation |

Statespace does not store metric definitions. The raw evidence stays available for new analyses.

## Outcome attribution

Attribution connects an outcome to the run whose treatment could have caused it.

An app's `logs` view joins each line that has a subject to a run of that subject. It uses the latest run that started at or before the line. A subject is in at most one experiment of an app at a time, so a line needs no experiment name. Lines from before the subject's first run have no attribution. When a response can occur long after exposure, define a narrower window in SQL.

## Repeated observations

One subject can give many runs and lines. These observations are related, because they come from the same assigned unit.

```text
user_42
├── click → position: 1
├── click → position: 4
└── click → position: 2
```

Aggregate repeated observations for each subject before an analysis that assumes independent units.

```sql
WITH unit_outcomes AS (
  SELECT
    subject_id,
    arm,
    avg((data->>'position')::float) AS unit_position
  FROM atlas.logs
  WHERE experiment = 'ranking'
    AND experiment_version = 1
    AND reason IN ('assigned', 'arm-unavailable')
    AND data->>'event' = 'click'
  GROUP BY subject_id, arm
)
SELECT
  arm,
  count(*) AS units,
  avg(unit_position) AS mean_position
FROM unit_outcomes
GROUP BY arm;
```

<Warning>
  If you count each run as an independent unit, the uncertainty looks smaller than it is. Match the unit of analysis to the [stable identity](/concepts/random-assignment#stable-identity), or use a method for clustered data.
</Warning>

## Guardrail metrics

A guardrail metric finds harm outside the primary objective, such as latency, errors, safety violations, or abandonment.

`ssp proxy` records some guardrails for every arm, with no code. It records the status and latency of each request, and CPU and memory for each minute.

```sql
SELECT arm,
       avg((status >= 500)::int) AS error_rate,
       percentile_cont(0.9)
         WITHIN GROUP (ORDER BY duration_ms) AS p90_ms
FROM atlas.requests
WHERE experiment = 'ranking'
GROUP BY arm;
```

Print other guardrails as lines, in the default and in every arm.

```python
print(json.dumps({
    "event": "performance",
    "subject": subject,
    "latency_ms": 42,
}))
```

## Structured outcomes

A line can hold any JSON object, so it can record conversations, traces, evaluations, and other structured evidence.

```python
print(json.dumps({
    "event": "conversation",
    "subject": subject,
    "tool_calls": 3,
    "termination": "completed",
}))
```

Statespace cuts lines longer than 16 KiB. Store large artifacts elsewhere, and print a reference to them.
