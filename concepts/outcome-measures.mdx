title: Outcome measures
description: Record responses and define how an experiment measures change.
---

An [outcome measure](https://en.wikipedia.org/wiki/Outcome_measure) assesses the effect of an intervention or treatment. Statespace records every line the arms print and lets SQL define metrics.

```text
assignment → exposure → raw outcome → metric
```

## Treatment exposure

An assignment records which variant a unit should receive. An exposure records that the unit received it.

`ssp proxy` records a run the first time it routes a subject, when it serves the request. A run with `reason = 'assigned'` is an exposure. A run with `reason = 'variant-unavailable'` was assigned an arm but served by the default. Count both in the assigned arm, so an arm that fails for some subjects cannot hide them.

This distinction affects whether the [estimand](/concepts/statistical-inference#estimands) measures assignment or actual exposure.

## Raw outcomes

Every line an arm prints is a raw outcome. A JSON line keeps its fields as `data`, and its `subject` field ties it to that subject's arm.

```python
print(json.dumps({"event": "click", "subject": subject, "position": 3}))
```

The subject of the current request is the `x-statespace-subject` header. Use the same event names, meaning, and units in the default and every variant. A line without a subject still belongs to the arm that printed it, which serves rates such as errors per request.

## Outcome metrics

A metric is a rule that summarizes raw outcomes. Choose important metrics before you inspect the variant comparison.

| Metric | Purpose |
| --- | --- |
| Primary | Answers the main experiment question. |
| Secondary | Measures another expected effect. |
| Diagnostic | Explains why another metric changed. |
| Data quality | Detects missing or invalid instrumentation. |

Statespace does not require metric definitions in the experiment definition. This keeps the raw evidence available for new SQL analyses.

## Outcome attribution

Attribution connects an outcome to the run whose treatment could have caused it. It is an experiment join rule, not marketing attribution.

An app's `logs` view joins each line with a subject to the latest run of the same subject in the app that started at or before it. A subject is in at most one experiment of an app at a time, so a line needs no experiment name. Lines that came before the subject's first run are not attributed. Define a narrower attribution window in SQL when a response can occur long after exposure.

## Repeated observations

One randomization unit can produce many runs and lines. These observations are related because they come from the same assigned unit.

```text
user_42
├── click → position: 1
├── click → position: 4
└── click → position: 2
```

Aggregate repeated observations at the randomization-unit level before a simple independent-unit analysis.

```sql
WITH unit_outcomes AS (
  SELECT
    subject_id,
    variant,
    avg((data->>'position')::double precision) AS unit_position
  FROM atlas.logs
  WHERE experiment = 'rank-v2'
    AND experiment_version = 1 AND reason IN ('assigned', 'variant-unavailable') AND data->>'event' = 'click'
  GROUP BY subject_id, variant
)
SELECT
  variant,
  count(*) AS units,
  avg(unit_position) AS mean_position
FROM unit_outcomes
GROUP BY variant;
```

<Warning>
  Counting every run as an independent unit can understate uncertainty. Match the analysis unit to the [stable identity](/concepts/random-assignment#stable-identity), or use a method that accounts for clustering.
</Warning>

## Guardrail metrics

A guardrail metric detects unacceptable harm outside the primary objective. Common guardrails include latency, error rate, safety violations, and user abandonment.

`ssp proxy` records some guardrails for every arm without code: each request's status and latency, and per-minute CPU and memory use.

```sql
SELECT variant,
       avg((status >= 500)::int) AS error_rate,
       percentile_cont(0.9) WITHIN GROUP (ORDER BY duration_ms) AS p90_ms
FROM atlas.requests
WHERE experiment = 'rank-v2'
GROUP BY variant;
```

Print other guardrails as lines in the default and every variant.

```python
print(json.dumps({"event": "performance", "subject": subject, "latency_ms": 42}))
```

## Structured outcomes

A line can contain any JSON object. This supports conversations, traces, evaluations, and other semi-structured evidence.

```python
print(json.dumps({
    "event": "conversation",
    "subject": subject,
    "tool_calls": 3,
    "termination": "completed",
}))
```

Lines longer than 16 KiB are cut. Store large artifacts elsewhere and print a durable reference.
