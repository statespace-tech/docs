title: Outcome measures
description: Record responses and define how an experiment measures change.
---

An [outcome measure](https://en.wikipedia.org/wiki/Outcome_measure) assesses the effect of an intervention or treatment. Statespace stores raw outcomes and lets SQL define metrics.

```text
assignment → exposure → raw outcome → metric
```

## Treatment exposure

An assignment records which group a unit should receive. An exposure records that the application used the assigned configuration.

Calling `assign()` records an assignment. Call it at the point where the application applies the behavior.

```python
group = experiment.assign("u_42")
result = group.function("ranker", rerank)([3, 1, 2])
```

Assignment is not proof of exposure. Avoid assigning subjects on code paths that do not use the group's parameters. If exposure can differ from assignment, record that fact as an outcome and state which effect the analysis estimates.

This distinction affects whether the [estimand](/concepts/statistical-inference#estimands) measures assignment or actual exposure.

## Raw outcomes

An outcome records a named JSON response for a subject. Any process can log it.

```python
experiment.log("u_42", "relevance", {"score": 0.7})
```

Use the same name, meaning, and unit for every treatment group.

## Outcome metrics

A metric is a rule that summarizes raw outcomes. Choose important metrics before you inspect the group comparison.

| Metric | Purpose |
| --- | --- |
| Primary | Answers the main experiment question. |
| Secondary | Measures another expected effect. |
| Diagnostic | Explains why another metric changed. |
| Data quality | Detects missing or invalid instrumentation. |

Statespace does not require metric definitions in the experiment definition. This keeps the raw evidence available for new SQL analyses.

## Outcome attribution

Attribution connects an outcome to the run whose treatment could have caused it. It is an experiment join rule, not marketing attribution.

`statespace.logs` joins each outcome to the latest run of the same subject that started at or before it. Results count an outcome for the group of the subject's first run in the analyzed version, and ignore outcomes that came before it. Define a narrower attribution window in SQL when a response can occur long after exposure.

## Repeated observations

One randomization unit can produce many runs and outcomes. These observations are related because they come from the same assigned unit.

```text
user_42
├── run_1 → relevance: 0.81
├── run_2 → relevance: 0.76
└── run_3 → relevance: 0.88
```

Aggregate repeated observations at the randomization-unit level before a simple independent-unit analysis.

```sql
WITH unit_outcomes AS (
  SELECT
    subject_id,
    group_name,
    avg((data->>'score')::double precision) AS unit_relevance
  FROM statespace.logs
  WHERE experiment_name = 'rank-v2'
    AND experiment_version = 1 AND reason = 'assigned' AND outcome_name = 'relevance'
  GROUP BY subject_id, group_name
)
SELECT
  group_name,
  count(*) AS units,
  avg(unit_relevance) AS mean_relevance
FROM unit_outcomes
GROUP BY group_name;
```

<Warning>
  Counting every run as an independent unit can understate uncertainty. Match the analysis unit to the [stable identity](/concepts/random-assignment#stable-identity), or use a method that accounts for clustering.
</Warning>

## Guardrail metrics

A guardrail metric detects unacceptable harm outside the primary objective. Common guardrails include latency, error rate, safety violations, and user abandonment.

Record guardrail outcomes for control and every treatment group.

```python
experiment.log("u_42", "performance", {"latency_ms": 42, "error": False})
```

## Structured outcomes

An outcome can contain any JSON-compatible result. This supports conversations, traces, evaluations, and other semi-structured evidence.

```python
experiment.log("u_42", "conversation", {
    "messages": [{"role": "assistant", "content": "Search results ranked."}],
    "tool_calls": 3,
    "termination": "completed",
})
```

Store scalar and structured evidence in the same dictionary when needed. Store large binary artifacts elsewhere and record a durable reference.
