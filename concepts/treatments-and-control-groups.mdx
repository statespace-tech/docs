title: Treatments and control groups
description: Compare variants of an app with the version you deployed.
---

A treatment is the behavior being tested. A variant is a signed build of your app that defines one treatment. Control supplies the comparison baseline.

## Interventions, treatments, and variants

This example changes search ranking with the variant `atlas-search`.

```text
intervention: change search ranking
treatment:    atlas-search, a build of the new-ranking branch of atlas
control:      the version of atlas you deployed
```

A variant can change anything in your app: code, dependencies, or how it starts. Variants are versioned, and an experiment records which variant version each of its versions used.

## Control group

Control is the code you deployed. `ssp host` runs it from the directory it starts in, with the same command as every variant.

```shell
ssp host --app atlas --command "gunicorn -b 127.0.0.1:{port} atlas:app" --trust-key "$SSP_PUBLIC_KEY"
```

Control receives the weight not allocated to variants. It estimates what would happen without the tested change.

## Implicit control

Give half of the experiment's subjects to `atlas-search`.

```shell
ssp experiment create rank-v2 --app atlas --variant atlas-search=0.5
```

The other half belongs to control. Weights that total one leave no control group. Ineligible subjects also get control, but their runs are not randomized control and must not be counted as control.

## Variant weights

Weights must be greater than zero and total at most one.

```shell
ssp experiment update rank-v2 --variant atlas-search=0.25 --variant atlas-search-bm25=0.25
```

This split leaves 50% for control. Unequal weights change the sample size and statistical power of each comparison. See [Variant allocation](/concepts/random-assignment#variant-allocation) for stable assignment ranges.

## Shared state

A variant shares your database, cache, and queues with control. Keep a variant's changes inside the code that handles requests.

- Land schema changes in the deployed code first. Give variants a database user without schema permissions with `--variant-env`.
- Turn off schedulers and workers that run inside your web process in variants, so nothing runs twice.
- Prefix cache keys in variants, so control never serves a response a variant cached.

To test two changes and their interaction, build each combination as its own variant and analyze the full grid.
