---
title: Treatments and control groups
description: Compare published functions with an application default.
---

A treatment is the behavior being tested. A group contains subjects assigned to the same behavior. Control supplies the comparison baseline.

## Interventions, treatments, and groups

This example changes search ranking with the published function `atlas-search@1`.

```text
intervention: change search ranking
candidate:   atlas-search@1 sorts results
group:       subjects assigned to atlas-search@1
control:     the application's existing ranking behavior
```

The CLI uses `--variant` to select a published function and its traffic weight. Logged candidate group names include the resolved function version, such as `atlas-search@1`.

## Control group

The application supplies control with a default callable.

```python
rank = run.get_function("u_42", default=lambda items: items)
result = rank([3, 1, 2])
```

This baseline receives the traffic not allocated to candidate functions. It estimates what would happen without the tested change.

## Implicit control

Allocate 20% of eligible subjects to the published candidate.

```shell
ssp experiment create --name rank-v2 --variant atlas-search@1=0.2
```

The remaining 80% belongs to control. A total candidate weight of one leaves no control group. Ineligible subjects also use the default, but their runs are unassigned and must not be counted as randomized control.

## Group weights

Weights must be finite, positive, and total at most one. Publish both function versions before using this split.

```shell
ssp experiment create --name rank-v2   --variant atlas-search@1=0.2 --variant atlas-search@2=0.2
```

This split leaves 60% for control. Unequal weights change the sample size and statistical power of each comparison. See [Group allocation](/concepts/random-assignment#group-allocation) for stable assignment ranges.

## Treatment parameters

Put candidate computation in the published function. Its input and output are JSON-compatible values. The current function CLI does not accept arbitrary group configuration fields.

Keep each candidate focused on the factors needed to answer the experiment question. Factorial designs require a deliberate analysis plan; Statespace does not automatically infer one.
