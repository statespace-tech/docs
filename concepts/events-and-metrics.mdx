What does Statespace record, and how do you turn it into numbers?

## Raw sources

The proxy records the control and the arms. It never records live. Statespace keeps raw rows for 90 days.

| Source | One row for each | Holds |
| --- | --- | --- |
| `requests` | request | Subject, side, arm, version, method, path, query, status, time, time to first byte, sizes |
| `stdout` | line | Side, arm, version, text, and `json` when the line is a JSON object |
| `stderr` | line | The same as `stdout` |

- Each row belongs to the copy that served or printed it.
- Statespace never stores headers or bodies.
- `redact` replaces matches in output lines with `[redacted]` before the lines leave the machine.

## Events

An event is a named count. You define it in `statespace.toml` with a CEL expression. Each event uses exactly one source.

```toml statespace.toml
# A request event: one row for each matching request.
[[event]]
name = "checkout"
match = '''
request.method == "POST"
  && request.path == "/api/checkout"
  && request.status < 300
'''

# An output event: one row for each matching line.
[[event]]
name = "fatal"
match = 'stderr.text.contains("FATAL")'
```

- The proxy checks request events after the response. It checks output events as the lines come.
- A match adds one row to `events`: the name, the side, the arm, the version, the time, and the subject for request events.
- A missing field is no match. It is not an error.
- Output lines have no subject. So output events count lines only.

## Totals

Statespace adds up the rows for each app, arm, version, and side.

| Total | Means |
| --- | --- |
| `subjects` | Assigned subjects. Overrides do not count |
| `requests` | Requests |
| `errors` | Requests with a status from 500 to 599 |
| `p50_ms`, `p90_ms` | Latency |
| `events["checkout"].lines` | Rows of the event |
| `events["checkout"].subjects` | Subjects with a row of the event. Request events only |

## Metrics

A metric is a CEL formula over the totals of one side. Statespace computes each metric for the arm and for the control when it shows the evidence.

```toml statespace.toml
[[metric]]
label = "checkout rate %"
value = '100.0 * events["checkout"].subjects / subjects'
```

- The first metric is the headline. The commit status shows it.
- A side with no subjects shows `–`.

## The split check

Statespace checks that the arm and the control got subjects in the ratio of their shares. It uses a chi-square test, from 100 subjects. The result is `split OK` or, for example, `split off (p=0.003)`. When the split is off, do not trust the other numbers.
