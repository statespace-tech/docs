How do you look at an arm yourself, without the random split?

An override is a request that names its experiment and arm. Overrides are
always on: there is no setting.

## Get a link

The value is `<experiment>:<commit>`. The commit is the full commit, or its
first 7 characters or more.

```text
https://shop.acme.com/?ssp=checkout:a1b2c3d
```

Add `?ssp=<experiment>:<commit>` to any URL of the app. `ssp experiment
show` and the dashboard show the link of each arm of a running experiment.

## Open an arm

| Client | Send | The proxy |
| --- | --- | --- |
| Browser | `?ssp=<value>` on a URL | Sets the cookie `ssp`, and redirects a `GET` to the same URL without the parameter |
| API | The header `ssp: <value>` on each request | Uses the arm for that request |

- The cookie keeps the value. It lasts 1 hour, and each request renews it.
- An empty `?ssp=` ends the override.
- A link to an arm that does not run gets a short page, such as
  "checkout:a1b2c3d is not running on shop-prod. Running:
  checkout:c0ffee1, checkout:f6a7b8c".
- You cannot pick live.
- Your app never sees the `ssp` parameter, cookie, or header.

Overrides work on every runtime, and behind a CDN when the CDN sends the
`ssp` parameter and cookie to the proxy. See [Behind a CDN](/guides/cdn).

## Records

Statespace records override visits with the reason `override`. They count
fully for the experiment: subjects, events, and metrics. Only the split
check leaves them out.

<Warning>
  A person who knows the experiment and the commit can open the arm while
  the experiment runs. Do not put secrets in an arm that live does not have.
</Warning>
