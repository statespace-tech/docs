title: Overrides

How do you look at a running arm yourself, without the random split?

An override is a request that names its arm. The app must allow overrides in `statespace.toml`. The default is `false`.

```toml statespace.toml
[app.shop-dev]
overrides = true
```

## Open an arm

| Client | Send | The proxy |
| --- | --- | --- |
| Browser | `https://shop-dev.acme.com/?ssp_arm=a1b2c3d` | Sets the cookie `ssp_arm`, and redirects a `GET` to the same URL without the parameter |
| API | The header `ssp-arm: a1b2c3d` on each request | Uses the arm for that request |

- The value is the commit: the full commit, or its first 7 characters or more. It must match one running arm of the app.
- The cookie lasts 1 hour. Each request renews it.
- An empty `?ssp_arm=` ends the override.
- Another value gets a short page, such as "a1b2c3d is not running on shop-dev. Running arms: b2c3d4e, c3d4e5f".
- Only running arms. You cannot pick the control or live.
- Your app never sees `ssp_arm` or `ssp-arm`.

`ssp arm show` and **Details** on the commit status show the override link when the app allows overrides.

## Records

Statespace records override visits with the reason `override`. They do not count as subjects, and the split check ignores them.

<Warning>
  Anyone who can reach the proxy can open a running arm with an override. Turn on overrides only for apps that are not public, such as `shop-dev`.
</Warning>
