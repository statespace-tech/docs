This page answers: how do you look at an arm yourself, without the random split?

An override is a request that names its experiment and arm. Overrides are always on: there is no setting.

## The link

Add `?ssp=<experiment>:<commit>` to any URL of the app. The commit is the full commit, or its first 7 characters or more.

```text
https://shop.acme.com/?ssp=checkout:a1b2c3d
```

`ssp experiment show` and the dashboard show the link of each arm while the experiment runs. With `--json`, the links are in `override_links`.

## How the proxy uses it

| Client | Send | The proxy |
| --- | --- | --- |
| Browser | `?ssp=<value>` on a URL | Sets the cookie `ssp`, and redirects a `GET` to the same URL without the parameter |
| API | The header `ssp: <value>` on each request | Uses the arm for that request |

- The cookie `ssp` lasts 1 hour. Each request renews it.
- An empty `?ssp=` ends the override.
- A link to an arm that does not run gets a short page with the arms that run.
- You cannot pick live.
- Your app never sees the `ssp` parameter, cookie, or header.

Overrides work on every runtime. Behind a CDN, the CDN must send the `ssp` parameter and cookie to the proxy. See [Put a CDN in front](/guides/cdn).

## Results

Statespace never counts override visits. The proxy sends nothing about them: no subject, request, or event. An override never sets the cookie `ssp_arms`.

<Warning>
  A person who knows the experiment and the commit can open the arm while it runs. Do not put secrets in an arm that live does not have.
</Warning>
