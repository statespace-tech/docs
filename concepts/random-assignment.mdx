---
title: Random assignment
description: Keep subject assignments consistent across SDKs.
---

Random assignment gives each eligible subject one group. Each published experiment version records its groups and allocation ranges.

## Stable identity

Choose an identifier at the level where treatment can vary independently. Label user-level assignment when creating the experiment.

```shell
ssp experiment create rank-v2 --assignment user_id --group atlas-search=0.2
```

The label does not read a context field. Supply the identifier value explicitly to the SDK.

```python
group = experiment.assign("u_42")
```

## Stable bucket

All SDKs calculate the same bucket from the experiment salt and subject ID.

```text
bucket = first 53 bits of SHA-256(salt + ":" + subject_id) / 2^53
```

The same subject, salt, and allocation ranges produce the same group in Python, TypeScript, Go, and every service instance.

## Group allocation

Each group has explicit bucket ranges. The remaining interval belongs to control. For an experiment with one 20% group, the allocation is shown below.

```text
atlas-search: [0.0, 0.2)
control:      [0.2, 1.0)
```

## New versions

An experiment keeps one salt for its lifetime. Starting a changed draft keeps each group's existing ranges where its new weight permits. New or expanded groups use free ranges. Updating a group's parameters keeps its ranges, so its subjects stay in the group.

Weight changes can still move subjects between groups. Analyze each experiment version separately. Starting a new version stops assignments to the previous one.

## Forced assignment

Statespace does not force a subject into a group. Keep manual overrides out of a randomized comparison. A separate diagnostic path does not provide the same inference as random assignment.
