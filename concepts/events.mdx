What does the proxy count for the arms, and how do you tell it what to count?

<Planned />

## What the proxy counts

The proxy counts the subjects of the arms. For each request that an arm serves to an assigned subject, it adds to the counters of that subject:

| Counter | Adds |
| --- | --- |
| Requests | 1 |
| Errors | 1 when the response status is from 500 to 599 |
| Latency | 1 in the bucket of the time to the response headers |
| Each event | 1 when the rule of the event matches |

- The proxy never counts live.
- The proxy never counts overrides. See [Overrides](/concepts/overrides).
- A subject counts from their first request to an arm in a version.
- When the arm of a subject is not ready, the request goes to live. The subject counts for the [split check](#the-split-check) only.
- The proxy counts in memory, and never makes a request wait. It sends the counts to Statespace every 60 seconds.

See [What Statespace keeps](/concepts/data) for what leaves the proxy.

## Events

An event is a named count. You define it in `statespace.toml` with a CEL rule over one request and its response.

```toml statespace.toml
# A visitor signs up.
[[event]]
name = "signup"
match = '''
request.method == "POST"
  && request.path == "/signup"
  && response.status == 201
'''
```

A rule can use these fields:

| Field | Type | Example |
| --- | --- | --- |
| `request.method` | string | `"POST"` |
| `request.host` | string | `"shop.acme.com"` |
| `request.path` | string | `"/signup"` |
| `request.query` | map of strings | `{"ref": "mail"}` |
| `request.headers` | map of strings | `{"cf-ipcountry": "US"}` |
| `request.cookies` | map of strings | `{"plan": "pro"}` |
| `response.status` | number | `201` |
| `response.headers` | map of strings | `{"x-shop-event": "purchase"}` |
| `response.ms` | number | `84.0`, the time to the response headers |

- The proxy checks each rule one time for each request of an arm, when the response headers arrive.
- The proxy never reads a body. So streaming responses work as before.
- When the arm fails, the proxy answers the visitor itself, such as with a 502. The rule sees the status that the visitor got.
- Header names are lowercase.
- A missing field is no match. It is not an error.
- The proxy can match headers and cookies. It never sends or keeps them. Only the name of the event counts.

## Events that no request shows

Some events do not show in the request or the status, such as a payment that the app accepts after a check. Let your app name the event in a response header. Then match that header.

```toml statespace.toml
# The app sends x-shop-event: purchase
# when an order is paid.
[[event]]
name = "purchase"
match = '''
response.headers["x-shop-event"] == "purchase"
'''
```

## Shared and own

Events at the top of `statespace.toml` are **shared**. They apply to every experiment. An experiment can also have its **own** events. They apply only to it.

```toml statespace.toml
[experiment.checkout]

[[experiment.checkout.event]]
name = "coupon"
match = '''
request.method == "POST"
  && request.path == "/checkout/coupon"
'''
```

- The arms of `checkout` count the shared events and `coupon`. The arms of `us-landing` count only the shared events.
- Own events come after the shared ones.
- An event name is lowercase snake_case, such as `add_to_cart`. CI refuses `Add-To-Cart`.
- `requests_4xx` and `requests_5xx` are built-in events. Every experiment has them, and the results show them first. CI refuses them as names of your events.
- The same event name two times is an error in CI: `event "coupon" is defined twice`.
- The first event is the **headline**. It shows on the commit status. See [Evidence on the commit](/concepts/evidence#evidence-on-the-commit).

## The split check

Statespace checks that the arms got subjects in the ratio of their shares. It starts at 100 subjects in all arms. The result is `split ok`, or `split off` when the ratio is too far from the shares to come from chance (less than 1 time in 1,000).

The check uses the subjects that the hash assigned, also when their arm was not ready. It does not use overrides. The check is a warning only. When the split is off, do not trust the other numbers.
