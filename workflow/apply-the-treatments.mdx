---
title: Apply the treatments
description: Open a pull request, run the arm when it can merge, and record what the arms print.
---

Open a pull request when the outcome is deployed and the branch is pushed. In its description, state the hypothesis.

```shell
gh pr create --title "Rank results by recent clicks" \
  --body "Sorted results should get more clicks."
```

## What runs

GitHub decides whether the arm may run. The arm runs the latest commit while the pull request can merge: approved, with its required checks, and without conflicts.

| The pull request | The arm |
| --- | --- |
| Can merge | Runs the latest commit |
| Never could merge | Does not run |
| Could merge, and then could not | Runs the last commit that could merge, and warns after 7 days |
| Is a draft, or a reviewer requested changes | Stops |
| Merged | The experiment ends |
| Closed | The arm is removed |

The `statespace/arm` check on each commit tells what runs, and why the arm waits. It never fails, so it never blocks a merge. `statespace/apply` tells whether CI recorded the commit.

Statespace also checks that the comparison is fair:

- The arm's base, where the branch left the default branch, must have run as the default. Until a proxy runs it, the arm waits.
- Each base has its own control, which runs the default build of that base.
- The arms fit in the app's traffic limit, first come, first served.

## Run the proxy

Run the app behind `ssp proxy`. Give it a runtime token as `SSP_TOKEN`.

```shell
ssp proxy --app atlas --image ghcr.io/acme/atlas:main --health /health
```

The proxy runs the default image as a container, and a container for each arm and control. A container gets traffic once `--health` answers 200. The proxy reports the digest of its default, so that Statespace knows which commit is deployed.

On Kubernetes, the proxy runs beside the default in each pod and `ssp controller kubernetes` runs the arms. See [Deployment](/getting-started/deployment).

## Keep arms apart from shared state

Arms share the database, cache, and queues with the default. Give them their own environment with `--arm-env`. Controls get it too, so both sides of a comparison run alike.

```shell
ssp proxy --app atlas --image ghcr.io/acme/atlas:main \
  --arm-env DATABASE_URL="$ARM_DATABASE_URL" \
  --arm-env SCHEDULER_ENABLED=false \
  --arm-env CACHE_PREFIX=variant
```

Use a database user without schema permissions for arms. Land migrations in the deployed code first.

## Record what arms print

Arms record every line they print on standard output and standard error. The proxy passes each line through to its own output, so existing log collection keeps working. `--redact` replaces matches before lines leave the machine.

```shell
ssp proxy ... --redact 'sk_live_\w+'
```

JSON lines keep their fields. A `subject` field ties a line to that subject's arm.

Arms also record every request, lifecycle events, CPU and memory, and per-minute HTTP summaries. The default is never recorded.

## Check the arms

Check that the arms run before you wait for outcomes.

```shell
ssp status ranking
```

```sql
SELECT id, kind, version, report FROM atlas.hosts;
SELECT timestamp, arm, commit, event, data FROM atlas.lifecycle ORDER BY timestamp DESC LIMIT 20;
```

## Change the arm

Push a new commit. When it is approved and can merge, it replaces the running commit. The arm keeps its subjects, and the experiment gets a new version. Evidence keeps its version and commit.

To change the share or the rules, change `statespace.toml` on the branch and push.

## Stop the arm

To stop an arm, make its pull request a draft. Mark it ready for review to run it again. In an emergency, stop every arm of the experiment at once from Statespace. The `statespace/arm` check says that Statespace stopped the arm. To run it again, push a commit, or mark the pull request as a draft and then ready.

```shell
ssp stop ranking
```

To ship an arm, merge its pull request and deploy as usual. Merging ends the experiment. Its other arms run again after you update them with the default branch.
