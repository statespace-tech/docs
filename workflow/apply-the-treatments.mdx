---
title: Apply the treatments
description: Assign subjects, read their group's parameters, and record outcomes.
---

Start the draft only after the application handles the group's parameters and its defaults.

```shell
ssp experiment start rank-v2
```

Starting publishes the draft as version 1 and pins the newest version of each group.

## Assign subjects

Pass a stable subject ID and the pre-treatment context the eligibility rule reads.

```python
import statespace

experiment = statespace.experiment("rank-v2")
group = experiment.assign("u_42", context={"country": "US", "plan": "pro"})
rank = group.function("ranker", rerank)
result = rank([3, 1, 2])[: group.value("top_k", 20)]
```

The SDK runs the group's function locally. Control and ineligible subjects receive the defaults. A failing function falls back to the default and records a `statespace.error` outcome.

## Record outcomes

Use the same subject ID for each JSON outcome, from this process or any other.

```python
experiment.log("u_42", "relevance", {"score": 0.7})
experiment.log("u_42", "click", {"position": 3})
```

Each serialized event must fit in 64 KiB. The backend commits accepted events to an account outbox. SQS and the worker persist them asynchronously.

## Publish a change

Change the group, then start the experiment again.

```shell
ssp group update atlas-search ranker=rerank.py:score top_k=20
ssp experiment start rank-v2
```

A group update does not change the running version until the experiment starts again. Starting version 2 stops assignments to version 1. Existing evidence keeps its original version.
