Start the draft once the outcome is deployed and the variant is published.

```shell
ssp experiment start rank-v2 --note 'First run at 5% of US users per arm.'
```

Starting publishes the draft as version 1, pins the newest version of each variant, and takes a slice of the app's subjects.

## Run the proxy

Run the app behind `ssp proxy`. Give it a runtime token as `SSP_TOKEN` and the public signing key.

```shell
ssp proxy --app atlas --runtime docker --image ghcr.io/acme/atlas:main \
  --health /health --trust-key "$SSP_PUBLIC_KEY"
```

The proxy runs the default image as a container. For each running experiment, it starts a control arm from the default's image and a container for each variant, after it checks the variant's signature. A container gets traffic once `--health` answers 200.

On Kubernetes, the proxy runs beside the default in each pod and `ssp controller` runs the arms. See [Deployment](/getting-started/deployment).

## Pin the control arm

The first proxy or controller that serves a new version pins the default's image, by digest, as the version's control arm. Every proxy then compares against the same baseline, even after you deploy a new default. A proxy runs a control arm only from an image it ran as its default.

## Keep arms apart from shared state

Arms share the database, cache, and queues with the default. Give them their own environment with `--variant-env`. Control arms get it too, so both arms of a comparison run alike.

```shell
ssp proxy --app atlas --runtime docker --image ghcr.io/acme/atlas:main --trust-key "$SSP_PUBLIC_KEY" \
  --variant-env DATABASE_URL="$VARIANT_DATABASE_URL" \
  --variant-env SCHEDULER_ENABLED=false \
  --variant-env CACHE_PREFIX=variant
```

Use a database user without schema permissions for arms. Land migrations in the deployed code first.

## Record what arms print

Arms record every line they print on standard output and standard error. The proxy passes each line through to its own output, so existing log collection keeps working. `--redact` replaces matches before lines leave the machine.

```shell
ssp proxy ... --redact 'sk_live_\w+'
```

JSON lines keep their fields. A `subject` field ties a line to that subject's arm.

```python
print(json.dumps({"event": "click", "subject": subject, "position": 3}))
```

Arms also record every request, lifecycle events, CPU and memory, and per-minute HTTP summaries. The default is never recorded.

## Check the arms

Check that the proxies run the arms before you wait for outcomes.

```sql
SELECT id, kind, version, report FROM atlas.hosts;
SELECT timestamp, variant, event, data FROM atlas.lifecycle ORDER BY timestamp DESC LIMIT 20;
```

## Publish a change

Publish a new version of the variant, then start the experiment again.

```shell
ssp variant create atlas-search --app atlas --image ghcr.io/acme/atlas:new-ranking-2
ssp experiment start rank-v2 --note 'Fix the empty-query crash.'
```

A new variant version does not change the running version until the experiment starts again. Starting version 2 stops assignments to version 1 and gives version 2 fresh arms and a fresh control pin. Existing evidence keeps its original version.
