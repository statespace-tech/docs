---
title: Analyze the outcomes
description: Query runs, lines, and requests, then record a decision.
---

Start with allocation and delivery checks. Then compare each variant with its control arm within one experiment version.

Analysis runs against your own PostgreSQL database. Create a token that reads the app once, and point any SQL client at its `database_url`.

```shell
ssp token create --name analyst --preset analyst --app atlas
```

## Check assignment counts

Count runs by assignment reason.

```sql
SELECT reason, count(*)
FROM atlas.runs
WHERE experiment = 'rank-v2'
GROUP BY reason;
```

Check that subjects split as the experiment's shares say.

```sql
SELECT variant, subjects, expected, p_value, mismatch
FROM atlas.sample_ratio
WHERE experiment = 'rank-v2' AND experiment_version = 1;
```

A `mismatch` means assignment or recording is broken, and the comparison cannot be trusted. It is tested once 100 subjects ran. The most common cause is an arm that fails for some subjects. Their runs have `reason = 'variant-unavailable'`: the default served them.

## Check the arms' health

Compare errors and latency of the arms before you trust outcomes. Divide by requests, so arms of different sizes compare fairly.

```sql
SELECT variant,
       count(*) AS requests,
       avg((status >= 500)::int) AS error_rate,
       percentile_cont(0.9) WITHIN GROUP (ORDER BY duration_ms) AS p90_ms
FROM atlas.requests
WHERE experiment = 'rank-v2' AND experiment_version = 1
GROUP BY variant;
```

Read an arm's errors from what it printed.

```sql
SELECT timestamp, variant, line
FROM atlas.output
WHERE experiment = 'rank-v2' AND stream = 'stderr'
ORDER BY timestamp DESC
LIMIT 50;
```

## Compare the arms

List the events the arms printed.

```sql
SELECT data->>'event' AS event, count(*)
FROM atlas.output
WHERE data IS NOT NULL
GROUP BY 1
ORDER BY 2 DESC;
```

Count subjects in the arm they were assigned to, including runs the default served because the arm was unavailable. Leaving those runs out hides failures. Extract numeric values from the JSONB `data` column.

```sql
SELECT
  variant,
  count(DISTINCT subject_id) AS subjects,
  count(*) FILTER (WHERE data->>'event' = 'click') AS clicks,
  avg((data->>'position')::double precision) FILTER (WHERE data->>'event' = 'click') AS mean_position
FROM atlas.logs
WHERE experiment = 'rank-v2'
  AND experiment_version = 1
  AND reason IN ('assigned', 'variant-unavailable')
GROUP BY variant;
```

Compare `atlas-search` with `control`, never with the default. Both arms are new containers with the same share of subjects; the default serves everyone else.

## Connect another tool

Create a token for a BI tool, notebook, or coding agent. Omit `--app` to read every app, and the account's audit log.

```shell
ssp token create --name notebook --preset analyst
```

Revoke the token when the integration no longer needs access. Revoking it also ends its database sessions.

```shell
ssp token revoke tok_123
```

## Make a decision

Decide on the primary outcome you chose before the experiment, with its uncertainty. Then check every guardrail: a better primary outcome does not cancel harm to a guardrail. Finally, weigh the effect against the cost and risk of shipping it. A precise effect can still be too small to be worth it.

Choose one action:

- **Ship** when the benefit holds and the guardrails pass.
- **Reject** when the variant is not worth it.
- **Revise** when the evidence points to a fixable problem.
- **Repeat** with a confirmatory experiment when uncertainty is still material.

Record the decision as a note when you stop the experiment, where the next person or agent will look. Stopping sends every subject back to the default, stops the arms, and keeps the evidence queryable.

```shell
ssp experiment stop rank-v2 --note 'Ship: +1.8 points of click rate (+0.6 to +3.0), no latency change.'
```

Notes are kept with the experiment version and the images and commits it pinned.

```sql
SELECT timestamp, action, note, variants FROM atlas.notes WHERE experiment = 'rank-v2';
```

To ship, merge the variant's branch and deploy it as usual; Statespace does not deploy the default. Turn open questions into a new experiment rather than editing a finished one.
