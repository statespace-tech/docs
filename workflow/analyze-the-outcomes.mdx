Check delivery and health first. Then compare each arm with its control, in one experiment version.

## Connect to the database

Each workspace has its own PostgreSQL database. Create a token that reads the app. Its output shows the database URL for your SQL client. On the **Tokens** page of the dashboard, choose **Read data in SQL**. **Settings** shows the host, port, and database name.

```shell
ssp token create --name analyst --preset analyst --app atlas
```

## Check assignment counts

Count runs by assignment reason.

```sql
SELECT reason, count(*)
FROM atlas.runs
WHERE experiment = 'ranking'
GROUP BY reason;
```

Make sure that subjects split as the experiment's shares say.

```sql
SELECT arm, commit, subjects, expected, p_value, mismatch
FROM atlas.sample_ratio
WHERE experiment = 'ranking' AND experiment_version = 1;
```

<Warning>
  A `mismatch` means that assignment or recording is broken, so do not trust the comparison. Statespace tests it after 100 subjects. The usual cause is an arm that fails for some subjects. Their runs have `reason = 'arm-unavailable'`.
</Warning>

## Check the arms' health

Compare the errors and latency of the arms before you trust outcomes. Divide by requests, so arms of different sizes compare fairly.

```sql
SELECT arm, commit,
       count(*) AS requests,
       avg((status >= 500)::int) AS error_rate,
       percentile_cont(0.9)
         WITHIN GROUP (ORDER BY duration_ms) AS p90_ms
FROM atlas.requests
WHERE experiment = 'ranking' AND experiment_version = 1
GROUP BY arm, commit;
```

Read an arm's errors from what it printed.

```sql
SELECT timestamp, arm, commit, line
FROM atlas.output
WHERE experiment = 'ranking' AND stream = 'stderr'
ORDER BY timestamp DESC
LIMIT 50;
```

## Compare the arms

List the events that the arms printed.

```sql
SELECT data->>'event' AS event, count(*)
FROM atlas.output
WHERE data IS NOT NULL
GROUP BY 1
ORDER BY 2 DESC;
```

Count each subject in its assigned arm. Include the runs that the default served because the arm was not available. Read numbers from the JSONB `data` column.

```sql
SELECT
  arm,
  commit,
  count(DISTINCT subject_id) AS subjects,
  count(*)
    FILTER (WHERE data->>'event' = 'click') AS clicks,
  avg((data->>'position')::float)
    FILTER (WHERE data->>'event' = 'click') AS mean_position
FROM atlas.logs
WHERE experiment = 'ranking'
  AND experiment_version = 1
  AND reason IN ('assigned', 'arm-unavailable')
GROUP BY arm, commit;
```

Compare `recent-clicks` with the control whose `commit` is the arm's base. Do not compare it with the default. In `atlas.arms`, the arm's base is `base_commit`.

## Connect another tool

Create a token for a BI tool, a notebook, or a coding agent. Without `--app`, the token reads every app and the account's audit log.

```shell
ssp token create --name notebook --preset analyst
```

Revoke the token when the tool no longer needs access. This also ends its database sessions.

```shell
ssp token revoke tok_123
```

## Make a decision

Decide on the primary outcome that you chose before the experiment, with its uncertainty. Then check each guardrail. A better primary outcome does not cancel harm to a guardrail. Compare the effect with the cost and risk of the change.

| Decision | When | Then |
| --- | --- | --- |
| Ship | The benefit holds, and the guardrails pass | Merge the pull request, and deploy as usual |
| Reject | The arm is not worth it | Close the pull request. Statespace removes its arm |
| Revise | The evidence shows a problem that you can fix | Push a fix. It runs when it can merge |
| Repeat | The uncertainty is still too large | Run a confirmatory experiment |

Write the decision and its evidence in the pull request, where the next person or agent looks.

<Note>
  A merge ends the experiment, and Statespace does not deploy the default. The evidence stays in the database, with its version and commit. For new questions, start a new experiment.
</Note>
