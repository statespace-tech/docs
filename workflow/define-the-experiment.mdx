---
title: Define the experiment
description: Choose a subject key, eligibility rule, and the groups to compare.
---

Start with one decision. Choose the randomization unit, eligible population, groups, and outcome before you start.

## Choose the randomization unit

Use a stable identifier at the level where treatment can vary independently. Use `user_id` for individual users or `account_id` when users in one account can affect each other. The assignment label does not extract a context field. The application supplies its value to the SDK.

## Write the candidate

Save the candidate ranking function as `rerank.py`.

```python
def score(items: list[int]) -> list[int]:
    return sorted(items)
```

Run it locally in the sandbox the SDKs use.

```shell
ssp run rerank.py:score --input '[3, 1, 2]'
```

## Create the group

Put the function and any values it is tested with in a group.

```shell
ssp group create atlas-search ranker=rerank.py:score top_k=10
```

The CLI builds the function into a WebAssembly component and uploads it. S3 stores the bytes, addressed by their SHA-256 hash. The group records the source path and source hash.

## Create the draft

Use a CEL rule with pre-treatment context and allocate 20% of eligible users to the group.

```shell
ssp experiment create rank-v2 --assignment user_id --group atlas-search=0.2 \
  --description 'Test sorted search results.' \
  --eligibility 'context.country == "US" && context.plan == "pro"'
```

The remaining 80% receives the application's defaults as control. The backend validates CEL and parameter types before it saves the draft.

Review the draft before starting it.

```shell
ssp experiment show rank-v2
```

`ssp experiment update` changes the draft. Omitted flags keep their values, and `--group` replaces the draft's groups.
