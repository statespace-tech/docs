---
title: Define the experiment
description: Name the experiment and arm with a branch, then choose its subjects, eligibility, and share.
---

Start with one decision. Choose the randomization unit, eligible population, arms, and outcome before you start.

## Choose the randomization unit

Use a stable identifier at the level where treatment can vary independently. Read it from the request with a CEL subject rule, such as `request.headers["x-user-id"]` for users or `request.headers["x-account-id"]` for accounts. Without a rule, each browser is a subject.

## Print the outcome

Statespace records each line that an arm prints, with its arm. Thus, your current logs are also evidence. Print a JSON line where the outcome occurs. To compare subjects, add a `subject` field.

```python
subject = request.headers["x-statespace-subject"]
print(json.dumps({
    "event": "click",
    "subject": subject,
    "position": position,
}))
```

The proxy calculates the subject with your subject rule. It sends the result in the `x-statespace-subject` header. The app reads the subject from this header.

Deploy this change to production first. Then the default and each arm print the same lines.

## Name the branch

The branch name gives the experiment and the arm. For one change, name the branch `exp/<name>`. To compare more than one change, name each branch `exp/<experiment>/<arm>`.

| Branch | Experiment | Arm |
| --- | --- | --- |
| `exp/ranking` | `ranking` | `ranking` |
| `exp/ranking/recent-clicks` | `ranking` | `recent-clicks` |
| `exp/ranking/bm25` | `ranking` | `bm25` |

Branches under one experiment are arms of that experiment. They share its subjects and are compared with the same control. Start the branch from the latest default branch, so that its base is a deployed commit.

```shell
git switch -c exp/ranking/recent-clicks origin/main
```

## Set the arm's settings

`statespace.toml` on the branch gives the arm's share and rules.

```toml
app = "atlas"
share = 0.05
subject = 'request.headers["x-user-id"]'
eligibility = 'request.headers["cf-ipcountry"] == "US"'
```

The arm gets 5% of the app's subjects, and its control gets another 5%. Every other subject gets the default. All arms of an experiment must use the same `subject` and `eligibility`.

Check the file and see the plan before you push. `--dry-run` records nothing, and works outside CI. Give it any pushed image of the app, such as the production image.

```shell
ssp apply --image ghcr.io/acme/atlas:main --dry-run
```

## Build the arm

Make one change on the branch. Check that its image starts and answers.

```shell
docker build -t atlas:mine .
docker run --rm -p 8000:8000 atlas:mine
curl localhost:8000/search?q=maps
```

Then commit and push. CI builds the image the way you build production, and `ssp apply` records it as a version of the arm.
