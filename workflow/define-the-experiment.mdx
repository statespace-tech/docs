---
title: Define the experiment
description: Name the experiment and arm with a branch, then set the arm's subjects, eligibility, and share.
---

Start with one decision. Before you push, choose the subject, the eligible population, the arms, and the outcome.

<Steps titleSize="h3">
  <Step title="Choose the subject">
    Use a stable identifier at the level where the treatment can vary independently. Read it from the request with a CEL rule.

    | Unit | Subject rule |
    | --- | --- |
    | User | `request.headers["x-user-id"]` |
    | Account | `request.headers["x-account-id"]` |
    | Browser | No rule. The proxy sets the `ssp_sid` cookie |

    For how subjects keep their arm, see [Random assignment](/concepts/random-assignment).
  </Step>

  <Step title="Print the outcome">
    Statespace records each line that an arm prints, with its arm. Print a JSON line where the outcome occurs. Add a `subject` field to compare subjects.

    ```python
    subject = request.headers["x-statespace-subject"]
    print(json.dumps({
        "event": "click",
        "subject": subject,
        "position": position,
    }))
    ```

    The proxy calculates the subject with your rule. It sends the result in the `x-statespace-subject` header.

    <Note>
      Deploy this change to production first. Then the default and each arm print the same lines.
    </Note>
  </Step>

  <Step title="Name the branch">
    The branch name gives the experiment and the arm. For one change, name the branch `exp/<name>`. To compare more changes, name each branch `exp/<experiment>/<arm>`.

    | Branch | Experiment | Arm |
    | --- | --- | --- |
    | `exp/recent-clicks` | `recent-clicks` | `recent-clicks` |
    | `exp/ranking/recent-clicks` | `ranking` | `recent-clicks` |
    | `exp/ranking/bm25` | `ranking` | `bm25` |

    The arms of one experiment share its subjects and its control. Start the branch from the latest default branch, so that its base is a deployed commit.

    ```shell
    git switch -c exp/ranking/recent-clicks origin/main
    ```
  </Step>

  <Step title="Set the arm's settings">
    Set the arm's share and rules in `statespace.toml` on the branch.

    ```toml statespace.toml
    app = "atlas"
    share = 0.05
    subject = 'request.headers["x-user-id"]'
    eligibility = 'request.headers["cf-ipcountry"] == "US"'
    ```

    The arm gets 5% of the app's subjects, and its control gets another 5%. Every other subject gets the default. All arms of an experiment must use the same `subject` and `eligibility`.
  </Step>

  <Step title="Check the plan">
    Check the file, and see the plan before you push. `--dry-run` records nothing, and works outside CI. Give it an image that is in the registry, such as the production image.

    ```shell
    ssp apply --image ghcr.io/acme/atlas:main --dry-run
    ```
  </Step>

  <Step title="Build the arm">
    Make one change on the branch. Make sure that its image starts and answers requests.

    ```shell
    docker build -t atlas:mine .
    docker run --rm -p 8000:8000 atlas:mine
    curl localhost:8000/search?q=maps
    ```

    Commit and push. CI builds the image, and `ssp apply` records it as a version of the arm.
  </Step>
</Steps>
